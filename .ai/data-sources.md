# 数据源与数据边界

> **本文件回答"这个数据从哪来、覆盖到哪、什么情况下会骗人"。**
> 建立：2026-09-26 · 依据 `references/deep-dives/10-akshare.md`
>
> **规则**：每个数据源必须有完整的「数据边界」声明。**"没报错"不算验证通过** —— 必须有具体的核对点。

---

## 一、为什么要有这个文件

1. **"未接入"的决定必须留档** —— 否则半年后会被重复调研（反面教材：某项目 v3.0–v3.7 的取舍决策全无留档）。
2. **降级路径必须写"与主源的差异"** —— 不是"备胎能替代主源"。**差异必须能被程序读到，而不只是写在文档里。**
3. **数据源会安静地骗人** —— 见第五节「已知的骗人方式」。

## 二、已接入数据源

### 2.1 数据边界表

| 源 | 域 | 覆盖 | **不覆盖** | 时间起点 | 口径限制 | 已知缺口 | 封禁风险 | 备胎 |
|---|---|---|---|---|---|---|---|---|
| **腾讯（实时）** | `qt.gtimg.cn` | 个股实时 · 指数实时 | 行业/概念字段 | — | **有前复权** | 无行业/概念字段 | **低**（最宽松） | 新浪 |
| **腾讯（日线）** | ⭐ `web.ifzq.gtimg.cn` | **个股日线（前复权 `qfq`）** | ⚠️ **不返回成交额** | — | 前复权口径明确（`fqkline/get` + `qfq`） | ⭐ **无成交额** → `Quote.amount = None`，**绝不填 0、绝不估算** | **低** | 东财 |
| **新浪** | `hq.sinajs.cn` | 个股实时 · 指数实时 | — | — | ⚠️ **无前复权** | 需 `Referer: https://finance.sina.com.cn`（**缺了会被拒**） | 中 | 腾讯 |
| **东财 push2his** | `push2his.eastmoney.com` | **个股日线（前复权，含成交额）** | 实时 | — | 前复权口径明确 | 连续请求会触发限流 | ⚠️ **高**（末位使用） | 腾讯 |
| **东财 datacenter-web** | `datacenter-web.eastmoney.com` | 财务 / 其他结构化数据 | — | — | — | ⚠️ **未验证** | **低**（**不受 `push2` 封禁影响**） | — |

> ⭐ **注意：同一域名的不同子域风控面不同。** `datacenter-web` 不受 `push2` 封禁影响。
> **"某站被封了"这个说法不准确，必须精确到子域。**
> ⭐ **腾讯也一样**：`qt.gtimg.cn`（实时）与 `web.ifzq.gtimg.cn`（日线）是**两个子域、两套能力**，必须分行声明。

### 2.2 优先级（按**封禁风险**排序，不按数据丰富度）

```
腾讯  →  交易所官方  →  新浪 / 巨潮  →  东财（末位）
```

### 2.3 降级路径表（**必须写差异**）

| 主源 | 降级到 | **与主源的差异**（程序必须能读到） |
|---|---|---|
| 东财（日线） | 腾讯（日线） | ⭐ **腾讯日线不返回成交额** → `amount = None`。**价格/成交量可用，成交额不可用。** |
| 腾讯（实时） | 新浪（实时） | ⚠️ **新浪无前复权**；字段顺序与腾讯不同；**量纲也不同**（腾讯报手/万元，新浪报股/元） |
| 任一 | 本地缓存 | ⭐ **标 `stale=True`**，保留原 `source` 与原 `fetched_at`，**用户必须看到"这是旧数据"** |
| 任一 | — | **不允许"静默降级"** —— 降级必须显式标记，且**用户可见** |

**⚠️ 反面教材**：某项目主源不可达时退到备胎，**但备胎"只有沪深、无价格"** —— 调用方会以为拿到了完整数据。**这是最危险的失败模式。**

**降级优先级（代码内，`providers/router.py`）**：
```
ok  >  no_data  >  stale  >  error
```
⭐ **"源说没有" 优先于 "缓存说昨天是"** —— 否则退市股会永远显示最后成交价。

### 2.4 限流与封禁（两件事，恢复策略不同）

| 现象 | 性质 | 恢复策略 |
|---|---|---|
| 腾讯返回空 | **限流** | 降速即可恢复（秒级–分钟级） |
| 东财 `RemoteDisconnected` | ⚠️ **封 IP** | 等 **20+ 小时**，或换网络 |
| ⭐ 东财**连接被中断**（`server closed abruptly`，无 HTTP 状态码） | ⚠️ **网络层不可达**（**与限流不同**） | 换网络 / 等；**代码按 `unreachable` 处理并降级** |

**实测**：**45000+ 请求会导致 IP 级封禁 20+ 小时。**
**实测（2026-09-26）**：本机沙箱代理下 `push2his.eastmoney.com` 连接被中断，**重试 3 次全失败**；腾讯 / 新浪**同时正常**。→ **说明这不是全站故障，而是东财这一条路径的问题**，也正是三源互备存在的理由。

## 三、实测记录（2026-09-25，本机真实执行）

> **格式：请求 → 返回行数 → 具体核对点。** 不是"没报错"。

| # | 请求 | 返回 | 核对点 |
|---|---|---|---|
| 1 | 东财 `push2his` 个股日线，前复权，2026-01-01 → 2026-09-24 | **178 条** | 日期连续无缺口 · 条数与区间交易日数一致 |
| 2 | 腾讯 `qt.gtimg.cn` 贵州茅台 | `1237.00 -1.14%` | **与新浪交叉验证一致** |
| 3 | 新浪 `hq.sinajs.cn` 贵州茅台 | `1237.000` | **与腾讯交叉验证一致** |
| 4 | 腾讯 指数实时 | 上证 `3888.37 -1.22%` · 深证 `-2.34%` · 创业板 `-2.68%` | 三个指数均有值且符号方向一致（当日普跌） |
| 5 | 东财 `push2his` 连续请求 | ❌ **触发限流后持续被拒** | — |

**结论**：**单一数据源不可靠。** 架构必须 = 三源互备 + 本地缓存优先 + 指数退避熔断 + 失败不静默。

## 三之二、实测记录（2026-09-26，实现数据层时的真实执行）

> 本次是**在写代码的过程中**测的，所以结论直接落进了实现。

| # | 请求 | 返回 | 核对点 / 结论 |
|---|---|---|---|
| 1 | 腾讯 `qt.gtimg.cn/q=sh600519` | 完整 GBK payload | 字段索引 **3=现价 / 4=昨收 / 5=今开 / 33=高 / 34=低 / 6=量(手) / 37=额(万元)**，与实现一致 |
| 2 | 新浪 `hq.sinajs.cn/list=sh600519` | 完整 payload | **必须带 `Referer`**；字段 **1=开 / 2=昨收 / 3=现价 / 4=高 / 5=低 / 8=量(股) / 9=额(元)** |
| 3 | ⭐ **交叉验证 1 与 2** | 腾讯 `1237.00 / 1250.01 / 1256.13 / 1231.05`<br>新浪 `1237.000 / 1250.010 / 1256.130 / 1231.050` | **价格四项完全一致**；量/额换算后一致（腾讯 `31239 手 × 100 = 3,123,900 股` vs 新浪 `3,123,935 股`） |
| 4 | ⭐⭐ **腾讯日线** `web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600519,day,2026-09-18,2026-09-26,10,qfq` | **5 条** `qfqday` | 返回 `[日期, 开, 收, 高, 低, 成交量(手)]` —— ⚠️ **只有 6 列，没有成交额**。**最后一根与 #1/#2 的实时 OHLC 完全吻合** |
| 5 | ⭐ **东财 `push2his`** | ❌ **连接被中断**（`server closed abruptly`） | **重试 3 次全失败**（含 `82.push2his` 子域与带 Referer 的请求）。**腾讯/新浪同时正常** |
| 6 | 北交所 `430047.BJ` | — | **未实测**：当前没有任何源声明支持 `.BJ` → 路由**不发请求**，直接 `no_data` / `no_provider`（诚实降级，见下） |

**⭐ 本次最重要的三条结论**：

1. **腾讯有日线**（此前记录为"可用但非首选"，实际是**完整可用的前复权日线**）→ **日线不再是东财单点**。
2. ⚠️ **代价是真的**：腾讯日线**没有成交额** → `Quote.amount` 为 `float | None`，**渲染时必须显示"该源不提供"，而不是 0**。
3. **东财不可达时，降级链真的工作了** —— 日线请求自动切到腾讯并返回成功（实测见 `backend/scripts/smoke_market.py`）。

**代码位置**：`backend/src/alphacouncil/providers/{sources,router}.py` · 测试 `backend/tests/unit/test_market_data.py`（**夹具用的就是上面这些真实 payload**）。

## 四、实现约束（对应宪法 4.5 / 7.8）

| # | 约束 |
|---|---|
| 1 | **所有外部访问走唯一入口函数**（串行 + 最小间隔 + 随机抖动 + 会话复用 + 默认 UA + 熔断 + 缓存） |
| 2 | **`finally` 里更新时间戳** —— 失败也算一次访问，否则连续失败变轰炸 |
| 3 | **403 不重试**（风控信号，重试加重） |
| 4 | **禁止在业务代码里裸调 `httpx` / `requests` / `urlopen`**（静态检查拦截） |
| 5 | **Ticker 归一化**：`re.match` **整串锚定**（禁止 `re.search` 捞 6 位）· **前后缀二选一**（`SH000001.SZ` 拒绝）· **解析失败抛错不返空** |
| 6 | ⭐ **`000xxx` 是"歧义段"不是"矛盾"** —— `sh000001` = 上证指数，`sz000001` = 平安银行。**必须让用户选市场，不能猜。** |
| 7 | **标的主键 = `(market, code)`**；**禁止从代码推断市场作为唯一依据**（推断只能校验，不能补全） |
| 8 | **指数代码白名单**：`SH_INDEX = {"000300", "000905", "000016", "000688", "000852", "000010"}` |
| 9 | ⭐ **数据四态类型化**：`ok` / `no_data(reason)` / `error(code)` / `unavailable(reason)` —— `DataResult` **构造即校验**（`ok` 必须有值、`error` 必须有码、`no_data` 必须给原因） |
| 10 | ⭐ **降级优先级固定**：`ok > no_data > stale > error` |
| 11 | ⭐ **实时快照不命中缓存**（旧价当现价 = 说谎）；**日线可命中**（历史不可变） |
| 12 | ⭐ **`stale` 必须显式**：降级时**保留原 `source` 与原 `fetched_at`**，前端必须显示"数据陈旧" |
| 13 | **403 / 429 → `blocked`**，冷却 **300s** 且**不重试**；连续 **3** 次传输失败 → **60s 熔断** |
| 14 | ⭐ **未声明支持的交易所不发请求** —— `.BJ` 未验证 → 直接 `no_provider`，**不用前缀去猜**（猜错 = 拿到另一个市场的数据） |
| 15 | **能力由代码声明**（`ProviderCapabilities`），`router` 按声明选源 —— **新增数据源 = 注册一个声明，不是加一个 `if`** |

**实现位置**：`backend/src/alphacouncil/models/market.py`（契约）· `providers/base.py`（能力与异常）· `providers/sources.py`（三源）· `providers/router.py`（路由与降级）· `providers/cache.py`（缓存）。

## 五、已知的"骗人方式"（必须防御）

| 骗法 | 现象 | 防御 |
|---|---|---|
| ⭐ **僵尸报价** | 北交所老号段迁移后，接口仍返回**成交量 0、价格定格在迁移日**的数据，**价差 17%~100%+**。**不报错、不崩溃，只是安静地骗人** | **价格下限校验**（`TDX_MIN_PRICED`）· 成交量为 0 且价格异常的记录直接拒绝 |
| ⭐ **"当前快照"当"历史数据"** | 指数成分 / 权重只有当前快照，用它做历史研究就是**前视偏差** | **没有历史时点数据时必须显式报错**，不能用当前快照代替 |
| ⭐ **静默降级** | 备胎数据不完整，但调用方以为拿到了全部 | 降级必须显式标记（见 2.3） |
| ⭐ **"接口坏了"被当成"确实没有"** | 返回空表被解读为"该区间无数据" | **数据四态**（宪法 4.6）· 业务结果 vs 系统故障**类型层面就不同** |
| ⭐ **"无法判断"时返回默认值** | 返回一个"看起来合理"的数 | **禁止默认值** —— 无法判断必须抛错 |
