# 发布检查清单

> **发布是一次被审查的 PR，不是"我打了个包"。**
> 建立：2026-09-26 · 依据 `references/deep-dives/09-primitives.md`（`release-process.md`）· `11-open-science.md`（`electron-builder.yml` 注释理由）

## 一、为什么要有清单

**打补丁式发布**与**检查清单式发布**的区别：

| | 无清单 | 有清单 |
|---|---|---|
| 漏项 | 靠记忆 | 靠清单 |
| 责任 | 模糊 | 每项有"谁做" |
| 可追溯 | 无 | 台账 |

**⚠️ 发布流程无长期 `stable` 分支** —— 每次从 `main` 临时建、**发完即删**。
理由：长期分支会漂移，且掩盖"发布就是从主线切出来的一个点"这一事实。

## 二、发布前 8 项（全绿才能发）

| # | 检查 | 命令 / 方式 | 通过标准 |
|---|---|---|---|
| **1** | **质量门禁全绿** | `make check` | **输出里 `0 failed`**（⚠️ 退出码 0 不代表通过，见 `.ai/error-codes.md` §3） |
| **2** | **检查脚本全绿** | `make check-static` + `make check-data` | 无 `severity=error` 的 Issue |
| **3** | **迁移可逆性验证** | 全新库 → 升级 → 回滚 | 回滚后数据完整，无残留表 |
| **4** | **打包体积核对** | 与上一版对比 | 增量有解释（**没有"不知道为什么大了 30MB"**） |
| **5** | **冷启动自检** | 装到干净机器 → 启动 | `frozen=True` / `http=200` / WebView2 OK / 窗口真实打开 |
| **6** | **离线可用验证** | **拔网线** → 启动 | 能启动 · 显示缓存数据 · **明确提示数据截至时间** |
| **7** | **首屏性能** | 计时 | 3 秒内可用 |
| **8** | **版本号一致性** | 检查 4 处 | `pyproject.toml` / `package.json` / Inno Setup 脚本 / `.ai/status.md` **四处一致** |

**发布 PR 必须包含**：改动目的 · 改动内容 · **验证方式（命令 + 实际输出）** · 关联 Issue。

## 三、⭐ 打包排除清单（每条必须写理由）

> **排除不只为了体积，也为了不泄露本地 agent 状态。**
> **⚠️ 禁止出现"没有理由的排除"** —— 三年后没人知道它为什么被排除。

### 3.1 排除清单格式

```yaml
# 排除 <路径/模式>
# 理由：<为什么排除>
# 症状：<不排除会发生什么 —— 具体到可观察的现象>
# 体积：<约 X MB>
excludes:
  - "<pattern>"
```

### 3.2 症状必须具体（反面教材 vs 正确写法）

| ❌ 不够 | ✅ 正确 |
|---|---|
| "排除测试文件，减小体积" | "排除 `tests/`：包含**内网地址与测试账号**；不排除会**泄露开发环境信息**；约 8MB" |
| "排除文档" | "排除 `docs/`：其中含**本地 agent 状态文件**；不排除会 **leaking local agent state into the shipped bundle**；约 2MB" |
| "排除缓存" | "排除 `__pycache__/`：会在**只读安装目录**下导致启动失败（症状：**窗口不打开，任务栏图标闪一下就退出**）；约 16MB" |

### 3.3 我们的排除清单（初版，随打包实测更新）

| 路径 | 理由 | 症状（不排除会怎样） | 体积 |
|---|---|---|---|
| `.git/` | 版本历史，与运行无关 | 包体积暴涨（可达 1GB+） | >1GB |
| `.ai/` | **本地开发资产 + agent 状态** | ⚠️ **把本地 agent 状态打进发布包** | ~0.5MB |
| `references/` | 借鉴项目源码（849MB） | 包体积不可接受 | **849MB** |
| `backend/tests/` | 测试代码，含 fixture 数据 | 泄露测试数据；包变大 | ~8MB |
| `**/__pycache__/` | 字节码缓存 | 只读目录下启动异常 | ~16MB |
| `*.md`（根目录） | 开发文档 | 用户不需要；泄露内部讨论 | ~0.3MB |
| `node_modules/`（若打包前端源码） | 前端已构建为静态产物 | 包体积 >200MB | >200MB |
| `.env*` | ⚠️ **可能含密钥** | **密钥泄露** | ~0KB |

> ⚠️ **`.env*` 的排除不是"为了体积"，是"为了不泄露密钥"。** 这类排除**必须写在清单第一位**。

## 五、明确不做

| 不做 | 为什么 |
|---|---|
| **代码签名 / SLSA 溯源 / SHA256SUMS** | 我们不做公开发布（简历项目 + 自用），**签名/溯源成本超过收益** |
| **自动更新** | 单用户桌面程序，手动装新版即可；自动更新会引入网络依赖与安全面 |
| **多平台构建** | 只做 Windows（用户就是 Windows） |

> **"不做"要写出来** —— 否则每次发布都要重新讨论一次（见宪法第十一条）。
