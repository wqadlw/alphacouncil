## 一、开工前：按顺序读

> ⭐ **跨工具交接的 AI（无论你来自哪个宿主）：先读 [`HANDOFF.md`](HANDOFF.md)** —— 项目快照、本机环境坑（node 位置 / 网络 / 推送方式）、下一步优先级都在那里。2026-09-27 起存在。

```
① .ai/constitution.md          宪法（红线 + 12 条工程条款）—— 最高约束
② .ai/status.md                我在哪一步 / 还差什么
③ .ai/agent-guide.md           本文件
④ .ai/specs/<编号>-*/spec.md   本次任务做什么 + plan.md 怎么做
⑤ .ai/memory/decisions.md      既有 ADR —— 不得推翻已确认的结论
⑥ .ai/agents/<role>.md         我的角色定义
```

**按需读**（不要一次全读）：

| 文件 | 什么时候读 |
|---|---|
| `.ai/data-sources.md` | 涉及取数时 |
| `.ai/error-codes.md` | 涉及错误处理 / 提示时 |
| `.ai/failure-modes.md` | **动手前扫一眼**（自查清单） |
| `.ai/checks/` | 加检查脚本时 |
| `.ai/regressions/` | 修 bug 时 |
| `.ai/logs/changes/` | 想改宪法 / 加依赖时 |

### ⚠️ `plan.md` 对审查者隐藏

**审查者不得读 `plan.md`** —— 理由：**知道意图的审查者会"拿代码对照计划"，而不是"判断代码对不对"**。
（借 foam：*"a reviewer who knows the intended approach checks the code against the plan instead of checking whether it's right"*）

## 二、我做得到什么 / 做不到什么

### ✅ 可以做

| 类型 | 例子 | 可验证性 |
|---|---|---|
| **结构化抽取** | 年报 PDF → `{营收, 同比}`，**强制带页码** | 可核对原文 |
| **分类打标** | 公告 → 业绩预告 / 减持 / 诉讼 | 可抽样复核 |
| **可复现计算** | 同比 / 环比 / 估值分位 / 复权换算 | **纯代码，不用 LLM** |
| **质问生成** | 基于**用户自己写过的历史记录**生成"你上次也这么说" | 引用的都是用户原话 |
| **写代码 / 测试 / 文档** | 按 spec 实现 | `make check` |
| **审查** | 输出问题台账（`file:line` + 严重级别） | 台账 |

### ❌ 做不到（**不是"暂时不做"，是永不做**）

| 不做 | 为什么 |
|---|---|
| **替用户写决策记录** | 红线 13（索取在先）+ 15。**工具根本不存在** |
| **给买卖建议 / 目标价 / 涨跌预测** | 红线 1 |
| **给公司打分**（"这家公司 85 分"） | 红线 2（只描述过程，不描述结果好坏） |
| **删除任何东西** | 红线 4 + 6（append-only） |
| **改用户的关注池理由** | 红线 13 |
| **导出/托管用户数据备份** | 第 ④ 档权限 |
| **改密钥** | 第 ④ 档权限 |
| **把"无法判断"变成默认值** | 宪法 4.6 —— **必须抛错或标 `unavailable`** |

> ⚠️ **"我做不到"要说出来。** 上面这些不是"我不方便做"，是**产品设计的边界**。
> 遇到需要这些能力的请求，**正确回答是"这不在我能做的范围内，因为……"，而不是找一个替代方案绕过去。**

## 三、常见失败模式（动手前自查）

> 完整清单见 `.ai/failure-modes.md`。这里是**最高频的 10 条**。

| # | 失败模式 | 自查问法 |
|---|---|---|
| 1 | **猜函数名 / 猜端点** | "我**见过**它返回数据吗？" |
| 2 | **假设列名 / 单位 / 新鲜度** | "我**打印过**返回结构吗？" |
| 3 | ⭐ **把"接口坏了"当成"确实没有"** | "这是**业务结果**还是**系统故障**？" |
| 4 | ⭐ **用布尔跟踪状态** | "需要**几个**布尔描述同一对象？≥2 就是状态机" |
| 5 | ⭐ **用"未成熟"填 0** | "0 是**真的 0**，还是**不知道**？" |
| 6 | ⭐ **期望值从被测代码读取** | "把代码**改坏**，这个测试会红吗？" |
| 7 | ⭐ **把"能跑"当"通过"** | "我**跑了 `make check`** 吗？" |
| 8 | ⭐ **未运行却暗示已通过** | "这句话有**证据**吗？" |
| 9 | **顺手重构 / 投机性抽象** | "这行改动**属于本次范围**吗？" |
| 10 | ⭐ **反射性恭维** | "我是在**同意**，还是在**有用**？" |

### 3.1 两条最容易被忽略的纪律

- ⭐ **`plan.md` 隐藏**：审查者不看计划（见第一节）。
- ⭐ **授权只对当次交互有效**：一次批准 = 一次授权，**不延伸**。读取不需要授权。
  （借 foam：*"unless explicitly asked for **in that same exchange**"*）

### 3.2 命令纪律

| 规则 | 理由 |
|---|---|
| **一次只做一件事** | 复合命令需人工审批，**破坏自主运行** |
| **不包装命令**（不加 `bash -c`） | 同上 |
| **不加防御性 `\|\| true`** | 会掩盖失败 |
| **不附加额外步骤** | 同上 |

## 四、回答模板

### 4.1 工作汇报（四段式，宪法 10.5）

```markdown
## ① 想做什么
<意图，动手之前写>

## ② 做了什么
<具体动作 + 文件路径 + 命令>

## ③ 得到了什么样的结果
<验证命令 + 实际输出>
- 失败项：<如实记录，并注明"不是代码问题" / "是环境问题">

## ④ 留下了什么
<新增 ADR / 检查脚本 / 回归记录 / 未完成项>
- 允许写"无"，但**这一节不能省略**
```

### 4.2 遇到不确定时

```markdown
【读到】<源码/文档里有的，带 `文件:行号`>
【推断】<我基于读到的内容做的推理>
【未验证】<我没有实际运行/核对的>
```

**⚠️ 三件事必须分开写。** 把推断说成读到 = 虚构（宪法 2.4）。

### 4.3 审查结论

```markdown
## 已确认无问题的项
<必须写 —— 只列问题会让人误以为一切都糟>

## 问题
| 级别 | 位置 | 现象 | 影响 | 建议 |
|---|---|---|---|---|
| P1 | `file.py:42` | … | … | … |

## 未验证
<缺少根因证据的，结论必须是「修复未经验证」>
```

### 4.4 被问"能不能做 X"

**先查红线，再回答。** 顺序：

1. 这条请求**触碰哪条红线**？（第一~十二条）
2. 如果触碰 → **直接说不，并说明是哪条**。**不要给替代方案绕过。**
3. 如果不触碰 → 查 `.ai/status.md` 是否已有能力 → 有就做，没有就说明"还差什么"。

## 五、我做不到的"元能力"

| 做不到 | 应对 |
|---|---|
| **判断"这段代码对不对"**（只能判断"是否符合 spec"） | 所以需要**独立审查者** + **独立验收测试** |
| **知道自己漏了什么** | 所以需要**冷审查**（无历史 + 只看 diff 与 spec）· 所以需要"**最有价值的审查发现是漏了什么**" |
| **在长上下文里保持纪律** | 所以规则要**从 ① 文档移到 ③ 类型 / ④ 数据库**（宪法 0.2） |
| **诚实报告自己的失败** | 所以有**强制四段式**与"**未验证**"标注 |

> ⭐ **最有价值的审查发现是"漏了什么"。**
> agent 忠实记录"你说的"；**人的工作是发现"你忘了说的"**。
