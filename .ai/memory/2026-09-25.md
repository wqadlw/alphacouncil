**过程中发现并修复的真实缺陷**

1. **`structlog.PrintLoggerFactory` 与 `add_logger_name` 不兼容**
   - 现象：每一次 `logger.info()` 都抛 `AttributeError: 'PrintLogger' object has no attribute 'name'`。
   - 根因：`add_logger_name` 处理器读取 `logger.name`，而 `PrintLogger` 没有该属性。
   - 修复：改为 structlog 与 stdlib 的标准桥接方式（`stdlib.LoggerFactory` + `ProcessorFormatter.wrap_for_formatter` + `ProcessorFormatter`）。附带收益：uvicorn / sqlalchemy 等第三方库的日志现在走同一渲染器，输出格式统一。
   - 发现方式：**由单元测试捕获**，而非运行时才发现。这正是 constitution 第三条要求「新增功能必须附带测试」的价值所在。

2. **`Settings(_env_file=None, **overrides)` 触发 mypy 类型错误**
   - 根因：未启用 pydantic mypy 插件，`BaseSettings` 的具名参数未被识别。
   - 修复：在 `pyproject.toml` 启用 `plugins = ["pydantic.mypy"]` 并配置 `[tool.pydantic-mypy]`。启用后原先的 `# type: ignore` 反而变成多余，已一并清理。

3. **starlette 1.7 弃用 `httpx`，要求 `httpx2`**
   - 现象：`filterwarnings = ["error"]` 使弃用警告直接变成测试收集错误。
   - 修复：dev 依赖加入 `httpx2>=2.0`。
