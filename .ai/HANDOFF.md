## 九、环境：一个会让你跟空的事实

**本机 `core.autocrlf=true`**，所以**任何新 clone 的工作树文件都是 CRLF**，
而仓库里存的是 LF。

```text
local  bytes=27368  CR=0    LF=714
clone  bytes=28082  CR=714  LF=714
归一化换行符后完全相同
```

**不是破损，也没有任何处报错** —— 只是你发现哪个比对不上。

两个后果：

1. **本项目对每个写入文件做的 `CR=0` 字节检查，只在工作树上成立** ——
   一个新 clone 会全部失败。
2. **「全新 clone 复验」要读的是「跑测试」，不是「比对哈希」** ——
   哈希不同时只说明行端有差异，而日志里的测试才说明内容对。
   注意：新 clone 里**没有 `node_modules`**，所以 `npm run test` / `test:e2e` 必须先
   `npm install` —— 不安装就跑会报「找不到模块」，而那不是产品变化。
