# 0025 · 「症状没了」和「病因处理了」是两句话，而只有第二句熬得过下一种形状

**日期** 2026-10-03 · **来源** spec 051（D4 接线第三步） · **类型** 门禁的第二次自身缺陷

## 发生了什么

`S-16`（`no_enum_drift`）把一个匹配的 union 报成「不存在」，而那个 union 就在它眼前七个值全在。
同一周前一次，它已经因为同一个原因报过一次（`0023`）。

⭐ **两次都是「union 里放了注释」。而这一次暴露的是：上一次的修复根本没生效。**

## 根因：两处，都在我自己写的修复里

| # | 错在哪 | 实测 |
|---|---|---|
| 1 | 引号状态**跨行**累积，而注释里的反引号不是字符串定界符 | 从那行之后**每一行**都被当成在字符串里，之后的注释一条也没剥 |
| 2 | ⭐ 剥掉的注释写成了空行 `""` 而不是**删掉** | ⭐ **空行照样截断** —— union 的模式在「后面不是 `|` 的换行」处收口 |

⚠️ 第 2 条是关键：**把注释置空，等于把原来的 bug 原样留下**，只是换了个位置。

## ⭐ 这一条真正要记的是方法，不是这两个 bug

上一次的修复「验证」方式是：**我手把注释挪出了 union，门禁绿了。**

⚠️ 也就是说 —— **修复本身从未被测过。** 我验证的是「症状消失」，不是「病因被处理」。
两条测试形状都是这样暴露的：跑门禁时**碰巧**在改一个带注释的 union。

⭐ 而且第 2 条的错误至今还在注释里写着：「Whole-line only, and deliberately … A trailing
comment on a value's own line would still truncate」。⚠️ **那句也是假的** ——
尾随注释不截断，因为字面量是从引号文本里取的，不是按 `|` 切的。写下来的「限制」比实际的
限制更严，而一个把自己说得比实际更弱的门禁，会让下一个人以为那里有个坑。

## 修法与它的顺序

```python
stripped = line.strip()
if stripped.startswith(("//", "#")):
    continue          # ⭐ 删掉，不是置空
... 然后才做引号状态扫描
```

⭐ **前缀判断必须在前。** 一行以 `//` 或 `#` 开头就是注释，**注释里的任何东西都不能改变扫描器的
状态** —— 散文里的反引号是反引号，不是定界符。这不是特例，这就是规则，而且更便宜。

## 三条带走的

1. → **修一个门禁，就为它写测试。** `S-16` 此前**一个单元测试文件都没有** —— 而这正是两个缺陷
   都能进 `main` 的原因。
2. → ⭐ **验收一个修复，要验收病因，不要验收症状。** 「门禁绿了」证明不了「形状被处理了」。
3. → ⭐ **门禁文档里写的「限制」也要被测。** 一条说自己比实际更弱的限制，会挡住真正该修的形状。

## 与 `0023` 的关系

`0023` 记的是「门禁把自己的扫描器误报成代码缺陷」——**那是症状**。
`0025` 记的是「上一次的修复从未被测过」——⭐ **那才是可带走的部分**，而且它对任何一条门禁都成立。
