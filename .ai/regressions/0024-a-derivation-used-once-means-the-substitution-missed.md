# 0024 · 一个只出现一次的模块级名字，是「替换没发生」的证据

**日期** 2026-10-02 · **来源** spec 051（D4 接线前的盘点） · **类型** 测试变换静默失败

## 发生了什么

上一轮把五处「硬写三元组」的测试改成从枚举派生。在 `test_criterion_eval.py` 里我加了

```python
NOT_A_COMPARISON = tuple(state for state in CriterionVerdict if not state.answerable)
```

脚本报告 **「`test_criterion_eval.py`: 0 triple(s) replaced」**，我读成了成功。

⚠️ **实际发生的是：派生加上了，没有任何地方用它，而那处三元组原地未动。**

原因很浅：那一处的三元组是**跨行**的，而我的模式是**单行**的正则。`re.sub` 匹配不到，
`if text == before` 于是返回 0。⚠️ **而 0 在我的脚本里与「已经全部替换过一遍」是同一个返回值。**

## 代价

`NOT_ANNOUNCED`（第六个成员）在 `test_criterion_eval.py` 里**完全没被覆盖** ——
它的 `answerable` 没有被断言。加上那处三元组是**手写**的，所以枚举加成员时它既不会红，
也不会被跑。这正是 `0021` 的形状（「一个概念，三个家，其中两个是对的」）第三次出现。

## ⭐ 那一行量测，本来能当场抓到

```
NOT_A_COMPARISON 在它自己的文件里出现：1 次
```

⭐ **一个只出现一次的模块级名字，说明它没有被使用。** 这一次测量是 1 行代码。
它没有做，所以派生的存在与它的用处脱钩了整整一轮 —— 而中间还跑过一次全绿的门禁。

## 两条由此来的规定

1. → **派生出一个常量之后，立刻数它在文件里出现几次。**
   一次是「定义了没人用」，两次以上才是「有人用」。⭐ 这是这条规律最有用的形状：
   **它不需要理解代码，只需要数一个字符串。**
2. → ⚠️ **变换脚本的返回值必须能区分「没匹配到」和「已经是对的」。**
   「0 处替换」在两种情形下是同一个数字，而**它不该被读成成功** ——
   新引入的派生第一次运行时，`0` 只可能意味着前者。

## 与既有记录的关系

- `0021`（一个概念三个家）：同一个形状的第一次。
- `F-221`（行的前缀不是行）：本会话另一个「锚点形状不对 ⇒ 什么都没发生」，
  而那次至少炸了（文件不再是 Python）。⭐ **这次的版本更坏：它安静地什么都没做。**
- ⭐ 两者合起来指向同一句：**静默的变换比炸掉的变换贵，因为炸掉的会被看见。**
