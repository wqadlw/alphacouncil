# 0020 · 一条存在的能力只能靠写代码用上，而它的读端点根本不存在

- **发现日期**：2026-10-02
- **严重级别**：P0（**一个视图对每一个用户都是空的**，与新用户无关）
- **状态**：已修复 + 已加门禁（变异 M1/M2/M3 均已确认）

## 现象

`status.md` K3 那一行挂着「还差：标的页卡片的『加入复习 / 下次复习 N 天后』」。
它挂了很久 —— ⭐ **而挂着的缺口和真实存在的缺口长得一模一样**（`regressions/0005`）。

对着一个**空数据库**（`ALPHACOUNCIL_DATABASE_PATH` 指到临时目录）量：

```
1. POST /api/v1/cards                 -> 201 card_1790916668533
2. GET  /api/v1/review/due            -> 0 条     ← 服务端不主动贡献任何东西
3. POST /api/v1/cards/{id}/schedule   -> 201 {"state":"learning","due_at":"…"}
4. GET  /api/v1/review/due            -> 1 条
5. grep scheduleCard                  -> api.ts:282 定义，调用者 0 个
```

**⇒ 卡片只能靠写代码进复习队列。复习页对每一个用户都是空的。**

⭐ **而笔记不是这样**：`VaultPage` 里有 `enrollNote`，配一段有理由的注释
（显式入队，因为「把读者写过的每样东西都入队会攒下一份没人清的欠账」）。
**同一个后端形状，卡片这边只有一半。**

## ⭐ 根因有两层，而第二层才是真的那个

**第一层（看得见的那个）**：`POST` 存在，没有界面按钮。

**第二层（不补上就修不好的那个）**：**`GET` 端点当时根本不存在。**

⇒ 界面**无法知道**一张卡片在不在队列里。而**也不能从 `/review/due` 推断** ——
那个端点只给**到期**的，一张排在下周三的卡片不在里面。

⇒ 所以「加入复习」这个按钮如果只能靠点完才知道结果，**它就是一个赌注**。
这个产品不拿读者的记录下赌。

## 修复

1. **后端加一条路由** `GET /api/v1/cards/{card_id}/schedule`。
   ⚠️ 仓储层**已经全有**了：`scheduling.get_schedule()` 与 `CardNotScheduledError`
   都存在（实测确认）。**所以这是一条路由，不是一个功能。**
2. **`api.ts` 的 `getCardSchedule()` 返回三态**而不是布尔。
3. **`CardSection` 的 `Enrolment` 控件**：未入队给按钮 · 已入队显示下次 · **不知道就说不知道**。

## ⚠️ 一处「照抄」是错的，而项目已经决定过了

笔记的 `GET /notes/{id}/schedule` 未入队时答 **404**。
**我本来要照抄**，然后去读 `api/errors.py`，发现卡片这边早就定了：

```python
# K3. Both are 409 rather than 404 on purpose: the *card* exists, and what
# conflicts is the request with the card's scheduling state. Answering 404
# would tell the user their card is gone when it is sitting right there.
ErrorCode.CARD_NOT_SCHEDULED.value: 409,
```

⇒ **照抄笔记会推翻一条已经写明理由的决定。** 用 409。
⇒ **而这也让三态成为后端给的**：409「不在队列」（正常的空，该给按钮）
vs 404「这张卡不存在」（另一个问题，按钮不该替它遮）vs 传输失败（**不知道**）。

## ⭐ 而「不知道」这一态，笔记那边是错的

`VaultPage` 的 `readNoteSchedule(...).catch(() => false)` ——
**任何失败都读成「未入队」**。于是后端一停，读者看到的是一个
**「加入复习」按钮，点下去必然失败**。

卡片这边按 `error.code === 'CARD_NOT_SCHEDULED'` 判断。
**本 spec 不改笔记那条**（那是 spec 028 的地盘，已记为欠账）。

## 回归测试

- 后端 `tests/unit/test_reviews_api.py` · `TestReadingASchedule`（**4 条**）
  - 未入队 → **409 + `CARD_NOT_SCHEDULED`**
  - 已入队 → 200，且**读回来的与写下去的逐字节相同**
  - 卡不存在 → **404 + `CARD_NOT_FOUND`**，并有一条测试专门说 409 与 404 为什么必须分开
  - **读没有副作用**：读过一次之后队列仍然是空的
    （⚠️ 因为界面每渲染一张卡就会读一次，**有副作用就等于每张卡自动入队**）
- 前端 `frontend/e2e/card-enrolment.spec.ts`（**10 条**）

## 变异检查（⚠️ 必填）

| 改坏哪里 | 哪个测试变红 | 结果 |
|---|---|---|
| M1 `Enrolment` 把任何失败都当成「未入队」（笔记那个形状） | `A6 · 读状态失败时说「不知道」，并且不给按钮` | ✅ **已确认变红** |
| M2 `getCardSchedule` 把**任何** `ApiError` 都当成「未入队」 | `卡片不存在时也不给按钮（404 与 409 是两件事）` | ✅ **已确认变红** |
| M3 删掉 `!converged` 守卫 | `已收敛的卡片不给入队按钮` | ✅ **已确认变红（第二轮）** |

⭐ **M3 第一轮没有变红，而那条测试是空的。** 它没有 stub 那个 schedule 读请求，
所以读走 404 → 控件落进「不知道」态 → **按钮不出现，但原因与「已收敛」无关**。
⇒ 补上 `409 CARD_NOT_SCHEDULED` 之后 M3 立刻变红。
**这是本会话第二次「少了一个 stub 所以永远变绿」，上一次是 `0012`。**

## 是否可被测试固化？

✅ 可以，而且必须分三层，后端一层、前端三层各一。

## 顺带查出来的另一件事：空队列文案

对着空库把五个页面截了图，量每页正文字数：

| 页面 | 字数 | 空态说了什么 |
|---|---|---|
| 今日 | 360 | ✅ 说了现在是什么、为什么空、下一步在哪 |
| 关注池 | 267 | ✅ 同上 |
| **复习** | **62** | ⚠️ 只说了**为什么这个队列是空的** |
| **复盘** | **74** | ⚠️ 同上 |
| 知识库 | 178 | ✅ 同上 |

⇒ **「五个空页面」这句话不准确。** 三个是合格的，**两个不合格** ——
对一个新读者来说，队列空的原因是**上游根本没有东西可排**，
而这两页从没说过。

⇒ 已改：两句都加上了「队列来自哪里」，**并且指向 spec 048 那个按钮**。

⚠️ **刻意不加「你还没有卡片」。** 页面**不知道**（`/review/due` 返回 `[]` 时
「一张卡都没有」与「有卡但都没到期」无法区分），**而一句会猜的话比没有更坏**。
已写一条反向断言把它钉住。
