# 0014 · 未分层的表单重置压过了每一个字号类，全仓控件的 `type-*` 都是死的

- **发现日期**：2026-10-01
- **严重级别**：P1（不是「看起来不对」，是**全仓性的、且不可见**）
- **状态**：已修复 + 已加门禁（`V-17`，变异已确认）

## 现象

开屏重做时，`<button class="serif type-page-title …">` 要求「进入今天」是 22px。
加完类、量出来：

```
viewport 1440x900
  .startup-enter   53 x 20px
```

**与加这个类之前逐字节相同。** 于是逐个类单独量：

| 单独挂在 `<span>` 上 | font-size | line-height |
|---|---|---|
| `.serif` | 13px | 20.15px |
| `type-page-title` | **22px** | **30px** |

类本身是对的。它挂在按钮上时是 13px。

## 根因

```css
input,
textarea,
button,
select {
  font: inherit;      /* ← 简写 */
  color: inherit;
}
```

三件事叠在一起：

1. **`font:` 是简写**，它连 `font-size` 一起重置。`font: inherit` 让字号从
   `<body>` 继承，而 body 是 13px —— 于是这条重置给每个控件都盖上了 13px。
2. **该文件 `@layer` 出现 0 次**（实测），所以这条重置是**未分层**规则。
3. **未分层规则在同等特异性下压过每一个分层规则**，也就压过了 Tailwind 的
   `utilities` 层 —— 而所有 `@utility` 字号类都在那里。

三条合起来：这条重置静默地赢过了字号体系。

## 为什么没人发现

**因为每个控件本来就都是 13px —— body 的字号。** 重置在做的事和它被写来做的
事完全一致，所以没有一处看起来是错的。这个缺陷只在**本来应该不一样大**的控件
上才可见，而在本产品里那一天之前不存在这样的控件。

⚠️ `V-12`（「字号只能写在那把尺子上」）抓不到：它扫的是组件里手写的
`text-[NNpx]`，而这里是**样式表的一条简写赢掉了组件确实写了的类**。V-12 是对的，
它问的是另一个问题。

这与本仓已记录的 `.mark` 缺陷同族（`status.md` §〇：「36 个元素在向它要一个它
没有的颜色」）—— **未分层规则压过分层规则**，那一次是 `border-*` 工具类，这一次
是字号类。

## 修复

把重置放进 `@layer base`：

```css
@layer base {
  input, textarea, button, select {
    font: inherit;
    color: inherit;
  }
}
```

实测：按钮从 `13px / 20.15px` 变成 **`22px / 30px`**，`53x20` 变成 `81x28`。

⚠️ **没有把整份样式表分层，是有意的。** 分层是更好的答案，但它是一次独立的改动，
和一次 bug 修复放在同一条提交里会让 bug 修复本身读不懂。现在只保证**这一条重置**
在正确的层里（`V-17`）。
