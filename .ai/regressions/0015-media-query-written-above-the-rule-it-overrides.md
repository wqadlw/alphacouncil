# 0015 · 媒体查询写在被覆盖规则之上，零效果，且没有任何东西会红

- **发现日期**：2026-10-01
- **严重级别**：P2（一个规则的意图完全落空，产品无可见损坏）
- **状态**：已修复 + 已加门禁（`V-18`，变异已确认）

## 现象

开屏的左栏与画框要对齐上下边（左栏第一行落在画框顶边、署名落在底边）。做法是
让 `.startup-copy` 变成 `stretch` + `space-between`。

覆盖写在了 `@media (min-width: 1180px)` 块里：

```css
@media (min-width: 1180px) {
  .startup-copy {
    align-self: stretch;
    justify-content: space-between;
    gap: 24px;
  }
}
```

量出来：

```
.exit   y=481   （加之前 481）
.signoff y=531   （加之前 531）
```

**逐像素不变。什么都没动。**

## 根因

两个原因，第二个才是关键：

1. `@media` 块在 L332，`.startup-copy` 规则在 L350 —— **覆盖在上，被覆盖者在下**。
2. **该文件 `@layer` 出现 0 次**（实测）。没有分层时，未分层规则**只按位置排序**，
   与特异性无关。同特异性下，位置靠后的赢。

⇒ 媒体查询是**条件**，不是**优先级**。它是「在某些视口下也适用」，不是「比别的话强」。

这与 0014 同族：**都是零分层的后果**，只是这次赢的是位置而不是层。

## 三种修法，选了一种并说明为什么

| 修法 | 后果 |
|---|---|
| 只把覆盖挪到被覆盖规则下方 | 修好这一处；下一个 `@media` 覆盖还会踩 |
| ✅ **挪下去 + 写下为什么 + 加 `V-18`** | 本次缺陷固化，形状被守住 |
| 给整份样式表分层 | 结构性答案，但与一次布局修复放在同一条提交里会让布局修复读不懂 |

第三条是对的答案，留作独立改动。**「我这次选了第二条」必须写下来**，否则三年后
的人会以为位置顺序是这个项目的层叠模型。

## 回归测试

`frontend/src/styleguide.test.ts` · `V-18 · never writes a @media override above the rule it overrides`

⭐ **结构检查而不是 grep，理由是 grep 看不见这个缺陷**：覆盖规则拼写完全正确，它只是
从来没赢过。grep `align-self: stretch` 会找到它并判定它没问题。

所以它走整份样式表、跟踪花括号深度，收集 `@media` 块内声明的选择器与顶层选择器，
报告同时出现在两处、且**顶层那份在后面**的选择器 —— 那正是「媒体查询输了」。

## 变异检查（⚠️ 必填）

| 改坏哪里 | 哪个测试变红 | 结果 |
|---|---|---|
| `.startup` 基础规则与其 `@media` 块对调 | `V-18 · never writes a @media override above the rule it overrides` | ✅ **已确认变红**（exit 1） |

⚠️ **变异不是撤销修复，而是重建缺陷 —— 而且第一版变异脚本失败了。**

第一版脚本试图搬动 `.startup-copy` 覆盖，抛了 `AssertionError`。原因是那条覆盖
**已经被删掉了**：量出来它是回归（左栏被拉成 480x796，中间三个 200px 的洞，四行
字读起来是四个碎片而不是一个陈述）。**搬不动的东西说明变异选错了** —— 撤销修复
只能证明门禁记得修复，重建形状才能证明门禁理解形状。

`.startup` 本身就是一个活例子：它在顶层（L313）与 `@media`（L332，正确地在后）
都声明，响应式规则正常工作。对调这两处把一条正常的规则变成死的，而样式表与测试
套件里没有别的东西改变。

## 是否可被测试固化？

✅ 可以 —— 「这个选择器在两处声明且顺序错了」是从源码可读出的结构事实。

⚠️ 这条门禁**故意不做成 CSS 解析器**：它靠数花括号跟踪嵌套，忽略字符串（这份样式表
里没有字符串）。一份会误报的门禁会被删掉，而这一份跑在一份已经被 formatter 处理过
的样式表上。

## 遗留

⚠️ `V-18` 只查**选择器相同**的情况。以下两种它看不见：

- 媒体查询里的规则与顶层规则**选择器不同但会互相影响**（如 `max-width` 覆盖一个
  `width`）；
- 分层一旦引入，「位置」就不再是唯一依据 —— 那时 `V-18` 应当**退役**，而不是
  继续按位置判断。

⇒ 已做：本条记录写明了这两种盲区；引入分层时必须同时处理 `V-18` 的退役，登记在
`.ai/logs/changes/2026-10-01-plan.md`。
