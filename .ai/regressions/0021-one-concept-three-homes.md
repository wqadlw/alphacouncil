# 0021 · 一个概念有三个家，而其中两个是对的、一个是漂移 —— 类型完全看不出来

- **发现日期**：2026-10-02
- **严重级别**：P2（*读者按的按钮与记录里写的不一致*，不是数据丢失）
- **状态**：已修复 + 已加门禁（`S-16`，变异 M1/M2/M3/M4 均已确认转红）

## 现象

同一个 FSRS 评分 `hard`，三份中文：

| 家 | 文件 | `again` | `hard` | `good` | `easy` |
|---|---|---|---|---|---|
| 笔记队列 | `RecallView.tsx:60` | 我的想法变了 | **想得起来，但有点犹豫** | 还是我的想法 | 太熟了 |
| 教训队列 | `LessonRecallView.tsx:49` | 我的想法变了 | **想得起来，但吃力** | 想得起来 | 张口就来 |
| **复习流水** | `timelineAdapters.tsx:160` | 我的想法变了 | **想起来了，但慢** | 记得 | 不用想 |

⚠️ **前两处不同是有理由的**：`RecallView.tsx:51-53` 与 `LessonRecallView.tsx:43` 各花整段论证
「笔记的 `again` 是『我的想法已经变了』而教训的不是」—— 笔记是读者写的，教训是系统自己得出的结论。

**第三处不是理由，是一个缺陷。** `NoteReviewTimeline` 由 `VaultPage.tsx:1016` 渲染，
那是**笔记详情里的复习流水**。

⇒ **读者在队列里按「想得起来，但有点犹豫」，事后的记录里写的是「想起来了，但慢」。**

## 为什么所有既有机制都没看见

| 机制 | 为什么绿 |
|---|---|
| TypeScript 类型 | ⭐ **线上的四个值一直完全相同**，只有屏幕上的字不同。`ReviewRating` 是对的 |
| 后端测试 | 后端不知道中文 |
| E2E | 没有一条测试从「按按钮」走到「看流水」 |
| `recallContract.test.ts` | 它断言的**正是那三张表之一** —— ⭐ **它守住了队列，漏掉了流水** |
| lint | `hard: '想起来了，但慢'` 语法上没问题 |

⚠️ `recallContract.test.ts:6` 写着「句子本身是被钉住的 —— 从组件 import，而不是抄一份」。
**那句话是对的，而它只对三张表里被钉住的那两张成立。** 一个从组件 import 的常量
和一份没被 import 的拷贝，在测试眼里长得一模一样。

## 这与 spec 028/045 是同一个问题，深一层

那两份 spec 开出来是为了回答**「我复习过 5 次，为什么今天又来了」**。

而流水连**「我当时按的是哪个」**都答不出来 —— **它是「发生过什么」，却连发生过的那次是
哪个按钮都对不上。**

## 修复

1. 新建 `frontend/src/components/knowledge/ratings.ts`，**两张表**（`NOTE_RATINGS` /
   `LESSON_RATINGS`），⭐ **两个队列的词汇差异被保留**，因为那是有理由的
2. `RecallView.tsx` 的 `RATINGS` 改为从 `./ratings` 再导出（`recallContract.test.ts`
   断言的就是这个名字，**不动它是本 spec 范围之外**）；**它的论证文字留在原处** ——
   表格归 `ratings.ts`，「为什么」归读者按下按钮的那个屏幕
3. `LessonRecallView.tsx` 同上
4. `timelineAdapters.tsx` **不再持有任何标签字符串**，改为 `labelsOf(NOTE_RATINGS)`
5. `ratings.test.ts` 8 条断言

⚠️ **`RecallView.tsx` 的注释没搬走，这不是遗漏。** 「把文字搬到代码旁边」与
「把论证留在读者遇到它的那块屏幕上」是两件不同的事。

## 门禁：`S-16`（spec 049）

⭐ **本条回归的真正产出不是那三行标签，是 `S-16` 本身** —— 因为
「同一个概念一个家」这个形状已经出现过四次（`0010` 的两套 EMA 定义、`0002` 的约束台账、
`0011` 的规则标题比它守的宽、加上本条），**而前四次都没有留下任何东西**。

`S-16` 读 FastAPI 一直在吐的 `openapi.json`，逐个枚举要求前端有**精确镜像**或
**一条说清「它是什么」的豁免**。实测基线：

```
openapi.json 发布 30 个枚举
其中 24 个在前端有一份手写镜像
24 个当前全部精确相符          <- 今天没有活的类型漂移
而后端加一个值时，没有任何东西会红   <- 这才是全部的发现
```

### 双向

| 方向 | 后果 |
|---|---|
| 后端有、前端没有 | 值到达后落进 `switch` 的 `default`，**静默** |
| 前端有、后端没有 | 客户端等一个永远不会到的值，**那一支是死代码，而且看起来是对的** |

### 三张豁免表，三个不同的键

| 表 | 匹配键 | 「还在吗」问的是 |
|---|---|---|
| `NOT_MIRRORED` | 后端枚举的**名字** | 后端还在发布吗 |
| `FRONTEND_ONLY` | 前端联合类型的**值集合** | 前端那个联合类型还在吗 |
| `SAME_VALUES_DIFFERENT_MEANING` | 前端联合类型的**名字** | 同上 |

⭐ **这不是不优雅，这就是它们的区别** —— 而第一版把它们塞进一张表，于是
一次干净的树上跑出 6 条「已豁免但不再声明」（`F-203` `F-204`）。

⚠️ **豁免的理由必须写「它是什么」，不许写「不适用」** ——
一句无法被反驳的理由不是理由，而这个文件半年后会被一个需要反驳它的人读。

## 变异

```
M1  后端给一个被镜像的枚举加一个值            exit=1  RED    findings 19
M2  前端从被镜像的联合类型里删一个值          exit=1  RED    findings 19
M3  删掉一条仍然需要的 NOT_MIRRORED 条目       exit=1  RED    findings 22
M4  把一条豁免的理由换成「不适用」            exit=1  RED    findings 19
```

⭐ **M3 与 M4 才是关键的那两条。** M1/M2 证明比较成立，M3/M4 证明**豁免不是一个带注释的洞** ——
而后者才是漂移规则活不过一个月的原因。

### 前端那条测试也有一次变异，因为它的边界值得写下来

```
M1  timelineAdapters 重新长出自己的标签表    exit=1  RED     3 failed
M2  NOTE_RATINGS 自己的措辞变了（对照组）    exit=0  GREEN   <- 记录在案的边界
M3  注释里抄一份那张表                      exit=0  GREEN   <- 注释是散文，不是第二个家
```

⚠️ **M2 是绿的，而且是应该绿的**：一张表内部的措辞是产品决定，不是漂移；
而**表被重新抄一份**（M1）红 3 条。⭐
**知道自己哪些断言是哪一种，是一道门禁和一件装饰品的区别**（`F-207`）。

## ⭐ 附：收敛 `QueueName` 时挖出一条**注释比它的代码宽**的假承诺

`routing.ts:201-203` 写着：

> Exhaustive over `QueueName` **by construction** — the parameter is the union, so
> adding a queue server-side without adding a route here is a compile error

而代码是三元：`queue === 'cards' ? REVIEW_HREF : RETROSPECTIVE_HREF`。

⚠️ **三元对联合类型不做穷尽。** 加第三个队列，它照样编译通过 ——
**注释承诺的编译错误从来不存在。** 这是 `regressions/0005`（文档断言代码不做的事）
穿着一件注释的外衣。

⇒ 改成 `Record<QueueName, string>`，承诺变成真的。⭐ **而承诺要测，不能信**：

```
M1  联合类型加第三个值，Record 仍是两个        exit=2  RED   报错点名 QueueName
M2  联合类型加第三个值，换回三元版本           exit=0  GREEN   <- 注释藏着的那个 bug
```

⭐ **M2 是关键的那一条**：只有 M1 时，「Record 修好了它」和「tsc 本来就会抓」完全无法区分。
**M2 通过，正是旧代码从来没有那个保证的证据。**（`F-211`）

⚠️ 而且这一段里 **spec 049 §2.6 写错了方向**：它说 `QueueName` 收敛到 `routing.ts`，
而**实测导入图说相反** —— `api.ts` 不 import 任何东西，是叶子；按 spec 写的方向会让
`api.ts` 反过来 import `routing.ts`，**那是一个环**。
⭐ **计划是预测，量测不是**（`regressions/0017`）。

⭐ **我先把「可被格式化骗过的规则不是规则」写进了规则的 docstring，然后自己用一条
单行正则骗过了自己** —— `api.ts:533` 的 `MetricState` 一行一个值，全仓被镜像得最多的
那个联合类型它看不见。⇒ 联合类型正则改成跨行，并**拿十种形状探测，其中两种是它必须不
匹配的**（`F-202`）。

⚠️ 而这个 bug 的严重级别不是「规则不准」，是**「漂移检测器在自己该抓的东西上报干净」**
—— 它被信任。
