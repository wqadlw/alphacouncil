# `.ai/checks/data/` —— 运行时扫库检查

> **检查对象 = 数据库里的数据本身。**
> 建立：2026-09-26 · 依据 `references/deep-dives/08-portfolio-performance.md`（24 条一致性检查清单）

---

## 一、与 `static/` 的区别

| | `data/`（本目录） | `static/` |
|---|---|---|
| 检查对象 | **数据内容** | **源码** |
| 什么时候能发现 | 数据写进去之后 | 写代码时（编译前） |
| 典型缺陷 | 悬空引用 · 缺字段 · 口径混用 | 裸 HTTP · 布尔状态 · 预测字段 |

**⚠️ 数据检查不能替代数据库约束** —— 能放进 CHECK / 触发器的规则，**优先放数据库**（宪法 5.4，第 ④ 层）。
**本目录只处理"数据库层表达不了"的跨表/跨行一致性。**

## 二、检查清单

### 2.1 引用完整性（数据库 FK 抓不到的）

| # | 检查 | 说明 | 可写性（2026-10-04 实测）|
|---|---|---|---|
| D-01 | **悬空引用** | 决策指向不存在的标的。⚠️ **原文写的是 `decisions.target_id`，而该列不存在**；实际的是 `market` + `code` 这一**对**。⚠️ 且 `decisions` 有复合外链，**这个状态数据库拿不到** | 已实现。⚠️ 每次运行都发 `note` 说明“问不出来” |
| D-02 | **孤儿实体** | 没有对应标的的持仓记录。⚠️ **2026-10-06 实测：任何 migration 都没有 `position`/`holding`/`portfolio` 表** ⭐⭐ 所以这一条**无表可读**，⭐⭐ **它的编号因此没有被占用** | 未实现（无表） |
| D-03 | **交叉引用不一致** | 决策里写的标的 ≠ 持仓里的标的 |
| D-25 | **悬空外键**（spec 060 · 2026-10-06） | ⭐⭐ **读 `pragma_foreign_key_list`，⭐⭐ 对每一条已声明的引用查一遍孤儿行** ⭐⭐ —— 实测 **17 张表 21 条引用**。⭐⭐ **不是给表名写死清单**：⭐⭐ schema 已经声明了一切，⭐⭐ 读回来意味着**新增外键当天就被覆盖** | 已实现 · 只读 · **`warning`** ⭐⭐ |

⭐⭐⭐ **D-25 为什么是 `warning` 而不是 `error`（2026-10-06 实测，不是为了让门禁变绿）** ⭐⭐⭐

| # | 量到的事实 | 推论 |
|---|---|---|
| 1 | `storage.db.connect` 与 `connect_for_migration` 都报 `PRAGMA foreign_keys = 1`；⭐ 裸 `sqlite3.connect()` 报 **0** | ⭐⭐ **产品代码今天写不出孤儿行** ⭐⭐ |
| 2 | `grep 'DELETE FROM decisions'` **零命中** | ⭐⭐ 那 4 行既**不会**再产生，⭐⭐ 也**不能**删（决策是读者的手写，⭐ 只增不改） |
| 3 | `checks/data.py` §「Which database」：数据检查**读的是读者自己的库**（临时库会让所有检查变空转） | ⭐⭐⭐ **这条规则永远不可能因为本仓库的缺陷而失败** ⭐⭐⭐ |

⭐⭐⭐ ⇒ 报成 `error` 就是**永远红**，⭐⭐⭐ 为一段谁都不能删的历史，⭐⭐⭐ **而一个永远红的门禁就是一个会被忽略的门禁** ⭐⭐⭐ —— ⭐⭐ 这正是 `D-01` 自己 `fix` 里警告的事。⭐⭐⭐

⭐⭐ **机制本身的代码级门禁是 `S-19`（`static/`），⭐⭐ 它可以是 `error`，⭐⭐ 因为它关于代码。** ⭐⭐
⭐⭐ 两条职责分开：**D-25 告诉读者「你的记录里有 4 行指向不存在的决策」，⭐⭐ S-19 保证产品不会写出第 5 行。** ⭐⭐

⭐⭐⭐ **D-25 一落地就报了真实数据** ⭐⭐⭐ —— 2026-10-06，读的是读者自己的库：

```
decision_review_state(decision_id)=(2026-09-30T11:26:24.998Z) → decisions
decision_review_state(decision_id)=(2026-09-30T11:26:25.022Z) → decisions
decision_review_state(decision_id)=(2026-09-30T11:26:25.037Z) → decisions
decision_review_state(decision_id)=(2026-09-30T11:26:25.053Z) → decisions
```

⭐⭐ **四条相隔 25ms ⭐⭐ —— 那是循环在写，⭐⭐ 不是人在记。** ⭐⭐ 而 `D-01` 守着 `decisions → instruments`，⭐⭐ **没有任何东西守着 `decision_review_state → decisions`。**

## 三、实现约束

1. **空数据库必须通过** —— 新用户第一次打开不能报错。
2. **每条检查必须能独立运行**（`--only D-15`），便于排错。
3. **每条检查必须有 fixture 测试** —— 一个"有问题"的库 → 确认它报错。
4. **`AUTO` 修复必须可逆** —— 修复前先记录被改的行。
5. **⚠️ 涉及"用户必须亲手做"的修复，`kind` 必须是 `MANUAL`**（写决策 / 打分 / 改理由）。
