## 二、⭐ 关于"衬线分工"的一条实测证据

规范 §2.1 说 **衬线只用于"标题与主张"**。这一轮第一次能**实测**它：

| 元素 | 字族 | 字号 |
|---|---|---|
| `H1 600519.SH` | **Songti SC（衬线）** | 17px |
| `H2/H3` × 7（小节标题） | **PingFang SC（无衬线）** | 11px |
| 卡片主张 / 复盘理由 / 恢复年数 | **Songti SC** | 15–20px |

**标题与读者自己写下的句子是衬线，界面是���衬线** —— 这正是规范要的分工，
而它是靠"小节标题改成 11px 铬饰"顺带达成的，**不是靠额外加什么**。

⭐ 顺带记一条**不能自动化的**：这个分工成立的前提是**每个小节标题都还是
`<h2>`/`<h3>`**。改成 `<div>` 视觉上一模一样，但屏幕阅读器按区域导航时就看不见了。
E2E 也是靠 `getByRole('heading', …)` 钉住的 —— **这是保住语义的那根钉**。

## 三、⭐ 迁移过程中撞出的一个**真缺陷**（不是样式问题）

`DecisionSection` 的每一行决策原本渲染了**同一个时刻两次**：

```jsx
<span>{formatMoment(decision.id)}</span>   // 2026-09-28 14:12
<span>{decision.id}</span>                 // 2026-09-28T06:12:47.514Z
```

`decisions.id` **就是那一刻本身**（主键是写入时刻，所以 `get_by_id` 是精确的，
这在 `decisions.py` 的注释里写着）。所以第二行是一个**正确但无用**的标识符：
读者无法拿它做任何事，而 24 个字符让它成为整行最宽的东西。

**和我前一轮在今日页犯的是同一个错** —— 把内部标识符当成人能读的标签。
已删掉。要找那一行，靠的**不是读代码，是渲染出来看**。

⭐ 这条比样式问题值得记，因为它是**同一个错误犯了两次**：
第一次是我在今日页新写的，第二次是**原有代码里一直存在的**。
说明"这类错误"不是粗心，而是**默认假设 id 可读**。

（`0→1→2→3→clamp→up`）才发现代码是对的。

### 4.1 ⭐ 还有一个：**自检脚本自己撒谎**

写这份变更日志的脚本末尾有一行自检（扫控制字符与 CR），用来保证中文没被写坏。
它先写成：

```python
return 0 if bad else 1      # <-- 漏了 not
```

于是它**打印「control=0」然后退出 1** —— 一个干净的文件被报成失败。
我是从上一个脚本复制过来时漏了那个 `not`，**而复制的时候正好没看这一行**。

⭐ 这与台账里记的 4 次 harness 失败、与 `styleguide.test.ts` 的正则回溯，
**是同一族**：**检查器自己出错了，却把错误报成被检查对象出错。**
它之所以能被发现，**只因为退出码和它自己打印的那个数字对不上**。

⭐ 于是这一轮多出一条纪律（已写进脚本注释）：

> **断言看退出码，不要看同一个程序自己打印的消息。**
> 一个程序的自检消息与它的退出码矛盾时，**默认是它错了** —— 而不是它检查的东西错了。
