# 2026-09-28 · K3 复习界面与 API（spec 019）

> 四段式台账（宪法 10.5）。**append-only：只追加，不改写。**
> 执行者：OpenCode（Codex · Space Bunny Free）· **同一天第五批**

---

## ① 想做什么

把 K3 做完。选它而不是开 J3 的理由：**产品侧最弱的一环是"主人根本用不到"** ——
K1/K2/K3 此前全都没有界面。

但 spec 018 留了一句债必须先还：*"界面必须先回答'不讨好用户怎么落地'"*。

## ② 做了什么

### 1. 先回答那个问题（写在 spec §一，因为它决定了整个界面）

**红线 13 的实现是一个"缺席"，不是一个功能。**

复习界面的全部输出只有三样：主张 · **来源始终可见** · **下次什么时候回来**。
界面**不会做**的事，逐条对应红线，并全部被 E2E 钉住：

| 不做 | 红线 |
|---|---|
| "你记住了 87%" | 9（`get_card_retrievability` 根本不调用） |
| "连续复习 5 天" | 11 |
| "已复习 3 / 8" 进度条 | 11（把"清空积压"变成可游戏化的数字） |
| 答错时说"没关系" | 13 |
| 答错时标红 / 计数 | 13/14 |

> **红线 13 之所以难落地，通常是因为被理解成"要设计一些不讨好的提示"。
> 它恰恰是不要设计任何东西。** 一旦开始评价，就必然有人在评价某个方向。

### 2. 「现在不是时候」是一等公民

S-05 原话：**「"暂不处理"是特性不是拖延」**。

五个按钮**并列、同等显眼**，不折叠进"更多"。理由不是 UX，是红线 14：
如果用户现在答不出来而产品只给"忘了"，他就必须撒谎（选"记得"）或放弃队列 ——
**两个都是产品造成的**。而 spec 018 已保证推迟**不产生评分、不改记忆强度**，
所以诚实选择是零成本的。

### 3. 逐条对照后发现**两处与已采纳解读的偏差**（ADR-0028）

| 解读 | 原文 | 实现 | 处置 |
|---|---|---|---|
| **S-07** | 记忆有 `priority`/`stability`/**`retrievability`** 三个独立维度 | **不计算 `retrievability`** | 记录理由：它是"你此刻能记住的概率"，**那是成绩** |
| **S-03** | 默认排序按 priority，不按时间 | 队列**只按 `due_at`** | 记录理由：把 priority 套到队列上是**给用户的积压排名**，撞红线 11 |

**如实记录，不悄悄保留。** 这是我今天第二次做这件事（第一次是 spec 016 的 ADR 双真源）。

### 4. 落地

- **API 三端点**：`POST /cards/{id}/schedule` · `GET /review/due?as_of=` · `POST /review/{id}`
- ⭐ **队列用独立前缀 `/api/v1/review`**，因为 `GET /cards/{card_id}` 会吞掉 `/cards/due`。
  靠注册顺序能糊过去，但那是**换个顺序就断的隐藏耦合** —— 队列是"界面"不是"卡的子资源"
- ⭐ **红线 9 写进契约**：`ScheduleRead` / `ReviewReceipt` 枚举字段，
  `TestTheResponseCarriesNoScore` 断言字段集合**恰好**是那三个，没有第四个
- ⭐ **`duration_ms` 客户端提交 → 422**：时长必须服务端测，客户端能填的就是表演
- **前端**：`#/review` 页面 + 路由 + API 封装

## ③ 得到了什么样的结果

- 门禁 **10/10 绿，退出码 0**
- 测试 615 → **637**（+22 API），E2E 15 → **23**（+8）
- `dev.py eval`：红线 11 `none → partial`，**通过率仍是 5/15**

### 三个只有真跑起来才会遇到的问题

| # | 问题 | 为什么值得记 |
|---|---|---|
| 1 | 新错误码没注册进 `CODED_ERRORS` | 领域抛了带码的错误，API 却回 **400** —— 全部失败长得都像"请求格式错了"。**码定义了不等于接上了** |
| 2 | `GET /cards/due` 被 `GET /cards/{card_id}` 吞掉 | FastAPI 按注册顺序匹配。**能糊过去的修法都是隐藏耦合** |
| 3 | 对不存在的卡做复习返回 409（"未排程"）而不是 404 | 409 说的是"卡存在但状态冲突"，**"你的卡没了"是另一回事** |

### 变异检查

本轮 4 个（含"字段里多一个成绩字段"）—— 明细见下节。**3 个当场变红；
1 个（给 `ScheduleRead` 加一个 `score` 字段）真的变红了**，因为
`TestTheResponseCarriesNoScore` 是 `assert fields == {...}` 而不是 `assert not fields & forbidden`
—— **后者在有人加字段时会静默通过**。

## ④ 留下了什么

### 新表面

- **`#/review` 复习页** —— 五按钮并列，答完只给一个日期
- **API 三端点** · `ReviewRequest` 的形状校验（"复习必须有评分、推迟必须没有"）
- **ADR-0028** —— S-07 / S-03 两处偏差与理由

### 红线 9 现在被**两处**同时守着

| 层 | 机制 | 拦住什么 |
|---|---|---|
| 契约 | 后端**不发送**成绩字段（字段枚举测试） | 有人给 API 加一个 `score` |
| 表面 | E2E 断言页面上不出现百分数/连续/进度 | 有人在前端**算**一个出来 |

> 单独任何一处都够挡一次意外；**两处一起才挡得住习惯。**

### 未做（明确划界）

| 不做 | 为什么 |
|---|---|
| 标的页卡片的「加入复习 / 下次复习 N 天后」 | 卡片区已有录入/核实/收敛三个动作，再加一个会变成一排按钮。已登记 |
| 复习历史界面 | 流水在库里、有 API，但**历史是给自己看的**，不是产品表面 |
| 批量复习 / 键盘流 | 会把复习变成可快速刷完的机械动作 —— 那正是红线 11 反对的 |
| 推送 / 每日提醒 | 红线 11，且 `.ai/eval` 红线 11 的 gap 明确点到了它 |
| `duration_ms` 的统计视图 | 红线 11：只自省，不排名 |

### eval 的诚实账

`partial 2 → partial 4`，`none 8 → none 6`，**通过率 5/15 一动不动**。

两条红线的机制都在了，但**都没有"强制手段"**：
红线 7 缺"J5 让每条教训自动排程"，红线 11 缺"别处的检查"。
**把 `partial` 算成通过会让数字好看，文档就是假的。**
