## 1. 为什么改

v2.0 写于 **2026-09-26 上午**，当时**只读完了 2 篇深度解读**（wealthfolio / anki），因此宪法的第二、四、五、六条只覆盖了 27 项决定。

**当天完成了全 11 篇深度解读，累计 188 项可落地决定**，其中 **15 项是对既有设计的修正**（不是新增，是**改我们原来的设计**）。

**这 15 项修正没有落进任何 `.ai/` 文件** —— 它们只存在于 `references/deep-dives/README.md` 的一张表里。
**一份只写在调研笔记里的修正，等于没有修正。**

### 1.2 四条跨 5 个以上项目独立确认的结论

1. **只增不改**（wealthfolio / anki / langfuse / mem0 / open-science）—— 且 **mem0 是走过弯路后退回的**。
2. **"检查"必须带"修复"**（wealthfolio / portfolio-performance / OpenSpec / primitives）。
3. **"确实没有" ≠ "出错了"**（portfolio 三种"空" / akshare `ValueError` vs `RuntimeError` / open-science "缺凭据不是空列表" / langfuse 禁止兜底）。
4. **红线不进 CI，就只是意图**（primitives 的 axe / akshare 的变异测试 / foam 的 `_verify` / OpenSpec 的 scenario）。

### 1.3 本系列最重要的结构性结论

> **从「纪律」到「机制」的四个层次**：
> **① 文档**（没代价，靠自觉）→ **② 检查**（事后发现）→ **③ 类型/编译期**（编译不过）→ **④ 数据库/运行时**（运行直接失败）
> **判据：能不能把这条规则从 ① 移到 ③ 或 ④？能移就必须移。**
>
> **一条规则如果只存在于第 ① 层，它迟早会被违反 —— 不是因为有人故意，而是因为没人记得。**
