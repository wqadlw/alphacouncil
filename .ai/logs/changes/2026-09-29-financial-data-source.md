## 一、⭐ 本来只打算接一个数据源，结果先照出**三处文档比实现宽**

规格写在 `spec 043`，执行顺序是「依赖 → 迁移 → provider」。⭐ 中间插了一段，因为
写 provider 要碰 `ErrorCode`，一碰就发现：

| # | 文档说 | 实际是 |
|---|---|---|
| 1 | 「限流与封 IP **必须**分成两个 code」（`error-codes.md` 就写在表下面） | `_guard` 把 **403 和 429 抛成同一个** `ProviderBlockedError` |
| 2 | `DATA_SOURCE_IP_BLOCKED` = 封 IP（`RemoteDisconnected`） | ⭐ **全项目没有一个地方 raise 过它** |
| 3 | `core/http.py`：「no jitter, no serialisation —— 那些在 `router.py` 里已经有了」 | `providers/` 里除本篇新写的文件外，**一个 `sleep` 都没有** |

⭐ 第 1、2 条是同一个：**枚举上有两个成员、文档里有一条明确的要求，而由零个地方产生。**
这不是「新功能没做」，是**规则已经写死了而实现没跟上** ⇒ `F-126`。

## 二、⭐ 拆了，而且**拆到行为上**

只改枚举是没用的——`F-126` 的教训就是「拆分若不改变行为就只是一次改名」。

| code | 谁产生 | 冷却 | 依据 |
|---|---|---|---|
| `RATE_LIMITED` | HTTP **429** | **30 s** | 降速 |
| `FORBIDDEN` | HTTP **403** | **300 s** | 原值不变 |
| `IP_BLOCKED` | 源**自己**点名（BaoStock `10001011`） | **20 h** | 文档写的「请等待约 20 小时」 |

顺带把 `_failure` 改成**读 `exc.code`**：⭐ 它以前在每个分支里**重新推导一遍**那个 code，
所以新加一个 `ProviderError` 子类从写出来那一刻起就是活的，会被静默报成
`DATA_SOURCE_UNREACHABLE`，直到有人想起来改这个函数。类自己已经带着答案了。

### ⭐ 而文档里那条错误触发条件，我**没有**实现

`error-codes.md` 说 `RemoteDisconnected` = 封 IP。**照做会有害**：

* 它绝大多数是**空闲 keep-alive 被对端回收**，不是封禁；
* ⭐ 一次网络抖动就能让一个健康源**整天不可用**（20 小时）；
* ⭐ 而且 **HTTP 状态码本身就区分不了**「你的地址被封」和「这个 URL 不可访问」。

⇒ `ProviderIpBlockedError` **只**在源自己点名时抛出。`RemoteDisconnected` 仍然是
`DATA_SOURCE_UNREACHABLE`，而那个判断是对的：它就是一次会自愈的传输故障。
**这条已写回 `error-codes.md`**（附理由），不是默默不实现。

### ⭐ 第三条（指向不存在的实现）只改了注释

`core/http.py` 那句指路已经改掉，并写明 §7.8 要求的七项里**行情路径缺三项**。
⚠️ 缺口本身**没有**在这一篇补上——那是一次热路径上的行为变更，值得单独的 spec；
但**一条指向不存在实现的注释本身就是缺陷**，先修它是这一步该做的。

## 三、⭐ PIT 存储：主键带 `announced_at`，因为公司会重述

`constitution.md` 早就为它写好了规则（红线 15/17），本篇**执行**：

```sql
PRIMARY KEY (market, code, period_end, announced_at, source, fetched_at)
```

⭐ 「**重述是一个更晚 `announced_at` 的新版本，不是对旧行的覆盖**」——
如果主键只有 `(market, code, period_end)`，重述就只能覆盖，而
2024-01-01 看到的和 2024-06-01 看到的**必须是两个不同的数**。

⭐ **`fetched_at` 也在主键里，而且是被一个测试逼出来的。** 第一版主键到 `source` 就结束，
于是「同一天同一家源把同一份公告又报一遍」撞主键。⭐ 而 `INSERT OR IGNORE` **不能**用来解决：
SQLite 在那个子句下把**任何**约束冲突都变成静默跳过，**包括**「公告日不得早于报告期」
那条 CHECK——于是该被拒的行会**悄悄消失**而不是被拒。

⭐ 三处我自己写错、被测试当场抓住的地方，都留在了注释里：
1. **GLOB 只看形状不看日历**：`2024-13-45` 稳稳通过，补 `date(...) IS NOT NULL`（⚠️ 少
   `IS NOT NULL` 的 `date(x)` 是一条**永远为真**的约束，CHECK 遇 NULL 判为通过）。
2. **`strftime` 认 `/` 作分隔符**：`2025/04/03` 通过了「格式」检查，而
   `announced_at <= ?` 是**字符串比较**，格式宽松就让 PIT 的边界由字符表决定。
3. **`float("nan")` 不抛异常**。⭐ 存进 SQLite 的 `nan` **比 NULL 更坏**：`nan > 0.5` 为假
   （判据说「没越过」），而 `nan != 0` 为**真**（任何和零比较的判据都以为它是个真读数）。

## 四、⭐ 变异 35 个：34 杀 + 1 个声明等价，而**存活的那几个全是真缺口**

⭐ 第一轮 **5 个存活**，没有一个是「测试写得不够多」这种泛泛的话：

| 变异 | 真实缺口 | 补的东西 |
|---|---|---|
| 「空单元格 → `0.0`」删掉整个守卫 | 守卫**列举的四个值全都**也让 `float()` 抛异常 ⇒ **它无法与「不存在」区分** | ⭐ 后来证明这守卫**整体就是多余的**，删了 |
| 两列股本互换 | fixture 里 `totalShare` 与 `liqaShare` **都填 `12.56`** ⇒ 「流通股 = 总股本」对真公司是**真话** | 每个字段取不同值 |
| `market` 有了 `DEFAULT 'sh'` | ⭐ **没有任何测试写过「不提供市场」** —— 而缺市场静默变上海，`000001` 与指数撞 | 新增一条 |
| 指标列 `NOT NULL DEFAULT 0.0` | 三个「缺失」测试恰好都空的是**另外三列** | **八列全部参数化** ⇒ `F-128` |
| `exc.code` 被忽略 | ⭐ 我把目标指向了**不走 `_failure` 的测试文件** | 换目标 ⇒ `F-131` |

⭐ 还有一个**脚本自己的错**：`BACKEND` 写成 `scripts/`，pytest 收集不到测试并以 **5** 退出，
脚本据此打印「BASELINE IS RED」⇒ **对不存在的运行结果下了正确的结论** ⇒ `F-130`。

⭐ 最后剩一个存活，**声明为等价并写了理由**：删掉 `ORDER BY ..., fetched_at DESC` 测试照过，
因为 `idx_financial_reports_pit` 本身就按 `fetched_at DESC` 建。
⇒ 确定性来自**索引**不是来自查询；两处都留着，**依赖写进了索引注释** ⇒ `F-132`。
