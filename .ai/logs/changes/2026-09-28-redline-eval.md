# 2026-09-28 · 红线评测集与 S-13（spec 017）

> 四段式台账（宪法 10.5）。**append-only：只追加，不改写。**
> 执行者：OpenCode（Codex · Space Bunny Free）· **同一天第三批**

## ① 想做什么

ADR-0027 把 `make eval` 抬成了明确优先级（agent 三件套启用条件的一半）。
开工前先问了一个更基本的问题：**它到底要评测什么？**

三条路：

| 选项 | 问题 |
|---|---|
| 评测运行期 LLM agent | **运行期没有 agent**（ADR-0027）—— 评测不存在的东西 |
| 评测开发流水线 | 已被静态检查 + 变异检查覆盖，再做一遍是重复 |
| ⭐ **评测产品红线** | 宪法第一条是一张 15 行表，**第三列逐行自称"实现层面的强制手段"，而从来没有任何东西查过那一列** |

选第三条。理由：**"我们的红线在代码里被强制执行"是一句断言，
和 v1 那份描述了四个没人建过的包的架构文档是同一类断言。**
而断言如果不计数，就只是叙述。

## ② 做了什么

### 1. `.ai/eval/redlines.json` —— 15 条红线逐条登记

每条含 `coverage`（`full` / `partial` / `none`）、`verifier`、`evidence`、`gap`。
**`partial` 与 `none` 强制要求写 `gap` 说清差在哪。**

### 2. 核心规则：**没有检查 = 失败**（T-19 用在产品自己的承诺上）

一条没有 verifier 的红线**算失败**，不算"不适用"，不算 skip。
理由：`.ai/regressions/0002`（一个从不被解析的 JSON 台账）与长期 `skipped` 的 S-09
都是同一个谎 —— **"没查过"报成"没问题"**。

所以 **`dev.py eval` 今天是红的，这是它的诚实状态。**

### 3. 两种 verifier，输出里分开标注

- `static` —— **当场执行** `checks --json --strict --only <id>`，要求规则真跑过且 0 error
- `gate` —— **不执行**（门禁每轮的事），只验证**声明不会腐烂**：门禁仍在 `CHECK` 里、
  且**被点名的 E2E 测试仍存在于源码中**

把 `gate` 说成 `executed` 就是夸大，所以标注分开。

### 4. S-13 `tool-encoding` —— P0 静态检查

**起因是我自己**：spec 014 修完 0004 的当天，我写 `eval.py` 时忘了加 `use_utf8()`，
`--json` 输出是 GBK，把中文字符串从中间截断。

> **三个调用点不是机制。** 而且我在 spec 016 §三 明确写过"不新增静态检查，
> 因为答不出'具体故障'"。**现在答得出了：故障就是我自己。**

**S-13 上线第一次运行就抓到第五处**：`backend/scripts/smoke_market.py` ——
手工跑真实网络的冒烟脚本，打印且从不调 `use_utf8()`。
**它不在 0004 的波及范围里（我只修了已知的三个），而且从没有任何测试跑过它。**

### 5. 修掉 spec 016 的一个错误结论

spec 016 §三 与 `regressions/0005` 都写了"不加规则，因为答不出具体故障"。
**这句话是错的**：具体故障一直能点名。已在 spec 016 加 §3.1 修订，
ADR-0027 加「补记」，**保留原文** —— "当时为什么这么判"和"后来为什么改判"都是信息。

## ③ 得到了什么样的结果

### 第一次诚实的测量

```
5 / 15 guarded (33.3%)  ·  coverage: full 5 · partial 2 · none 8
baseline 2026-09-28: 5 / 15 (+0 since)
```

**baseline 在动手修任何东西之前就写进了注册表** —— 这个数字不可能被测量行为本身抬高。

| coverage | 红线 |
|---|---|
| **full 5** | 1 不做预测增强 · 4 结果之前记录 · 6 未成熟结果留空 · 9 不展示成绩 · 12 必须显示时间的成本 |
| **partial 2** | 2 只做过程优化 · 13 不讨好用户 |
| **none 8** | 3 · 5 · 7 · 8 · 10 · 11 · 14 · 15 |

**8 条 `none` 里有 5 条的 gap 写着"依赖某个未实现的能力"**（K3 / J3 / D2 / agent）。
即：**超过一半的红线目前没有可被违反的对象。**
这与 `ARCHITECTURE.md` 新增的「Adopted but not implemented」是同一件事的两面。

**红线 14 明确标 `none` 并写"这条大概率永远无法有自动化检查"** ——
它关于"整体手感"。**宁可 5/15 不好看，也不硬造一个假检查把数字凑到 6。**

### 变异检查 4 / 4 变红

| # | 改坏哪里 | 结果 |
|---|---|---|
| M1 | S-13 不再检测未守卫的工具 | ✅ 2 failed |
| M2 | 允许 `partial` 通过 | ✅ 2 failed |
| M3 | 让 `skipped` 的规则算通过 | ✅ 1 failed |
| M4 | `gate` 不再检查测试是否还在 | ✅ 1 failed |

**M3 / M4 各暴露一个真实缺口，而且是同一种病：我写的测试重新实现了逻辑，而不是调用它。**

- **M3**：我造的 report 里 `rules_ran=0`，代码先命中 `ran == 0` 分支，
  **从没走到 `skipped` 分支**。分支正确且完全没被钉住。
- **M4**：`TestDeclaredVerifiersCannotRot` 在**测试侧**重新实现了一遍"测试还在不在"，
  于是删掉 runner 里的实现没有任何测试变红。
  **重新实现规则的测试是第二条规则，它会各自腐烂。**

> ⚠️ **变异脚本本身出了一次假绿**：第一版把 `"path -k S13"` 当成单个 argv 传给 pytest，
> pytest 收集到 **0 个测试**、退出码非 0，于是三个变异被报成"已抓住"。
> **"收集到 0 个测试"必须判为 harness 错误。** 修完第二次跑就正确报 `HARNESS ERROR`。
> **这是本项目最多次的同一种错误，不同的是这次它出现在测量工具里。**

### 门禁

`dev.py check` **10 道全过 + 退出码 0**；测试 536 → **563**；静态检查 12 → **13 条**。

## ④ 留下了什么

### 对约束①「写进简历」的影响

`status.md` §四 验收① 从 **1 / 3** 变成 **2 / 3**（eval 集存在且跑出 pass rate）。

而且现在这个数字**可以被追问**：任何人都能跑 `dev.py eval` 看到 **5/15**，
并读到**每一条差在哪**。

> 约束①真正能诚实展示的是**开发流水线**。今天它不再只是叙述 ——
> **"我们的 15 条红线只有 5 条被真正强制执行"，这个数字本身就是最强的工程素养证据**，
> 比声称 15 条都有要可信得多。

### 由此产生的路线图优先级

那 8 条 `none` 里，**5 条的 gap 都指向一个未实现的能力**。所以补红线的正确顺序
**不是写检查，而是先建那个能力**：

| 缺口 | 依赖 | 顺序建议 |
|---|---|---|
| 7 教训必须能再次遇到 | K3 FSRS | 先做 K3，检查随之而来 |
| 5 + 10 过程分独立 / 面对不舒服的数据 | J3 四象限 | 次之 |
| 3 · 8 · 11 | 便宜，可立即做 | **11 有一个可机械化代理**（仓库不应有"连续天数/打卡/成就"类字段） |
| 15 Agent 只抽取 | 运行期 agent | ADR-0027 条件未满足 |
| 14 日常体验要顺 | — | **可能永远没有自动检查，如实标注** |

### 新的机制

- **S-13 `tool-encoding`（P0）** —— 开发者工具的编码所有权
- **`.ai/eval/redlines.json`** —— 机器可读的红线注册表
- **`dev.py eval`** —— 主动调用的命令，**刻意不在 `CHECK` 里**

### 关于 `eval` 不进 `CHECK`（一个容易被质疑的决定）

它今天是红的。**放进 `CHECK` 会让 `dev.py check` 永久红，
而一个永久红的门禁会训练所有人忽略汇总** —— 那正是"门禁不再是门禁"。

本项目已经有相反的先例并珍视它：`check` 曾经一直红，
`status.md` 说"**这条纪律正是靠'一直红着'把 S-09 逼到落地的**"。

**区别在于**：S-09 是**可完成**的（写个组件就有了），
而红线覆盖是**长期工程**（8 条里有 5 条依赖尚未开工的能力）。
**把长期工程做成永久红的门禁，只会让人学会无视它。**
所以 `eval` 保持为要主动调用的命令，baseline 让进步可度量。

### 本条**没有**做的事

| 不做 | 为什么 |
|---|---|
| 把 `eval` 加进 `CHECK` | 见上 |
| 把 `partial` 算通过 | 数字好看，文档就是假的 |
| 给红线 14 造一个假检查 | 关于"整体手感"的可检查性是假的 |
| 立刻补那 8 条检查 | 多数依赖未实现能力。**本 spec 只负责让缺口被看见并可测量** |
| 改 `checks --json` 契约 | 动别人已文档化的行为；`--only` 够用 |
| 实现运行期 agent | ADR-0027 条件未满足 |
| 推 GitHub | 悬空的 `origin/main` 仍未修 |
