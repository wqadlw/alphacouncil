# 2026-09-28 · 回归 0007：复盘完的决策**永远留在队列里**

> 起因是上一轮结尾那句「下一件该做的：跨页缓存失效」。
> **先探测那个问题是否真的存在**，结果它不存在 —— **存在的是另一个更基础的问题**。
> 执行：OpenCode（Codex）· 模型：Space Bunny Free

---

## 一、发生了什么

**先验证，再动手。** 上次我把"跨页缓存失效"列为下一件。该做的第一件事是**确认它是不是真问题**——
不是读代码猜，是起一个真后端、记一次真复盘、打印今日页载荷。

```
due before review : {'reviews': {'queue': 'reviews', 'count': 1}}
review recorded  : quadrant=repeat
due after review  : {'reviews': {'queue': 'reviews', 'count': 1}}
```

**count 不动。** 而这**不是缓存问题**——服务端的数就已经错了。

**根因是两个队列的离开机制不同，而只有卡片那套是自动的：**

| | 复盘后怎么离开队列 |
|---|---|
| 卡片（K3） | FSRS 把 `due_at` **往后推** → 不再匹配 |
| 决策（J3） | `due_at` **一次设定、永不改变** → **永远匹配** |

`due_reviews()` 原本只有 `WHERE due_at <= ?`。卡片队列不需要"已完成"过滤，
所以**这个不对称一直没被发现**。

**修法**：`AND reviewed_at IS NULL`。

---

## 二、⭐ 为什么这比"数字错了"更严重

1. `due` 的 count 从「**还欠多少**」退化成「**历史上一共到期过多少**」
2. ⭐ **做完之后那一行还在说有事** → 读者学会跳过默认页上**唯一一行有时为真**的话
3. 这与今日页已防住的**另一个方向**（「计数为零 → 整行不渲染」）**完全同构**：
   **两个方向都会教读者忽略那一行**

---

## 三、⭐ 顺带暴露的**限制**（不是缺陷，是记录）

> **一条决策只能复盘一次。** `decision_review_state` 没有 reschedule，`due_at` 不会动。
> 要发明第二个间隔就是**发明策略**（spec 020 §六「买满 90 天」；
> spec 023「三天未处理」也是同样处理）。
> **想再看一次 = 记一条新决策**，或把教训变成卡片走它自己的排程（J5）。
> 若要"第二次复盘"，需要**一个会移动的到期日** + 一条 ADR。

另外：**没有复盘历史视图**，`reviews_for()` 在仓储里但无调用方——
复盘完就从界面消失了。**队列的定义就是"还欠什么"**，所以这不是缺陷；
但**读者看不到自己过去写过什么**，而 `项目总纲` 强调"三年后你能不能说出当时的自己"。
**已登记进 `status.md`。**

## 五、⭐ 这条记录自身的一次教训

**第一版回归测试"复现"了缺陷，而它其实什么都没插入。**

seed 用 `NOW.isoformat()` 写 `created_at`，而 schema 的 identity CHECK 要的是
`utc_millis()` 的 `...Z` 规范形式 → fixture 报错 → 队列为空 → `assert 0 == 1` ——
**看起来正是缺陷的症状**。

> **一个从未成功写入的 fixture，会精确地产生"队列是空的"这个症状。**
> 而"队列是空的"**正是**这个缺陷的表面现象。

如果当时只看 `assert 0 == 1` 而不看错误信息，就会归档一条**假**回归记录。
**今天第四次**：先确认测试真的跑到了要测的地方，再相信它的失败。

（与 0004「换行会骗过哈希校验」同族：**纪律本身没覆盖的失败模式**。）
