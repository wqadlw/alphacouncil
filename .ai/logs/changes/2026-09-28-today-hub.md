## 二、⭐ 核心：把"来找你"和"推送"之间的界线写死

三条规矩看起来打架：`项目总纲` §2.1⑤ 允许主动找人、红线 8 禁推送、红线 11 禁促使用户动起来。
不把界线写死，下一个人会往任一边滑。

> ### ⭐ 界线
> **关于「你自己已经承诺过的事」的事实** vs **关于「你可能想要的东西」的建议**

| | 允许 | 禁止 |
|---|---|---|
| 主语 | **你写下的那句话** | 产品 / 市场 |
| 性质 | **事实** | 建议 |
| 举例 | 「到期要看的：2 条决策 · 3 张卡片」 | 「今天有 3 个机会」「你的持仓异动了」 |

**一句话记住**：可以主动来找用户的，是**到期的东西**；不可以的，是**新的东西**。

所以 `due` **只有 `count` 和逻辑队列名**。没有到期日（能被排序 = 排名）、没有标题
（今日页会变成更好扫的第二视图）、没有排序、没有分母（"一共多少" = 进度条）、
没有链接（见下）。

### ⭐ 队列名是**逻辑名**，不是 URL

路由表是前端唯一真源（spec 022）。后端再写一份路径就是**第二份真相**，
那种复制品的典型结局是"开发好用、上线 404、没人能解释"。

而 `queueHref(queue: QueueName)` 的参数是**联合类型** ——
**服务端加了队列而前端没加路由，是编译错误，不是一个 404。**

## 三、⭐ 不发明「三天」阈值

`项目总纲` §2.1⑤ 写的是「**三天未处理** → 一句陈述」。但**三天这个判据没有定义**：
第四天该说什么不一样吗？逾期更久要不要说得更重？全都没写。

和 J3 的复盘到期日**完全同一种情况**（020 拒绝发明「买满 90 天」，021 让用户自己写）。

**而且这里不猜的理由更硬**：不猜只是保守；
而「**逾期越久说得越重**」**本身就是催促机制**，直接撞红线 11。

所以本片**只显示「已到期」**，并把"三天"**记为判据未定义**。

### 红线 10 的 `gap` 第三次更换理由

| 版本 | 理由 |
|---|---|
| spec 020 后 | 「**没有界面**」 |
| spec 022 后 | 「页面建好了，但**没有入口**」 |
| **spec 023 后** | 「**入口有了、主动也做了**，剩下③措辞检查（需 NLP，刻意不做）与④三天阈值（判据未定义）」 |

**每一次都不是把数字调乐观，而是把理由换成当下仍然为真的那一条。**
所以它**仍然是 `partial`**，评测数字**仍是 6/15**。

## 四、⭐ 变异 harness：把 020~022 踩过的坑全部前置成护栏

这一轮的承重断言**几乎全是负面的**（"整行不出现"、"那一行不含这些词"、
"十一件与一件是同一个句子"）—— 一个什么都不渲染的页面能通过大半。所以变异不是可选项。

harness 一开始就带着 020~022 的教训：

| 护栏 | 来自 |
|---|---|
| **编译不过 → 拒绝评分** | 022：一次 `tsc` 错误被记成"抓到了" |
| **输出含 `webServer`/`EADDRINUSE` → 判 INFRA FAILURE** | 022：端口占用，套件根本没跑 |
| **路径分隔符按 Windows 的 `\` 匹配** | 022：假阴性，一个**确实被抓住**的变异被判成没抓住 |
| **跑前确认端口空闲** | 022：同一个坑 |
