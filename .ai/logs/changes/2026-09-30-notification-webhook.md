## 一、⭐ 先回答一个不回答就不能写代码的问题：**这撞红线 8 吗**

红线 8 的原文是「**功能是『拦截』不是『推荐』**」+ 禁止「机会推送/每日精选/异动提醒」。

⭐ **禁的是那三类，不是「所有通知」。** 标题就是判据：这个产品的职责是**在你动手前拦住你**，
不是**替你找机会**。而「拦截」如果只在你恰好打开今日页时才发生，它就不是拦截，是一行表格。

| | 发什么 | 撞不撞红线 8 |
|---|---|---|
| ✅ | 「你写的判据『gpMargin > 0.95』**已越过** —— 毛利率 现在 0.97。」 | ❌ 不撞。它**报告的是读者自己写的阈值比较** |
| ❌ | 「贵州茅台值得关注」「今日精选」「你的持仓异动了」 | ✅ 撞。**主语是产品，不是读者** |

⚠️ 而且这**不是我的发明**：`ADR-0031` 与 `spec 033` §一 早就写了同一条纪律 ——
「本 spec 只建通道，不建决策」。

## 二、⭐ 真正的障碍：那五句话只存在于前端

`spec 040` 的五态句子在 `frontend/src/criterionVerdict.ts`。⭐ **后端只有状态和数值。**

```typescript
// frontend/src/criterionVerdict.ts:87
verdict: `已越过 —— ${metric.label} 现在 ${formatValue(metric.value)}（${metric.as_of}）。`
```

⭐ **照做只有两条路，两条都错**：在 Python 里**重写一遍**（两个孩子，会漂移），
或只发状态码 `crossed`（那不是提醒，是一行调试输出）。

⇒ **分两步交付**。本篇先做第一步：后端成为那句话的唯一所有者，
`criterionVerdict.ts` 缩到只剩**表现**（颜色 + `adjudicable`）。

⭐ **这不是「为 webhook 而重构」**——它让「今日页和通知不可能说不一样」变成**结构性**的。

### ⭐ 顺带被抓到的三件事

1. ⭐ **mypy 拒绝了一个我认为更「干净」的写法。** 我为渲染层另立一个 `Literal` 五态，
   理由是「不要把求值器拖进渲染层」——⭐ 而实际代价是**五个名字的第二个家**，
   正是这次搬家要消灭的东西。⇒ 改为 import `CriterionVerdict`。
2. ⭐ **E2E fixture 暴露了格式化规则**：`1185.30` **不是** `1,185.30` ——
   千分位只在值是整数时加。⭐ 第一版 fixture 写错了，而失败读起来像
   「一句没改过的代码出现了渲染 bug」。
3. ⭐ **红线 8 的测试我第一版写错了**：`assert '值得关注' not in verdict` 会被一个**合法**
   判据打脸——读者完全可以把「值得关注」写进指标名。⇒ 改成断言**形状**
   （`MetricFacts` 里没有能装下推荐的字段），并加一条测试记录这件事。

## 三、⭐ 去重**不是**数据缓存，而这两件事极易被混为一谈

用户跑两次 `send_due` 就会收到两条一样的话。看上去要「加个缓存」——
⭐ **而那正是 `ADR-0031` 明令禁止的那一格**：

> 缓存 | ⭐ **不要 —— 有害** | 要
> ⭐ 如果当初没有把 webhook 塞进行情层，就不会有人试图让通知继承数据缓存。
> 那个继承一旦写进去，几乎不可能被审出来 —— 它长得太像「复用了已有的好机制」。

| | 数据缓存 | 通知去重 |
|---|---|---|
| 问的是 | 「这个值我们取过没有」 | 「关于**这一件事**，我说过没有」 |
| 错在哪 | 一条提醒被悄悄丢掉，**且看不出丢了** | 同上 |

⇒ 一张 append-only 的 `notifications_sent`，⭐ **只在送达时写入**：
失败若写进去，下次就会被跳过，⭐ 而读者再也听不到「差一次重试就说到」的事。

⭐ **指纹只认判据，不认结论** ⇒ 同一条判据只说一次。
`crossed → not_crossed` **不再发第二条**：那是「异动提醒」（红线 8）且代价由用户承担（红线 11）。
