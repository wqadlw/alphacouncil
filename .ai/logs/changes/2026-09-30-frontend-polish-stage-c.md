## 一句话

⭐ **阶段 C 真正的起点不是「加两个组件」，是发现同一概念已经有两个家** —— 读代码时先撞见的不是缺口，是 `InstrumentPage` 里已经有一个 `TimelineRow`，而 `CardSection` 的卡片流水是另一段 ad-hoc `<ul>`。规格里写的是「新增 `RecordTimeline`」，实际该做的是**把已有的两处收进一个家**。

## 做了什么

### C1 · `RecordTimeline`（收已有的两处，不是新增第三处）

| | 之前 | 之后 |
|---|---|---|
| 标的页 watchlist 流水 | 本地 `TimelineRow`（2px 左规 + 事件号 + 取代 #N） | `WatchlistTimeline` 适配器 |
| 卡片 `card_events` | 裸 `<ul>`，`type-meta`，无规无号 | `CardTimeline` 适配器 |

⭐ **组件管「一行长什么样」，调用方管「这件事是什么」。** 判据是 `what` 收**一句话**而不是 enum —— 第一版取 `kind: 'verified' | 'converged' | 'added' | ...` 加查表，那就是一个每加一种事件就要改一次本文件的 `switch`。用句子之后，卡片说「已对照出处」、标的页说「改口」，两边互不知情。

⭐ **顺便删掉一个已经漂移的孤儿。** `format.ts` 的 `EVENT_LABEL` 零调用者，且它管 `reason_revised` 叫「修改理由」而日志里叫「改口」—— ⭐ 同一组三个事件，两张表两套词。删掉它而不是让适配器指过去，是因为日志行是**关于你做了什么**的一句话，「改口」是读者的叫法，「修改理由」是列标题的叫法：原表的词对它的新位置来说是错的，不只是重复。

### C2 · `GET /notes/{id}/backlinks`

`notes.backlinks_for` 从 spec 026 起就在仓里，**有测试、无调用者** —— 正是 `status.md` 一直挂着的「反链有函数无面板」。

⭐ 两处不是模板代码：
- `NOTE_NOT_FOUND` **不在** `errors.py` 的状态码表里 ⇒ 不显式 `try/except` 会返 **400 而不是 404**。`GET /{note_id}` 早就为此有显式处理，这条照抄那个形状而不是相信兜底。
- 行只带 `from_note_id` + `title`，不带正文。**不带正文的理由不是省流量**：反链面板紧挨记录渲染，把每条被引笔记的全文发过去会让面板成本正比于知识库而不是面板大小。

### C3 · `BacklinkList` 与落位

⭐ **vault 的选中项是组件状态，note id 不在 hash 里** ⇒ 反链**不能是真链接**。第一版签名是 `hrefFor: (id) => string`，调用点传了 `undefined as never` —— ⭐ **一个组件兑现不了的承诺、一个类型检查看不见的谎**。改成 `onSelect: (id) => void`：`<a>` 长得像链接但中键无效，只会让读者以为这个列表坏了。

⚠️ 真正的修法是让 vault 的 URL 可寻址，**不在本阶段范围**。

## ⭐ 三个我自己写错的东西

这一阶段最有价值的部分不是交付物，是**三次被自己的检查抓住的错误**。三条都进了 `failure-modes.md`。

### 1 · 一个从假设写出来的守卫（`F-151`）

端点第一版带 `if row is not None`，注释解释「指向已删笔记的反链会被跳过」。⭐ **注释两半都是错的**：`note_links.from_note_id` **有级联**（先删笔记，链接行就没了），而 `get_by_id` 对缺失笔记是 **RAISE 不是返回 None** ⇒ 守卫**永远走不到**。

是**变异检查**找到的：删掉守卫，测试全绿。我先把它读成「规则有洞」，才读成「代码的事实」。一个探针（`probe_delete.py`）一次跑出答案：删除前 `[source]`、删除后 `[]`；`get_by_id` RAISED。

⭐ **没量过就写下的防御分支，比没有分支更糟**：它能过评审、它读起来像 diligence，而它看起来提供的保护**从来就不存在**。跟一小时前删掉的 `EVENT_LABEL` 是同一个形状。

### 2 · 又一次把规则写宽了（`F-153` / `F-148` 第三次）

`V-14` 第一版正则把 `{card.events.length > 0 && <CardTimeline .../>}` 也报了 —— ⭐ **正确的委派，在委派的文件里**。写成「不要碰这个字段」的规则会抓住**让正确写法成为正确写法的那个守卫**。

⭐ 三个提交里第三次，**这是习惯不是意外**。每次的信号一样：第一版跑出来大量正确代码违规。

### 3 · 一个什么都不做的变异体（`F-156` / `F-150` 第四次）

探针第四个变异体在注释后面追加了 `DISABLED`。⭐ 什么行为都没改，套件全绿，脚本报「SURVIVED: V-14 抓不到坏时间线」—— ⭐ **假得不能再假**：探针自己什么都没做。

⭐ `F-150` 的第四次，但方向是新的：之前是「变异体把自己的违规变成合规」，这次是「变异体压根没违反任何东西」。**报告里那行 `SURVIVED` 的可信度，取决于变异体有没有真的改变行为。**

| | |
|---|---|

| 变异 | 后端 5/5 + V-14 5/5 全杀 |

⭐ **E2E 那条改写是真行为变化，不是改测试凑绿。** 旧断言匹配 `已收敛：公司改直营，渠道先行关系失效` —— 一句话里前缀和理由连着。`RecordTimeline` 现在把**发生了什么**和**读者的话**画成两个元素，因为日志行是关于一个决定的主张，理由是读者的话、不是产品的话。两条断言分开后**互相独立**：只断言理由，理由丢了标签还在也会过；只断言标签，理由被吞了也会过。

⭐ 定位器试了三个才对，两个失败是同一个错：`getByText('已收敛')` 命中标题「已收敛的主张」（子串），`{ exact: true }` **还是命中两个** —— 卡片自己的状态徽章也正好写「已收敛」。⭐ 需要三次 `exact`/`.last()` 调整才唯一的文本断言，已经不再描述它在检查什么。

## 诚实的边界

- ⚠️ **这个仓无法在测试里渲染组件**：没有 `jsdom`、没有 `@testing-library/react`，10 个测试文件全是纯逻辑或源码扫描。⭐ 所以 V-14 第三条查的是**接线**（`{absentDetail}</p>` 出现在渲染点上），不是行为。加 DOM 环境是一次依赖预算决定（V-07），本阶段没做。
- ⚠️ **反链是按钮不是链接**，因为 vault 的选中项不在 URL 里。
- ⚠️ **端点返回的行不带正文**，这是判断不是约束；带不带正文的取舍未验证过面板的实际观感。
- ⚠️ **§5 的自相矛盾（「唯一主库 Lucide」vs「自绘金融图标」）仍未裁定**，进 `decisions.md` 等主人拍板。
