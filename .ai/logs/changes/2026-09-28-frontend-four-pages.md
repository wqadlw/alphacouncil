## 二、⭐ 字体到底变没变：一个**会骗人的指标**

先量了最容易想到的那个数：

| | 之前 | 之后 |
|---|---|---|
| 低于 13px 的占比 | 98 / 178 = **55.1%** | 114 / 187 = **61.0%** |

**这个数上升了。** 按它下结论会说"迁移把密度做差了"，而实际发生的是：

| 真正该看的 | 之前 | 之后 |
|---|---|---|
| **正文 13px** | 37 | **56**（+19，+51%） |
| **文档级字号 ≥17px** | 34 | **8**（−26，−76%） |
| **26 / 28px** | 6 | **0** |
| 铬饰 11–12px | 98 | 113（+15，**故意的**） |

**判据是"分工"不是"下限"**（`FRONTEND_STYLE_GUIDE.md` §2.2）：
表头与元数据**本来就该**是 11/12px，**散文才不许**低于 13px。
所以这一轮做的是**把小字从散文挪进铬饰**，同时**把喊叫的大字砍掉三分之二**。

⭐ 值得记的是：**那个会骗人的数是我自己算出来的，而且差点被我当成结论汇报。**
写脚本时特意把两套口径都打出来，并在末尾写明「测不到的」那一条 ——
**一个只报一个漂亮数字的度量脚本，本身就是那种 bug。**

**明确未测**：剩下的 114 处 11/12px **是否全是铬饰**。grep 分不清表头和段落，
这正是 **V-03（衬线只用于主张）至今仍是人工评审项**的原因。

## 三、⭐ `ui.tsx` 为什么该删，而且**早该删**

删之前查了引用：只有 `ReviewPage` 和 `RetrospectivePage` 从 `./ui` 导入。
而那个文件里有**三样东西在新体系里都是错的**：

| `ui.tsx` 里的 | 问题 |
|---|---|
| **`AppShell`** | **完全死代码** —— 全仓只被它自己引用。是 spec 022 的外壳，被 `AppShellFrame` 取代后没删 |
| **`EmptyState`** | ⭐ **和 `components/ui` 里的同名函数重复实现**，一个 26px 衬线 `<h1>` 一个 13px。**同一个事实有两处，正是 `FRONTEND_STYLE_GUIDE.md` §9 明令禁止的** |
| **`Page` / `WidePage`** | 720/860px 定宽 + 32px 内边距。在三栏外壳里**主动有害** —— 外壳已经分栏，页面再自带定宽就把它自己的 pane 撑变形了 |

**留着它的真实代价**：一个 `import { EmptyState } from './ui'` 就能把页面拖回旧语汇，
而且编译器不会报错。**这不是死代码的美观问题，是一条没有护栏的退路。**

## 四、⭐ 两个**没有做**的判断，都写了理由

### 4.1 复习页与复盘页：**故意不把队列放进第三栏**

`AppShellFrame` 留了 `detail` 槽位，复盘页看起来是天然的候选（左队列、右卡片）。
**没做，因为把"还剩几张"画成列表，就是用图片代替数字的进度条**：
一列卡片在每次作答后肉眼可见地变短，这正是红线 11 反对的
"把数字留下来、试着去爬"的形状。所以现在只给**一句话里的一个数字，不给位置**
（`今天要过一遍的 1 张`，永远不是 `1 / 8`）。

⭐ 这是这一轮里**"做成程序"和"守红线"方向相反**的唯一一处，**红线赢**。
理由写进了两个文件的头注释 —— **否则下一个读者会看到空的第三栏，
以为是没做完。**

### 4.2 复盘页的判定态：**不渲染队列计数**

`retrospective.spec.ts:120` 断言危险象限下 **`document.body` 整页无数字**。
而判定态发生时队列**仍然是 N 条** —— 就算这个计数"关于读者自己"，
它仍然是个数字，仍然会让断言红。
所以判定态只渲染**判词 + 一个按钮**，这是它本来就该有的样子。

顺带记下一条**将来会咬人的约束**：**外壳顶栏那个 `⌘K` 提示是承重的** ——
它是整块铬饰里最想渲染数字的地方，而它渲染的是一个字母。
