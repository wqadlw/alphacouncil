## 一、量出来的，不是想到的

### 1.1 一个新用户打开看到什么

对着**一个空数据库**（`ALPHACOUNCIL_DATABASE_PATH` 指到临时目录、另一个端口）
把十三个列表端点挨个打了一遍，**全部返回 `[]`**。

然后在浏览器里把五个页面挨个截图，量每页的正文长度：

| 页面 | 字数 | 空态说的是什么 |
|---|---|---|
| 今日 | 360 | 现在是什么、为什么空、下一步在哪 |
| 关注池 | 267 | 同上，且表单就在上面 |
| **复习** | **62** | 只说了**为什么这个队列是空的** |
| **复盘** | **74** | 同上 |
| 知识库 | 178 | 同上 |

⇒ **「五个空页面」这句话不准确。** 三个合格，**两个不合格** ——
对新读者来说，队列空的原因是**上游根本没有东西可排**，而这两页从没说过。

### 1.2 更要紧的一半：队列**结构性地进不去**

`status.md` K3 挂着「还差：标的页卡片的『加入复习 / 下次复习 N 天后』」。
对着机器量：

```
POST /api/v1/cards                 -> 201 card_1790916668533
GET  /api/v1/review/due            -> 0 条    （服务端不主动贡献任何东西）
POST /api/v1/cards/{id}/schedule   -> 201 {"state":"learning", …}
GET  /api/v1/review/due            -> 1 条
grep scheduleCard                  -> api.ts:282 定义，调用者 0 个
```

**⇒ 卡片只能靠写代码进复习队列。** 而**缺的不止是按钮** ——
**`GET` 端点当时根本不存在**，界面既不知道一张卡在不在队列里，
**也不能从 `/review/due` 推断**（那个端点只给**到期**的）。
⇒ 「加入复习」如果只能靠点完才知道结果，**它就是一个赌注**。

而**笔记不是这样**：`VaultPage` 有 `enrollNote` 且配了理由。
**同一个后端形状，卡片这边只有一半。**

## 二、设计：三态，不是一个布尔

| 状态 | 界面说什么 | 为什么 |
|---|---|---|
| **不知道** | 「复习状态取不到。」**不给按钮** | 后端一停就出现一个点了必然失败的按钮，**那比没有更坏** |
| **未入队** | 「加入复习」+「到时会自己回来。」 | |
| **已入队** | 「已加入复习 · 下次 …」 | |

⚠️ **笔记那边现在是 `.catch(() => false)`** —— 任何失败都读成「未入队」，
于是后端一停就出现一个骗人的按钮。**卡片这边按 `error.code` 判断**，
⚠️ **笔记那条本轮未改**（属 spec 028 的地盘，已记为欠账）。

⚠️ **`GET` 未入队答 409 而不是 404 —— 而这个决定项目早就做过了。**
我本来要照抄笔记的 404，然后读到 `api/errors.py`：

```python
# K3. Both are 409 rather than 404 on purpose: the *card* exists, and what
# conflicts is the request with the card's scheduling state. Answering 404
# would tell the user their card is gone when it is sitting right there.
```

⇒ **照抄笔记会推翻一条已经写明理由的决定。** 用 409。
⇒ 而这也让三态成为后端给的：409 正常的空 · 404 另一个问题 · 传输失败**不知道**。

⚠️ **不给「全部加入」** —— 入队是显式的，理由沿用 `VaultPage` 已写下的那条。
⚠️ **而教训相反（红线 7 强制入队）**：教训是系统自己的产出，卡片是读者署名的东西。
⚠️ **不给队列加数字** —— 会把它变成一张待办清单。

## 三、过程中我犯的四个错

### 1 · 我又一次猜字段名（第三次）

卡片创建的字段是 `content` 不是 `claim`，拿到 422。
⚠️ **这是本会话第三次猜字段**（`TradingDayVerdict` / `?q=` / `claim`），
**「读模型再发请求」应该是探针的第一条规矩，而不是被坑三次之后才补的。**

### 2 · 探针的转发层两次让产品看起来有错

① 转发对所有方法都用 `p.request.get()` ⇒ **入队的 POST 被用「读」的回答答了**，
点一下看起来像失败。② 为测「读失败」而注册的 abort 路由**写在通用路由之后**，
被后注册者守守归零 —— ⚠️ **那正是 `F-198` 在探针里重演一次。**

⇒ **探针必须转发真实的 method 与 body**，而不能自己发明的那个。

### 3 · 我照抄文档时写错了字符串，两次

`status.md` 的替换脚本连续两版**断言了一句凭记忆敲出来的字符串**，都不匹配。
⇒ 第三版**先把那段逐字节验证过**（打印 `identical over the whole span`）再改。
⚠️ **猜字段名、猜主键名、猜文档的确切措辞是同一个错误**，第三个并不比第一个更可原谅。

### 4 · 一条测试因为「它经过」而永远变绿

「已收敛的卡片不给入队按钮」那条**没有 stub 那个 schedule 读请求**，
所以读走 404 → 控件落进「不知道」态 → **按钮不出现，但原因与「已收敛」无关**。
**变异 M3（删掉 `!converged` 守卫）没有让它变红** —— 那是它空的证据。
⇒ 补上 `409 CARD_NOT_SCHEDULED` 之后 M3 立刻变红。

⇒ **本会话第二次「少了一个 stub 所以永远变绿」**，上一次是 `0012`（CSS 扫描）。

## 四、门禁

| 变异 | 结果 |
|---|---|
| M1 把任何失败当成「未入队」（笔记那个形状） | `A6` 红 |
| M2 把**任何** `ApiError` 都当成「未入队」 | 404 那条红 |
| M3 删掉 `!converged` 守卫 | **第二轮才红**（见 §三.4） |

⚠️ **M1 与 M2 都需要，且失败方式不同。** M1 保留了按钮出现在坏读上；
M2 保留了错误码判断而丢掉 404/409 的区分。**只把异常折叠的实现与只折叠错误码的
实现都不对，而只有两个都跑，才证明套件看得见两种。**

后端 +4（其中一条专门说 409 与 404 为什么必须分开，另一条说**读没有副作用** ——
因为界面每渲染一张卡就会读一次，**有副作用就等于每张卡自动入队**）
前端 E2E +10 · 改了一句 `review.spec.ts` 的既有断言（它正确地拦住了我的文案改动）

## 六、留下的欠账

- **`VaultPage` 的笔记入队仍是两态**（`.catch(() => false)`）—— 同一形状的另一个实例
- **复习历史界面**（K3 剩下的那一半）
- **五个页面仍没有「从哪来」的上游引导** —— 两句文案改了，五页布局未动
- **`dev.py demo`**（T0 的另一半，独立路径的演示库）
- **孤儿扫描**（三次量错的那个）仍不可靠
