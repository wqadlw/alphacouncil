## ⭐ 最贵的一课：缺陷藏在一个「看起来正确」的解释后面

向前 Tab **前五步都在面板内**，向后 Tab **第一步就出去**。两个方向不可能都是偶然，而那个让这个 bug 显得无害的读法是：

> 「面板在 DOM 最后，所以向前 Tab 自然是安全的。」

⭐ **这句话看着对，而且关于原因是错的。** 面板被 portal 了 ⇒ 向前 Tab 必须先穿过整个页面 ⇒ 那五步是**浏览器自己的顺序**，不是陷阱在干活。第六步落到 `body`，因为没有任何东西让它回绕。

⭐ **藏在一个正确外观的解释后面的缺陷，是贵的那个。** 所以：先量；Tab 按**比行数更多**的次数按，两个方向都按（修前正好是 `rows + 1` 步逃出，按 `rows` 步的测试对着坏版本也会过）。

## 做了什么

1. **记录原焦点并在关闭时还回去**（`previousFocus`，在 `open` 变 true 时读，rAF 后还，且检查 `isConnected`）。
   ⭐ 记在 `open` 变 true 而不是 `onClick` 里：面板有**三条**打开路径（⌘K / 侧栏按钮 / 页面贡献的命令），只有一条是点击——⭐ 写在 `onClick` 里会让另外两条把焦点还到 `body`，**而那正是在测试里能过、在真实使用里坏掉的形状**。
2. **焦点陷阱挂在 panel 自己的 `onKeyDown` 上**，不在 `window`。
   ⭐ 挂在 `window` 上会修好向后、留下向前——`keydown` 在被处理的元素上**冒泡不到** React 根监听器之后才注册的那个 document 监听器。
3. **`inert` 加在 shell 上**，面板 `createPortal` 到 `document.body`。
   ⭐ **「modal 不能是它所禁用子树的的后代」**——这句话是设计约束，不是对 DOM 的观察。`inert` 是平台特性，§6 禁的是**库**。
4. **恢复时写回读到的值**而不是 `false`：别的东西可能自己让 shell `inert` 了，硬写 `false` 会悄悄把它解开。

## 我做错的两处

### ⭐1 · 我差点做一次「读起来必要」的 refactor（`F-163`）

下一步我打算把 `<CommandPalette>` 从 `AppShellFrame` 挪到 `App`，理由是「这样它就是 shell 的兄弟」。

⭐ **`createPortal(node, document.body)` 已经让它是 `#root` 的兄弟了。** 那次移动**什么都不会改变**。DOM 顺序是后来量出来的（`panelParentIsBody: "body"`、`panelInsideShell: false`）——⭐ **portal 落在哪由它的参数决定，不由它写在哪决定。** 少想一步就多一个 prop 和一次职责搬家。

### 2 · 变异检查抓出**我规则的洞**（`F-158`）

V-15 写的是 `/createPortal\([\s\S]*?document\.body/`，变异体 `document.body.firstElementChild` **存活**了——⭐ 那正是「portal 回被禁用的子树里」，是模式的**前缀匹配**。

⭐ `F-148`/`F-153` 是我写**太宽**，这条是**没说值在哪里结束**。**一个不断言值在哪里停下的模式，会接受每一个以同样方式开头的更长值。** 改成 `document\.body\s*[,)]` 后杀掉。

⭐ 而且这条规律我是**两个方向都错过**：三个提交里先太宽，这里又太松。**方向的差别不重要，重要的是第一次跑没有告诉我。**

## 变异检查本身出的三个问题（`F-159` / `F-160` / `F-156` 再一次）

⭐ 12 个变异体，第一次跑只有 9 个算数：

- 2 个被 **`tsc -b` 拦下**（`if (true) return` 造成死代码；删掉 `trapFocus(event)` 调用造成未使用声明）—— ⭐ **编译器和测试是两个不同的捕获者**，而脚本把它们一起报成 `BUILD FAILED`，读起来像「变异体把构建搞坏了」。
- 1 个是我的**探针自己**：`stdio: 'ignore'` 让一次**成功的构建**返回 status 2，于是五个变异体全被报成构建失败。

⭐ ⇒ 三条：**变异体必须类型干净**（只改行为）· **探针必须和门禁用同一种方式调工具链**（门禁用 `npm.cmd` 重定向到文件，探针调了 `npm` → `npm.ps1` → 被执行策略拦）· **`shell:true` 下 `cmd.exe` 不把 stderr 传进管道**，所以必须打 `error.message`，⭐ 否则探针会把自己的失败归档到错误的原因名下。

## 诚实的边界

- ⚠️ **V-15 是源码规则，不是行为规则。** E2E 那三条才是行为。V-15 钉的是**机制**（必须 portal 到 `document.body`、必须设 `inert`、必须写回读到的值），因为 trap 正常时 E2E 也会过，而「被自己冻住」的失败**在每个不尝试输入的测试里都像一个正常 modal**。
- ⚠️ **原焦点的恢复有一个刻意的不对称**：命令若自己移动了焦点（`run` 打开某个编辑器），恢复会在一帧后检查元素仍连接着、然后**覆盖它**。目前命令只有 `href` 导航（换页 ⇒ 旧元素已卸载 ⇒ `isConnected` 为假 ⇒ 不恢复），**所以现状正确**；⭐ 但一个「命令把焦点放到别处」的场景会与之冲突，**那时候这条规则要重写而不是加例外**。
- ⚠️ **阶段 D 的其余三项（Drawer / Popover / Toast / DatePicker）未开工。**
- ⚠️ **§5 的自相矛盾仍未裁定**（「唯一主库 Lucide」vs「自绘金融图标」）。
