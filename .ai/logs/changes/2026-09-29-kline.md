## 二、端点：形状照抄 `/quote`，理由也照抄

```
GET /api/v1/instruments/{market}/{code}/daily?start=&end=  →  DataResult[list[Quote]]
```

四态（`ok` / `stale` / `no_data` / `error` / `unavailable`）**原样传出去**。
⭐ `/quote` 的 docstring 已经把理由写好了：「`no_data` 与 `error` 是两句不同的话，
只有一句值得重试」—— 所以这个端点**继承**那个论证，而不是重述一遍。

**升序是契约，不是巧合**：router 会合并多个源，而每个源自己的顺序不同，
所以只有端点能保证它。⭐ 喂给图表的倒序数据会画出反的。

**窗口有上界，且上界在这里**：默认 320 天，硬上限 1500 天。
⭐ 一个有界的历史端点可以被人不小心问到无界，而数据源会努力满足它。

## 三、⭐ 页面不许承诺它填不满的图表

`usable_datasets()` 的 docstring 已经写着：**页面不得承诺它填不满的图表**（宪法：诚实的空状态）。

所以组件有四个状态、没有第五个：

| 状态 | 说什么 |
|---|---|
| `ok` | 画图 + 说明根数、区间、来源、以及**成交额该源不提供** |
| `stale` | ⭐ **照画，但标出「这是缓存里那一份」** |
| `no_data` | 「没有数据源报这个代码」—— **不是「这只票没有历史」** |
| `error` / `unavailable` | 「所有已知数据源都拒绝了」—— **这一条值得重试** |
| （`ok` 但 0 根） | 「这段时间没有交易」—— 是区间的性质 |

⭐ **空图表是最危险的第五种**：它看起来像「这只票没有历史」，
而真相可能是「今天三个源都在熔断」—— 两句话指向完全不同的下一步。

## 五、我这次的错

**1. ⭐ 我把 `stale` 当成了状态。**
`DataStatus` 是 `'ok' | 'no_data' | 'error' | 'unavailable'`，`stale` 是 `ok` 结果上的**标志**。
我按自己发明的联合类型写了 `status === 'stale'` —— ⭐ **那句「这是上次拿到的数据」有个
永远走不到的分支**，而那正是读者最需要被告知的情况。

⭐ 而且能让我犯这个错的，正是「复用」本身：**自己发明的联合类型没有成员可以拒绝一个错误
想法，错误想法于是通过了类型检查**。照抄 `QuoteResult` 的形状会当场抓住它。

**2. ⭐ 子串守卫又栽了。** `"export interface Quote"` 命中了 `QuoteResult` ——
而那正是我照着建的类型。同一种形状第三次：**一个能被更长的名字满足的检查，
就是会在它本该拦住的那种情况上通过。**

**3. ⭐ `useResource` 要四个参数，我给了两个；`const detail` 是 2 空格缩进，我猜了 4。**
脚本**拒绝写盘**而不是应用五处里的三处 —— ⭐ **部分应用比不应用更糟**：
文件会留下指向不存在资源的 import。

**4. 我口述 `lightweight-charts` 是 MIT。** 实测 `package.json`：**Apache-2.0**。
两者都宽松、门禁都判 `ok`，⭐ 但说错许可证是要改的。

**5. ⭐ 我查了装上的 API，而不是凭记忆写。** 4.2.0 有 `addCandlestickSeries`，
而 v5 的 `addSeries` / `CandlestickSeries` 在它的类型定义里**出现 0 次**。
凭记忆写会得到一个「类型检查什么都不检查、也画不出东西」的组件。

## 八、补记：批准、体积实测，以及又一次子串守卫

**批准**：主人指令「怎么展示数据的，全部拿过来」＋ 其后的「继续」。
⭐ 记录里写的是**主人实际说过的话与日期**，不是「主人批准」四个字 —— §3.2.1 的原话是
「批准这件事必须留在宪法里，只写在变更日志里，等于把这些包为什么合适变成一个需要考古的问题」，
而一个没有出处、没有日期的「批准」正是它要防的东西。

**同时把「图表库」从未批准清单里划掉了，但没有放开这一类**：
新增第二个图表库仍要走 §3.2 的四点与人工确认。⭐ 移出措辞与放开措辞的区别，
就是一年后有人能不能顺手再加一个 ECharts 的区别。

**体积实测（第 4 点，唯一还开着的一项）**：**+157,510 bytes 原始 / 约 45 kB gzip**。

⭐ 取基线连失败两次，而**两次失败都说明了问题**：

1. `npm run build`（`tsc -b && vite build`）—— 类型检查先失败，因为导入缺失模块的组件
   根本不能编译。⭐ 这不是测量出错，**这是依赖预算在正常工作**。
2. 单跑 `vite build` —— import 分析阶段同样失败。

所以基线只能这样取：**保持 import 图有效，把库换成同形状的本地空实现**。

**我口述时把体积说成「几 kB」** —— 作者确实这么说，而实测是 153.8 kB 原始。
⭐ 引用别人的宣传数字而不量，是把别人的口径当成了自己的口径。

**⭐ 第四次子串守卫**：判断「宪法里是否已记录 `lightweight-charts`」用的子串匹配，
被**另一节的一张技术选型表**满足了（那表在 L193 提到了它），而 §3.2.1 的**批准表**（L247-249）
根本没有那一行 —— 脚本报告「已记录」，实际一个字没写。

⭐ 本轮四次同形状的失误，逐个归因：

| # | 被什么满足 | 本该问的是 |
|---|---|---|
| 1 | **旧名字**（改名之前） | 「**这里**是不是新名字」 |
| 2 | **更长的名字**（`QuoteResult` 含 `Quote`） | 「这个标识符**独立**出现过吗」 |
| 3 | **被忽略的目录项**（`.pytest_cache` 的 README） | 「这条路径**在跳过列表里**吗」 |
| 4 | **另一节**（技术选型表 vs 批准表） | 「它在**该出现的那张表**里吗」 |

⭐ 共同点：子串测试回答的是「这个字符串**在任何地方**出现过吗」，
而「已经做过了吗」问的永远是「它在**该在的那个地方**出现了吗」。
**锚要指向位置，不是指向字符串。**
