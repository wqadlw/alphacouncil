# 2026-09-29 · S-01 从目录白名单改成模块白名单 —— 而且是改紧（spec 039 / ADR-0031）

> 起因：主人说「继续」。`spec 033` 抄 webhook 通道时撞在 S-01 上，
> **卡了三个月**，而它卡住的原因不是「抄不过来」，是**一条 P0 规则在本代码库里
> 有一个已经错了的建议**。
> 执行：OpenCode（Codex）· 模型：Space Bunny Free

---

## 一、卡住的那句话是错的

S-01 拦住「不在 `providers/` 里 `import httpx`」，官方修复建议是：

> 走 provider 层 —— `alphacouncil.providers.default_router()`

⭐ **那条建议对 webhook 是错的。** `default_router()` 是**行情**路由 ——
按 `Dataset` 声明能力、按 `BatchSemantics` 处理批量失败、三源互备、带磁盘缓存。
把一条飞书消息塞进去意味着要给它发明一个 `Dataset` 成员，
⭐ 而加成员会打破两个断言**精确集合**的既有测试。
那两条测试变红不是障碍，**是它在告诉你这个抽象不接受这个东西**。

## 二、⭐ 规则真正想守的，逐条都是关于数据源

宪法 §7.8：「限流**必须是一个函数**，不能是"请大家记得加 sleep"」。
§4.5 把它说全：三源互备、东财触发限流、**「限流」与「封 IP」是两件事**、
**同一域名的不同子域风控面不同**。

⭐ 所以 §7.8 那一串机制（串行化 / 最小间隔 / 抖动 / 会话复用 / **默认 UA** / 熔断 / **缓存**）
**逐条都是数据源出口的关切**。而 S-01 的实现判的是**目录**：

```python
return relative.parts[:1] == Path("providers").parts
```

**意图**是「客户端只在被认可的地方被构造」，**实现**是「在一个目录里」。
⭐ 这两个命题之间的缝，就是通知通道待的地方 —— 也是这道问题卡了三个月的原因。

## 三、⭐ 这是改紧，而且数字可数

| | 允许构造客户端的**文件集合** |
|---|---|
| 改前 | `providers/` 下**每一个** `.py`（今天 4 个，将来更多） |
| 改后 | **1 个**（`core/http.py`） |

`sources.py` 自己构造客户端这件事**改后不再被允许** —— 它必须调工厂。
⭐ 口子是缩小到原来的一个文件，不是扩大到第二个目录。

而这个数字**现在是一条测试**。⭐ 因为不写成测试，
它就会在某一次「顺手加个文件」里悄悄变回 4 个。

## 四、⭐ 一份 UA 不能两边共用，所以「一个入口」不是「一个 client」

`spec 033 §2` 要求把 `User-Agent: TickFlow-Webhook/1.0` 重新冠名 ——
⭐ **webhook 不该冒充浏览器**，而腾讯/新浪**必须**冒充（它们拒绝陌生 UA）。

塞进一个带默认 UA 的工厂，等于让其中一边撒谎。
所以共享的是**「客户端在哪里被构造」这条规则**，不是**一个构造好的 client**。

⭐ 这也是 `build_client` 的 `user_agent` 为什么**必填**：
**带默认值的那个默认值，迟早会在某一侧变成一句谎话。**

## 五、⭐ 缓存那一格是这次调查最值钱的一格

| §7.8 的机制 | 行情 | webhook |
|---|---|---|
| 超时 / 连接复用 | 要 | 要 |
| 最小间隔 + 抖动 | 要 | 要 |
| 默认 UA | 要（且必须**不**诚实） | 要（且必须**诚实**） |
| 熔断 | 要 | 语义不同（通道坏了 ≠ 数据陈旧） |
| 缓存 | 要 | ⭐ **不要 —— 有害** |

⭐ **如果当初没有把 webhook 塞进行情层，就不会有人试图让通知继承数据缓存。**
而那个继承一旦写进去几乎不可能被审出来 —— 它长得太像「复用了已有的好机制」，
**一封被去重的通知就是一次静默丢弃的提醒**。

宪法 §7.8 因此加了一段 ⚠️：那句「唯一入口内置 … 熔断 + 缓存」**只对行情成立**。

## 六、⭐ 两种权限被混成了一种，是收紧时才暴露的

改完立刻报了一个**看起来像误报**的错：`sources.py` 仍然 `import httpx`
（要用 `httpx.HTTPError`、要标注 `httpx.Response`），而它不是构造点。

⭐ 旧规则只能用**目录**同时表达两件事，于是选了权限更大的那个去满足：

| 权限 | 名单 |
|---|---|
| **构造**客户端 | `CONSTRUCTION_SITES`（1 个文件） |
| **命名** `httpx`（为了类型与异常） | `HTTP_AWARE_MODULES`（+`sources.py`） |

⭐ **而这次能安全放宽 import 名单，恰恰因为收紧先做了**：
构造检查现在**无条件**在所有文件上生效，`httpx.get` 也是。
所以「允许命名 `httpx`」不再带来任何构造能力。

⚠️ **顺序反过来就是一个洞。** 先放宽 import、之后再收紧构造 ——
那中间任何一刻 `providers/` 都能自己造客户端。这条写进了规则的 docstring。

## 七、⭐ 变异 7 个，第一个就存活了

| # | 变异 | 结果 |
|---|---|---|
| 1 | 构造点加回 `providers/sources.py` | killed |
| 2 | **删掉构造检查里的「对的文件」条件** | **SURVIVED** |
| 3 | 构造检查整个不触发 | killed |
| 4 | import 白名单变成整个产品 | killed |
| 5 | `HTTP_AWARE_MODULES` 塌缩成构造点 | killed |
| 6 | 工厂名清单去掉 `build_client` | killed |
| 7 | `CONVENIENCE_CALLS` 不再拦 | killed |

⭐ **存活的那条是本次最有价值的产出。**

规则 3 有**两个**条件：对的文件 **且** 对的函数名。
而我原来的 fixture 把函数叫 `fetch` —— **两个条件同时被破坏**，
所以无论文件条件在不在，测试都红。**它测不出这两个条件是分开的。**

删掉文件条件后测试照绿 —— ⭐ **「这条测试通过」不等于「这个条件被测过」。**

补的 fixture：**函数名叫 `_client`（合法工厂名），文件是 `providers/sources.py`（不是构造点）**。
只破坏一个条件。重跑 **7/7 全杀**。⇒ `F-115`

## 八、⭐ 顺带修掉规则建议文案里的一个错

规则 1 的 fix 文案原来只说「走 provider 层」。
那是**给想要行情的人**的正确建议，和**给不想要行情的人**的错误建议 ——
⭐ **一条建议在本代码库的一个真实场景里是错的，下一个读者就会开始给整条规则打折。**

改成两个选项并列：`build_client(...)`（要发 HTTP）/ `default_router()`（要行情）。

## 九、⭐ 门禁第一次红是 ruff，而它是**对的**

`RUF002`（docstring 里的全角逗号）指向 `core/http.py` 里逐字引用的宪法 §7.8。

⭐ 既有先例（`today.py` / `notes.py` / `lessons.py`）写着一句话：
**「为了迁就 linter 去改一段引用，比这条警告本身更糟」** ——
因为转述成英文之后，**它就不再能被眼睛对着宪法核对了**。

所以按先例加了一条窄豁免，并写明「这个文件里除了那段引用和那张表没有别的 CJK，
所以这条豁免买不到别的东西」。

`SIM300`（Yoda 条件）是自己写错的，直接改。
