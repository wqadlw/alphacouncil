# 2026-09-29 · 门禁从来没有跑过 `tests/integration`（spec 035）

> 起因：主人说「继续你决定」。我在两个待办里选了这个 —— 它属于同一类
> 「门禁承诺的覆盖面比实际跑的窄」，而且更便宜：**一个跳过 42 条测试的护栏是有洞的护栏。**
> 执行：OpenCode（Codex）· 模型：Space Bunny Free

---

## 一、⭐ 洞在哪，以及它是怎么被发现的

`scripts/dev.py` 的 `test` 步骤跑的是：

```python
(_PY, "-m", "pytest", "tests/unit", "-m", "unit", "-q")
```

⭐ **`tests/integration` 从来没有被门禁跑过。** 那 42 条测试做的事是**迁移真实的数据库** ——
而里面有 **3 条一直是红的**，红过了**六个迁移**（spec 027/028/030 各加了一个），
期间门禁每次都报 `ran 10 · passed 10`。

发现它是因为我跑了 `pytest tests/` 而不是门禁那一行。

## 二、⭐ 这和 spec 031 是同一类，但方向相反

spec 031 那一类：**门禁承诺了它没做的事**（扫 npm 许可），中间靠人的记性。

这一条相反：**门禁没承诺它没做的事**（跑 integration），所以连「缺失」都不会被报出来。

⭐ 两种失效**在可见性上完全一样**：一个空洞，一个谎。T-19 管的是
「声明了但被跳过」的门禁，而这一条是**连声明都没有**。

所以 `dev.py` 的模块文档补了 T-19 的另一半：

> ⭐ 门禁**静默跳过**它覆盖范围的一部分，与**承诺超过它实际做的**一样失效 ——
> 因为两种情况下的缺口都不可见。

## 三、⭐ 那 3 条为什么一直红

它们把迁移版本**写死**了：

```python
assert report.applied == (2, 3, 4, 5, 6)
assert migrate.schema_version(connection) == 6
```

⭐ **每加一个迁移就断一次，而修法是去改三个数字。**

这和我上一轮刚在 V-07 里删掉的是**同一个缺陷**（把「现在有几个」手写成常量），
也和 registry 测试里那个是同一个。所以两处一起改成从 `migrate.load_migrations()` 派生：

* **起点版本保持写死**（1 / 2 / 3）—— 那是这些测试的**前提**
* **尾部和最终版本改成派生** —— 那是**结论**，而结论派生自世界就不会漂移

⭐ 另有一条测试名 `..._upgrades_to_version_four` 其实是升到 10，**名字也是写死的一部分**，改了。

## 四、⭐ 但派生本身证明不了什么，所以留了一条必须手改的

「把起点之后的全应用上了」这条断言，⭐ **在迁移数为零时也会通过**。

所以留了一条断言绝对版本的测试，它**就该被手改**，而它的失败信息直接写明了怎么办：

> 如果这是有意的：改掉这个数字，并检查发布说明与 `.ai/status.md` 是否与之一致。

## 五、为什么 `check-lite` 也加（不是取舍）

`check-lite` 自己的注释写着「只在 CI 跑的护栏，是在你搞坏那次提交之后才跑的护栏」。

⭐ 而 integration **实测 4.4 秒**（不是估的），unit 是 3 分钟。
⭐ **成本理由和补洞理由指向同一边**，所以这不是一个权衡。

两个集合都加了，而且是**分开的一步** —— ⭐ 失败时报出是哪一半坏了。
合成一步会把这个洞继续藏住：**六次迁移没人发现，正是因为没人跑过它们，
而合成一步读起来就是「测试通过了」。**

## 六、验证

* integration **43 通过**（原 3 红 / 39 绿）
* ⭐ 门禁 **10 → 11 步**，`test-integration` 在 `CHECK` 与 `CHECK_LITE` 里各一次
* `ran 11 · passed 11 · failed 0` · ruff 0 · mypy --strict 0（103 文件）

## 七、我在写这个脚本时犯的一个小错

我断言 `"test-integration"` 应该出现 **3** 次，实际 **4** 次，于是脚本报 1。
⭐ 那是**我数错了**（`Gate()` 的 id、两处元组、以及我自己注释里的一次），
不是代码有问题 —— 而门禁那一步**确实跑过并通过了**。
⭐ **脚本的退出码不等于事情没成**，所以我当时看的是门禁输出而不是脚本的退出码。
