## 一、⭐ 缺口不是"没装软件"，是数据模型把入口堵死了

实测（动手前）：

```text
backend 里的「笔记」概念        0
全文检索 / FTS5                0
标签 tags                      0
Markdown                       0
```

整个知识层是**一张 `cards` 表**，每行被三条硬约束锁死：

```python
CardDraft:
  source_url:   str          # 必填，必须 http/https
  source_title: str          # 必填
  symbols:     tuple[Symbol] # Symbol = 6 位数字代码 + 市场
```

前端 `createCard` 更硬：`symbols: ['sh600519']` —— **一张卡只能挂一只票**。

### 于是这些全都记不下来

| 想记的 | 能记吗 |
|---|---|
| 「流动性收紧时周期股先跌」（宏观） | ❌ 无标的、无 URL |
| 「我的估值框架是这样」（方法论） | ❌ 同上 |
| 「我第 3 次因为只看 PE 错过」（经验/教训） | ❌ 同上 |
| 一篇研报的读书笔记 | ❌ 必须有 URL、必须挂票 |
| 任何没有出处的想法 | ❌ provenance rule 是必填 |

⭐ **所以这个产品能"复习知识"，但不能"记录知识"。它有一个队列，没有一个知识库。**
这是主人那句话的字面含义。

## 五、⭐ 变异检查抓出的**两个真漏洞**（都是我自己的测试太弱）

11 次注入全部被抓住。其中两次值得单列，因为**它们不是代码有 bug，是我的测试比我自己以为的弱**：

| 注入 | 结果 |
|---|---|
| 标题可为空 · 正文写入时被 trim · 标签可含逗号 | ✅ 抓住 |
| **标签过滤从 `=` 改成 `LIKE`** | ❌ **第一版漏了** |
| **`add_link` 去掉链接存在性校验** | ❌ **第一版漏了** |
| **provenance rule 放松（卡片可不带来源）** | ✅ 抓住（而且是 400/422 两层都要对） |
| 笔记不存在时返回空笔记 · 编辑可改 `created_at` · 编辑可清空正文 | ✅ 抓住 |

### 5.1 `LIKE` 那条：我测的是「常见情况」，没测「够得着的范围」

我把 `WHERE t.tag = ?` 改成 `LIKE ?`，**测试照样绿**。
因为 SQLite 的 `LIKE` 在**模式里没有通配符**时就是精确匹配 —— `宏观` 仍然不会带出
`宏观债`，所以我那条断言根本没被触动。

**变异只在"值里带通配符"时才咬人**，而这一点没有任何测试覆盖：
读者在标签框里打一个 `%`，`LIKE '%'` 对每个字符串都成立，**整个知识库都会出来，
且不报错**。

⭐ 补的测试是这个洞的形状：
> **一个接受用户字符串的过滤器，必须说清"当这个字符串本身是个模式时会发生什么"。**
> 第一条测试证明了常见情况，变异检查证明了**够得着的范围**没被测 —— 两者不是一回事。

### 5.2 `add_link` 那条：**同一条规则写了两遍，第二遍没测**

`create` 和 `add_link` 各写了一次链接存在性校验。我把 `add_link` 里那份删掉，
**测试全绿** —— 因为所有"坏链接"的用例都走 `create`。

⭐ 这是"一条规则出现在两个地方"的特有危险：
**第二份在评审里删掉不花任何代价，换来一条几个月后才在界面上变成空白的死链。**
重复的规则需要重复的测试，而**只有变异检查会告诉你你没写**。
