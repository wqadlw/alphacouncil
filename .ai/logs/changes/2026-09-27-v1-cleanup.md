## ① 想做什么

`/health` 汇报 `retrieval.recall_top_k / graph_retrieval / text2sql`——一个废弃方向里**从未存在的层**。半年后的我们、面试官、排查故障的用户读到它都会得出错误结论。**系统在对自己撒谎**比少一个配置更糟。同批清掉：检索调优字段、Qdrant/embedding/reranker/langfuse 连接配置、`/api/v1/research` 501 存根、`models/domain.py` 整套 v1 检索模型。

## ② 做了什么

**config.py**：删 `embedding_model/dim`、`reranker_model`、`qdrant_*`（3）、`langfuse_*`（4 + 生产校验分支）、`recall_top_k`、`rerank_top_k`、`enable_graph_retrieval`、`enable_text2sql`，以及随之失去对象的两个校验器（URL 归一化、rerank≤recall）。**明确保留**：`llm_*` 与 API key 别名（agent 桥接是锁定栈）、`database_path`、agent runtime guards（LangGraph 桥接的既定护栏）。

**app.py**：`/health` 只报真实存在的 `status/version/env/llm_provider/llm_model`；`/api/v1/research` 501 存根删除——v3 没有这个方向，一个回应"还没做"的端点本身就是在为不存在的计划背书。

**models**：`domain.py` 整文件删除（RecallRoute / RetrievedDoc / Citation / ResearchRequest / ResearchReport / StatementType / FinancialItem / 重名的 v1 Quote）；`models/__init__.py` 重写为包说明。D4 财务层落地时按 5.2 规则 17（`period_end` + `announced_at`）重新设计，不继承这些形状。

**测试**：`test_domain.py` 全删（14 个用例全部测 v1 模型）；`test_config.py` 删 4 个 v1 用例、**新增 `test_v1_fields_are_gone`**（`Settings.model_fields` 不得出现任何 v1 字段名——死配置复活的守卫）；`test_api.py` 的 research 6 用例换成一个 404 守卫、health 用例改为断言 `retrieval` 键不存在。

**`.env.example`**：删 Embedding / Vector store / Langfuse / Retrieval tuning 四段与 Postgres `DATABASE_URL`（v1 遗物，v2 从未用过），补上真实存在的 `ALPHACOUNCIL_DATABASE_PATH`。
