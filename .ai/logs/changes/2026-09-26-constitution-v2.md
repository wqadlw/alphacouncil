# 变更记录：宪法 v1.0 → v2.0

- **日期**：2026-09-26
- **类型**：治理文件修订（`docs`）
- **范围**：`.ai/constitution.md` · `.ai/README.md` · `.ai/agents/reviewer.md` · `.ai/specs/001,002,003` · 新增 `.ai/traces/`
- **依据**：宪法附则 —— "修改本文件本身需要：在 `.ai/logs/changes/` 开一条记录 + 人工确认"

---

## 1. 为什么改

v1.0 写于 2026-09-25，当时项目方向**尚未收敛**。两天内发生了四件事，使 v1.0 不再成立：

| # | 事件 | 对宪法的影响 |
|---|---|---|
| 1 | 主人指出"功能规划没有亮点 · **数据必须要有** · 不能让人觉得很无聊" → 产出产品定义 **v2**（9 项功能 → 22 项，路线顺序反转） | 需要数据契约与迁移纪律 |
| 2 | 主人明确交付形态是**桌面程序（exe 安装包）** | 技术栈整表过时（Next.js → Vite + pywebview） |
| 3 | 主人加三条约束：**简历 / 自用 / agent 全程开发** → 产出产品定义 **v3** | 需要 Agent 协作规约 + Agent 权限边界 |
| 4 | 完成 wealthfolio 与 anki 深度解读，得到 **27 项可落地决定** | 需要把这些决定固化 |

## 2. 改了什么（四处结构性修改）

### 2.1 新增第一条 · 产品红线 15 条

**v1.0 完全没有产品红线** —— 只有工程红线。这是一个缺口：
产品的红线如果只写在产品文档里，代码里就会出现 `result_score = 0`（违反红线 6）。

**v2.0 为每一条红线都指定了「实现层面的强制手段」**，让红线可被代码审查。

### 2.2 技术栈整表替换

| 移除 | 原因 |
|---|---|
| LlamaIndex · Qdrant · LightRAG | ⚠️ **v1 的方向性错误** —— 当时把"智能检索层"当产品卖点。**我们做决策记录，不做检索框架** |
| AKShare | Python 标准库直连**已验证可用**（东财日线 178 条 / 腾讯·新浪实时），引入只会给 exe 增重 |
| Next.js | 桌面壳里 SSR 无用，改 **Vite + React** |

**新增**：pywebview · PyInstaller + Inno Setup · SQLite + Alembic · py-fsrs · LangGraph · Langfuse · fastmcp

**并新增 3.1「明确排除」表**（附理由，不得重提）—— 防止 agent 反复提议已被否决的方案。

### 2.3 新增第二、四、五、六条

| 条 | 内容 | 来源 |
|---|---|---|
| 第二条 | **Agent 协作规约**：六条工作约定 + **新增机制的门槛** + 单一命令入口 + 不虚构 | `wealthfolio/AGENTS.md` · `anki/CLAUDE.md` |
| 第四条 | **数据契约**：四类口径（百分比 / 复权 / 日期 / 股本）+ PIT + 数据源纪律 | TSP 借鉴笔记 · anki 反面教材 |
| 第五条 | **数据库与迁移纪律**：可逆 / 不编辑已发布 / 迁移前快照 / **`temp_store=FILE`** | wealthfolio 51 个迁移 + 21KB 验证报告 |
| 第六条 | **Agent 权限边界**：工具权限四档，红线 15 的代码级落地 | `wealthfolio/.../cli-mcp-agent-access.md` |

### 2.4 审查纪律升级

新增两条（借 wealthfolio `AGENTS.md:146, 154-156`）：
1. ⭐ **质疑「这个机制是否需要存在」，而不只是「它是否能工作」**
2. ⭐ **缺少根因证据时，结论必须是「修复未经验证」**

**P0 级别新增两项**：产品红线违反 · agent 越权写入。
