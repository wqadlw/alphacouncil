# 2026-09-28 · 知识库检索：FTS5 + trigram，以及「两个字搜不到」这件事（spec 027）

> 接 spec 026。上一轮把「记录知识」的能力补上了，但**记了却找不到**，
> 而一个记了却找不到的知识库等于没记。
> 执行：OpenCode（Codex）· 模型：Space Bunny Free

---

## 一、⭐ 先量，再选

「用 SQLite FTS5，中文用 trigram」是标准答案。**动手前先量**：

```text
sqlite3 version: 3.53.1
FTS5: available
trigram tokenizer: available
  MATCH '流动性' -> 1 hit   MATCH '不存在的词' -> 0 hits
```

**四个机制实测通过**（不是想当然）：

| 要确认的 | 结果 |
|---|---|
| 触发器能否在 **STRICT** 表上写进虚拟表 | ✅ 能 |
| `DELETE FROM notes_fts WHERE note_id = ?`（该列 UNINDEXED） | ✅ 能，不报错 |
| UPDATE 之后**旧文本是否真的消失** | ✅ 消失（最要命的一条） |
| `bm25()` 排名 | ✅ 存在，**但不用它** |

## 二、⭐⭐⭐ 最要紧的一条：**trigram 有 3 个字的下限，而中文最常搜的就是两个字**

```text
  2 chars  MATCH '利率'     -> 0 hit(s)      ⭐
  2 chars  MATCH '白酒'     -> 0 hit(s)      ⭐
  2 chars  MATCH '估值'     -> 0 hit(s)      ⭐
  3 chars  MATCH '现金流'   -> 1 hit(s)
```

`trigram` 索引**重叠的 3 字序列**，少于 3 字匹配不到任何东西。
而「利率」「白酒」「估值」「宏观」「渠道」——**这个领域里最自然的检索词恰好全是两个字**。

⭐ **一个对「利率」返回空结果的搜索框，比没有搜索框更坏**：
没有搜索框，用户知道没有；搜索框返回空，用户会以为**那条笔记不存在** ——
而那条笔记可能就在屏幕上。

→ **≥3 字走 FTS5，<3 字走 `instr()`。** 两条路都有测试，且分工写在代码注释里。

---

## 三、⭐ 「只过滤，不重排」

`bm25()` 可用，**主动不用**。

列表的顺序是 `updated_at DESC`，这是一个**承诺**。打了字就换成相关度排序，
会让同一批数据**因输入长短呈现两种顺序** —— 那种「说不清哪里怪」的不一致比没有排序更坏。

→ 检索是**过滤器**：`WHERE` 加上，`ORDER BY updated_at DESC` 不动。

---

## 四、⭐ 短路径用 `instr` 而不是 `LIKE` —— 把失败模式**去掉**，不是**绕过**

spec 026 的变异检查在**标签**过滤上抓到过这个洞，所以这里是已知的形状：

```text
     '%'    instr -> 1   LIKE -> 4
     '_'    instr -> 0   LIKE -> 4
```

读者在两字搜索里打一个 `%`，`LIKE '%%%'` 会返回**整个知识库**且不报错。

`instr(x, y)` 是纯子串判断，**完全没有通配符语义**。
spec 026 里那个洞是**加测试**堵的；这里是**改形状**，所以测试不会被忘掉。

---

## 五、索引由**触发器**维护，不由仓储维护

三条理由：触发器**不可能被忘记**（绕过仓储直接写库的那条路没人会记得同步索引）·
触发器对**每条写路**都生效 · UPDATE 必须**先删后插**（FTS5 虚拟表不支持 UPDATE，
只插不删会留下一条「正文已改、索引仍是旧文」的行）。

---

## 六、⭐⭐ 虚拟表与约束台账：一个必须处理的意外

`test_storage.py` 按 `kind == "table"` 过滤，而 **FTS5 虚拟表在 `sqlite_master` 里
就是 `type='table'`**。更糟的是实测发现**一张虚拟表带来五张影子表**：

```text
notes_fts_config  notes_fts_content  notes_fts_data  notes_fts_docsize  notes_fts_idx
```

**决定：台账只收「我们在已发布迁移里写过 `CREATE` 的表」。**

被否掉的方案是按名字排除 `<vtable>_<something>` —— **那是名字启发式**，
不符合命名习惯的影子表会被**偶然**归类。改问「我们自己的 SQL 里有没有这条 CREATE？」
是「已声明」的一个**定义**，不会漂移。

配套两条测试：
- `test_the_filter_is_not_vacuous` —— 过滤器**不能把表全滤掉**（否则空集对空集恒真）
- `test_only_a_virtual_table_may_have_no_declared_constraints` —— **`{}` 只允许虚拟表**
  （`notes_fts` 确实是 `{}`：FTS5 解析自己的语法，装不下 CHECK。
  但 `{}` 本身是个洞 —— 任何表都能用 `{}` 免掉台账检查。**把洞变成护栏**）

### 7.1 孤儿行：我的测试**声称钉住的东西，它其实没钉住**

`test_a_deleted_note_is_not_findable` 在删掉 `AFTER DELETE` 触发器后**照样绿** ——
因为检索是 `notes_fts JOIN notes`，**是 JOIN 保证看不见的，不是触发器**。

⭐ 「搜不到」和「不保留」是**两句关于不同机制的话**，把它们混成一句，
测试就会在它唯一该起作用的地方失效。

补的测试直接断言**行数**。而且 **id 必须在删除前抓** ——
第一版从索引里反查 id，而触发器一旦生效就查不到，**测试只在 bug 还在时通过**。

### 7.2 组合：两条断言**无法区分**「组合」与「标签压过检索」

原 fixture 是「一条有文字有标签 + 一条都没有」——
「先搜后筛标签」和「只按标签筛、完全不管检索」**返回同一批**。

补的形状：**一条有标签但没有那个词**。于是「只按标签筛」返回两条、组合返回一条，
「不管检索」变成**看得见的**差异。E2E fixture 同样改了（`宏观但正文无关`）。

### 7.3 一个**不是变异**的变异（如实记下来）

「删掉空查询的提前返回」这条注入**测试全绿，而这是对的**：
实测 `instr(x, '')` 返回 1，所以空 needle 已经匹配每一行、顺序也一样 ——
**删掉这个分支，调用方能观察到的行为一个字节都不变**。

留在报告里就是拿一个 no-op 冒充"漏网"。所以它被换成了真变异，
而那个分支的性质写进了仓储的 docstring：**它是清晰度与成本的分支，不是行为的分支**，
免得下一个人为不存在的差异写测试。
