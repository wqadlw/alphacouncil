## 二、⭐ 三个由**调查**得出、不是由喜好得出的决定

### 2.1 依赖：零新增

宪法第三条禁止未经批准引入运行时依赖。锁定表前端是
**Vite + React + TypeScript + shadcn/ui**（明确**不用 Next.js**），
而 **TanStack Router / Query 不在表里**。

主人明确选择：**不引入，用现有栈建好框架层**。
于是 `shadcn/ui` 与 TanStack 已如实记进**宪法 §3.0 的「已采纳 / 未落地」**
（该表从 5 条差异增加到 **6 条**），**不假装已实现，也不顺手引入**。

### 2.2 ⭐ 外壳里**不能有任何数字** —— 这条是查出来的

我本以为"导航加不加角标"是审美问题。查 E2E 时发现**三条测试断言的是整页正文**：

| 断言 | 位置 | 禁止 |
|---|---|---|
| 危险象限下**整页无任何数字** | `retrospective.spec.ts:119` | `0-9` |
| 整页不含 | `review.spec.ts:75` | `%` `正确率` `记住率` `掌握度` **`评分`** `得分` |
| 整页不含 | `today.spec.ts:25` | `收益率` |
| 空态不含 | `retrospective.spec.ts:184` | `连续` `打卡` `完成率` `%` |

**导航是正文的一部分。** 所以外壳零数字、零禁用词。
⭐ 顺带一个硬约束：**任何元素都不得叫「评分」**，即使显示的是过程分 ——
这就是全应用一律叫「过程分」的原因。

### 2.3 ⭐ 导航**不预告队列里还剩几条**

`项目总纲` §2.1⑤ 对"想忘记"那个时刻的规定是
**一句陈述，无推送、无红点、无催促词**。

`复习 3` 这个角标会把"你欠着三张卡"变成**看得见、能攀比**的数字 ——
那是**红线 11 戴着.helpful的小牌子**。所以导航只有文字；
队列里有几条，由**点进去之后**的那句话回答。

（队列页**内部**报数是可以的——那是读者已经选择去看之后的事实。
E2E 有一条测试专门区分这两者。）

## 三、⭐ 两个当场被抓到的设计错误

### 3.1 路由名不该从 href 切出来

我第一版写 `name: href.slice(2)`，**看起来很聪明**。测试立刻红了：

```
expected { name: 'unknown', raw: '#/' } to deeply equal { name: 'today' }
```

`'#/'.slice(2)` 是 `''`，不是 `'today'`。**name 不是从 href 可还原的。**

> **"聪明"和"错"的比例最差的一种，就是只在唯一一个 case 上错的那种。**

### 3.2 ⭐ `useResource` 的竞态原本**根本没法测**

代次计数器是这里唯一微妙的东西：切到另一张卡时两个请求同时在飞，
**后到的会覆盖先到的**，页面静静显示错的那一行。

问题是：**本仓库 vitest 没有 DOM 环境**（没有 jsdom，加它算新依赖，宪法不批），
所以 hook 一行都测不了。

于是把计数器抽成 `RequestRunner`（普通 class，不需要 React），
hook 变薄绑定。测试直接驱动它，**把两个请求乱序 settle** ——
**这是唯一能证明计数器有用的办法**：按顺序 settle 的测试，
对一个根本没有计数器的实现也会通过。

抽出来的副产品：`set-state-in-effect` 警告 8 → 1。那不只是噪音，
那是每次加载多一次渲染。

## 四、⭐ 变异 harness 出了三个 bug，**每一个都指向了错误的方向**

这一轮的承重断言**全是负面的**（"导航无数字"、"导航不预告条数"）——
一个空导航也能让它们全绿。所以变异不是可选项。

| # | harness 的错 | 后果 | 修法 |
|---|---|---|---|
| 1 | 端口 5173 被我**自己给主人演示时留下的 `npm run dev`** 占着 | Playwright 的 webServer 起不来，**整个套件没跑**，退出码非 0 被记成"抓到了" | 杀掉残留进程；并给 harness 加**基础设施关键词拒绝**（`webServer` / `EADDRINUSE` 一律判为 INFRA FAILURE） |
| 2 | M5 的第一个写法让 `current` 变成未使用变量 → **`tsc -b` 失败** → `npm run build` 在 `&&` 处短路 → webServer 退出 2 | ⭐ **编译错误伪装成了测试失败** | 变异必须**能编译**；harness 先跑 build，编译不过就**拒绝评分** |
| 3 | 我的正则只认 `/`，而 Windows 上输出是 `e2e\nav.spec.ts` | ⭐ **假阴性**——一个**确实被抓住**的变异被判成"没抓住"，会让我去写一条**已经存在**的测试 | 正则改成字符类 |

**这是同一个错误的第四次出现**（020 丢信号、021 拿错信号、022 端口冲突、022 编译错误），
而第 3 条是**第一次指向相反方向**。共同点不变：

> **一个只看退出码的 harness，分不清"测试抓到了"和"套件根本没跑"。**

M5 复验后的真实结论：**被 `nav.spec.ts:109`「地址看不懂时导航仍在」抓住**
（`Expected: 0, Received: 1` —— 正是"错误页不许点亮任何导航项"那条）。
