## ① 想做什么

把「有来源的主张」变成系统的一等公民。K1 是知识层的**第一块**：一张卡片 = 一句主张 + 出处（URL+标题）+ 立场（支持/质疑/中性）+ 权重 + 数据截至日 + 关联标的。三个约束是它存在的理由：**没有出处的断言不进门**（domain 守卫）；**id 是服务端写入时刻，客户端带 id 即 422**（S-06，防倒填日期）；**AI 生成的卡片必须标记 origin，且只能由人对照出处后升级**（红线 15，防 AI 自我认证）。

## ② 做了什么

**修复半成品缺陷（先于一切新功能）**：
- `repositories/cards.py`：`CardRow` 的 `as_of/origin/priority/status/created_at/symbols` 六个字段从文件底部的裸注解移回 dataclass；`verify()` 改用 `dataclasses.replace` 返回升级后的行（此前设计是二次查询 + `type: ignore`）；清理导入排序、行长、S608（白名单表 + 行内 noqa）、F842。
- `domain/card.py`：`CardPriorityInvalidError.code` 改为新增的 `CARD_PRIORITY_INVALID`，并在 `.ai/error-codes.md` 与 `error_codes.py` 双登记。
- **补测试**：`test_card.py` 新增 12 个仓储用例（create 全字段回读、无标的回读、自动建 instruments 行、query 三维独立过滤、limit、list_for_symbol、重复关联幂等、verify 升级持久化、verify 已升级 409、verify 缺失 404、list_all 排序）——此前仓储零覆盖，缺陷②③都是这样漏网的。

**T5 API**：`routes/cards.py` 四动词。`CardCreateRequest` 无任何服务端字段（`extra="forbid"`）；`POST /cards` 201 回读服务端盖戳的完整行；`GET /cards` 支持 claim_type/origin/status/limit 与 market+code 组合过滤（单边拒绝 422）；`GET /cards/{id}` 404 envelope；`PATCH /cards/{id}/verify` 只有 `ai_generated` 可升级（否则 409）。`instruments/{market}/{code}` 详情附 `cards`（newest first）。symbols 走 `parse_ticker`，与全 API 同一解析器。

**T6 前端**：`CardSection.tsx` 挂到标的页（第五问「我对它说过什么」）。列表 newest first（与决策日志 oldest first 相反，理由写在组件注释里）；每张卡显示立场、权重、数据截至日、来源链接、采集时刻；`ai_generated` 卡带警告色 + 「我已对照过出处」升级按钮；表单四个必填（主张/标题/链接）+ 立场/权重/数据截至日；提交后清空并刷新。`InstrumentPage` 头部问题改为五个，「还没有的部分」移除 K1 行、把缺口表述更新为「K2 复习与淘汰」。

**测试**：`test_cards_api.py` 20 例——服务端字段、空 symbols、S-06 拒绝 id/captured_at、空白/超长内容、非 http 来源、非法 ticker、越界优先级、空列表、三维过滤、标的过滤、单边 422、单卡回读、404、verify 三条路径、标的页集成（卡片随详情返回、newest first、无关标的卡不出现）。
