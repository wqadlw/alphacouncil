## 二、⭐ 三件由**调查**得出、不是由喜好得出的事

### 2.1 ⭐ 一份写得极细的规范，零人实施、零人发现

`AlphaCouncil-前端资源与打磨规格.md` §4.3 列出 **12 个必须补的组件**，
§七要求 **⌘K 全局搜索面板**，§3.1 **早已选定** Lucide 图标。
实测：组件 **0 个**、⌘K **未实现**、图标 **零**、搜索 **零**。

字号也能量化：174 处里 **91 处用 12px、7 处用 11px**，
而姊妹项目给同类程序定的下限是「**正文永不小于 13**」。**56% 的界面比程序允许的密度还小。**

⭐ **这份事实比"没有规范"更值得记**，因为它的失败方式很特别：
**规范写得越权威，越不会被怀疑没做。** 所以本轮最重要的产物不是组件，
是 `styleguide.test.ts` —— **把 V-01~V-08 从散文变成会失败的测试**。

### 2.2 ⭐ 合并两份规范，但**没有各打五十大板**

两份规范在**四处是有意不同的**，折中会毁掉本项目：

| | 裁定 | 依据 |
|---|---|---|
| 圆角 > 4px | **保留禁止**（姊妹项目用 8/12/16） | §4.4：一圆就变成 SaaS 后台 |
| 任何 `box-shadow` | **保留禁止**，⌘K 遮罩开**唯一**例外 | 研报是印刷品，印刷品没有阴影 |
| 衬线 | **保留必需**，并定分工：**衬线=内容，无衬线=外壳** | 规则 1 |
| 入场动画 | **保留禁止**（姊妹项目有 `fade-slide`） | 每次打开都等 = 像 Landing Page |
| 字号 | ⚠️ **两者都对，说的是不同东西** | 见下 |

⭐ **字号是唯一的真冲突**，判据一句话：
> **要读成段落的字不得小于 13px；表格与标签可以小，因为它们不是段落。**
> 规则 6（信息密度优先）说的是后者。

**采纳姊妹项目的是管道，不是审美**：`cn()` / `cva` / 组件清单 / `app/ components/ hooks/ lib/`。

### 2.3 ⭐ 姊妹项目的 §2「冻结技术栈」是**愿望**，落地是**刻意极简**

它 §2 列了 TanStack Query / Zustand / RHF+Zod / Recharts / fontsource，
**而 `package.json` 里一个都没装** —— 实际只有 `cva` / `clsx` / `tailwind-merge` / `lucide-react`。

这份"规范是愿望"的证据直接决定了本项目的依赖预算：
**"做成程序"在这个主人的作品里，代价只有 3 个小工具。**
主人据此批准了 4 个包，**没有批准 shadcn 全量（Radix）**。

## 三、⭐ 四个当场被 E2E 抓到的设计错误（**全部是真回归**）

第一次跑门禁：**5 处 E2E 失败**。逐个查清，**没有一个是测试过时**：

| # | 我写的 | 抓到什么 | 修正 |
|---|---|---|---|
| 1 | `UnknownRoute` 自己写了一个 `<h1>这个地址看不懂</h1>` | `titleFor('unknown')` 已由外壳标题渲染同一句 → **屏幕上两遍**，Playwright 严格模式直接判失败，**2 个测试同时红** | 删掉重复标题。**命名页面是外壳的职责** |
| 2 | 把「失效条件」和「去核实数据」拆成同一行两段 | ① 严格模式下 `去核实数据` 匹配到 2 个元素；② **更要紧的是丢掉了语义** | 恢复整句 |
| 3 | 删掉了空态那句「你写下的每个条件都会在它该被看的那天出现在这里」 | 后半段是**空页面不是数据丢了**的唯一保证 | 恢复 |
| 4 | 以"外壳已经说了今天"为由删掉 `今天 · 2026-09-28 · 周一` | 日期是今天页与静态列表的**唯一区别** | 日期进**外壳标题**，且是**同一个句子** |

⭐ **第 2 条是这批里最要紧的一条，因为它不是排版问题**：
「**观察期已到 —— 去核实数据**」是一个从句，拆成"状态 + 链接"读起来弱得多，
而**弱的那个读法会让读者以为条件已经被裁定过了** ——
而 `已触发` 是 `today.spec.ts:25` 明确禁止出现的（系统没有指标源，什么都没裁定）。

⭐ **第 4 条是这批里最有价值的一条**：`today-hub.spec.ts:171` 用
`getByText('今天 ·')` 当"页面渲染了"的代理。
**如果我当时图省事把它改成 `getByRole('heading')`，日期会悄悄消失，而这个测试仍然会绿。**
一个用脆弱方式写对的测试，比一个用稳健方式写错的测试更有价值 —— 但只有前者抓得到东西。

## 四、⭐ 变异检查：9 次全抓，**其中 3 个抓出的是真漏洞**

一个从没失败过的 lint 不算 lint。逐条注入后：

| 注入 | 结果 |
|---|---|
| `rounded-lg` / `rounded-full` | ✅ 抓住 |
| `@keyframes` / `animate-pulse` | ✅ 抓住 |
| `package.json` 加一个未批准依赖 | ✅ 抓住 |
| 把 `--color-up` 换成绿色（**红涨绿跌被换掉**） | ✅ 抓住 |
| **`shadow-md`** | ❌ **第一版漏了** → 补 |
| **`shadow-[0_1px_2px_…]`** | ❌ **第一版漏了** → 补 |
| **`style={{ boxShadow: … }}`** | ❌ **第一版漏了**（正则大小写敏感，`boxShadow` 有大写 S） → 补 |

⭐ **三个漏洞指向同一件事**：这个代码库里没人会手写 CSS，阴影会从**Tailwind 类名**进来，
而全局 `* { box-shadow: none }` 会把它**藏起来** ——
类名留在那儿看起来有意义，**改一行 CSS 就开始生效**。
**只有变异检查能发现这类漏洞**，因为它们在代码评审里完全正常。

### 4.1 另外两个**假阳性**，教训比漏洞更通用

- **三处失败全是"规则在描述自己"**：`globals.css` 里的 `box-shadow: none`（**禁令本身**）、
  `index.tsx` 注释里的 `` `rounded-lg` ``（**解释为什么禁止它**）。
  → 扫描必须**先去注释**。不做的后果很具体而且很坏：
  维护者会**为了让它变绿而删掉解释规则的注释**，知识没了，测试绿了。
- **一条断言失败、消息却是空的**：`box-shadow\s*:\s*(?!none\b)` 里的 `\s*`
  会**回溯到零宽**，让负向前瞻站在空格上、判定通过。
  → 用 `(?=\S)` 钉住。**"失败信息为空"是这条 bug 的唯一症状** ——
  和台账里记的 4 次 harness 失败属于同一类：**检查器自己出错了，却报成了被检查对象出错。**

### 4.2 ⭐ `.gitignore` 的 `data/` 差点让一个核心源文件**不进仓库**

准备提交时 `git status` 列出 22 个文件，**唯独少了 `DataTable.tsx`**。
`git add -A` 报成功、`git status` 看起来干净，而那个文件**根本没被暂存**。

原因：`.gitignore` 第 51 行的 `data/` **没有前导斜杠，所以 git 在任意深度都匹配它** ——
连 `frontend/src/components/data/` 一起吃掉。**这不是猜测**：
`git status --ignored` 把它列为 `!! frontend/src/components/data/`。

**为什么值得单列一节**：门禁 **10/10 全绿**，因为门禁跑的是**工作区**，
而工作区里那个文件好好地在那儿。**这个缺陷只有在"将要提交的内容"这个视角下才存在。**
clone 那个提交的人会得到一个**编译不过**的前端。

修法沿用仓库里已有的先例（`.ai/checks/data/` 同样被 `data/` 吃掉，所以已经有 `!` 反选）：
加 `!frontend/src/components/data/`，并把坑写在 `.gitignore` 里。

⭐ **顺带一条可复用的检查**（本轮实际执行过）：

```powershell
# 磁盘上的源文件 vs git 认的源文件
$onDisk   = Get-ChildItem frontend\src -Recurse -File -Include *.ts,*.tsx,*.css | % { $_.FullName }
$tracked  = git ls-files frontend/src
$onDisk | ? { $tracked -notcontains $_ }
```

结果 `31 / 31` 全部入库。**这类"存在但没被跟踪"的路径，任何静态检查都发现不了** ——
因为它们就在那里，只是 git 不打算收。
