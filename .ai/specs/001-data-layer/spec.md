## 背景与目标

Agent 的所有分析都建立在数据之上。当前系统没有任何数据获取能力，需要先建立**可靠、可复现、可追溯**的数据底座。

核心约束：**数据必须落地到本地**，而不是每次分析时实时调用外部接口。原因有三：

1. 外部接口不稳定，实时调用会让 Agent 的行为不可复现；
2. 投研分析需要历史数据（如「近三年营收」），实时接口通常只给最新值；
3. 本地数据可做增量更新与版本追踪，便于复盘。

## 用户故事

- 作为研究 Agent，我希望拿到某只股票的历史行情，以便计算技术指标。
- 作为研究 Agent，我希望拿到某公司的财务报表数据，以便计算估值指标。
- 作为系统维护者，我希望数据能定时增量更新，以便不重复抓取全量数据。

## 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | 支持按股票代码拉取日线行情（开高低收、成交量、复权因子） |
| FR-2 | 支持拉取财务报表数据（利润表、资产负债表、现金流量表主要科目） |
| FR-3 | 支持拉取自选股列表（watchlist）批量更新 |
| FR-4 | 数据落地到关系型数据库，表结构支持按代码 + 日期查询 |
| FR-5 | 支持增量更新：只抓取本地缺失的日期区间 |
| FR-6 | 抓取失败时记录失败明细，支持重试，且不污染已成功的数据 |
| FR-7 | 所有数据记录携带 `source` 与 `fetched_at` 字段，保证可追溯 |

## 非功能需求

- **性能**：单只股票 5 年日线数据拉取 + 入库 < 10 秒
- **幂等**：同一日期区间重复执行不产生重复记录（依赖唯一约束 + upsert）
- **可观测性**：每次抓取记录条数、耗时、失败数，输出结构化日志
- **可测试性**：数据源通过接口注入，测试时使用本地 fixture，**不依赖真实网络**

## 验收标准

- [ ] AC-1：给定股票代码与日期区间，执行抓取后数据库中可查询到对应记录，且记录数等于交易日数
- [ ] AC-2：重复执行同一区间，记录数不变（幂等）
- [ ] AC-3：给定已存在部分数据的区间，只抓取缺失部分（通过日志中的请求参数验证）
- [ ] AC-4：当数据源返回错误时，抓取任务返回失败状态且给出失败代码清单，数据库无脏数据
- [ ] AC-5：所有记录均含非空 `source` 与 `fetched_at`
- [ ] AC-6：单元测试与集成测试在无网络环境下全部通过

## 明确不做（Out of Scope）

- 实时行情推送（本项目为研究用途，不需要 tick 级数据）
- 分钟级 / tick 级数据
- 交易下单接口（系统明确不接入券商）
- 港美股数据（P1 仅做 A 股；美股作为后续可选扩展）

## 边界与异常

| 场景 | 期望行为 |
|---|---|
| 股票代码不存在 | 记录 `InvalidCodeError`，跳过该代码，继续处理其余代码 |
| 数据源超时 | 重试 3 次（指数退避），仍失败则记录并标记该代码为 `failed` |
| 返回空数据（如停牌） | 记录为 `empty`，**不视为错误**，不写占位数据 |
| 日期区间包含未来日期 | 截断到最近交易日，记录警告日志 |
| 部分代码失败 | 整体任务标记为 `partial_success`，返回成功/失败清单 |

## 数据结构（草案）

```
quotes_daily
  code            str     股票代码
  trade_date      date    交易日
  open/high/low/close  float
  volume          float
  amount          float
  adj_factor      float   复权因子
  source          str     数据来源
  fetched_at      datetime
  PRIMARY KEY (code, trade_date)

financials
  code            str
  report_date     date    报告期
  statement_type  str     income / balance / cashflow
  item            str     科目名
  value           float
  source          str
  fetched_at      datetime
  PRIMARY KEY (code, report_date, statement_type, item)
```
