## 背景与目标

投研问答包含四类问题，**单一向量检索在其中的三类上表现不佳**：

| 问题类型 | 示例 | 单一向量检索的问题 |
|---|---|---|
| 语义型 | 「市场对这家公司的担忧是什么」 | 尚可 |
| 精确型 | 「600519 2024 Q3 毛利率」 | 答不准 —— 数字、代码、专有名词的稠密向量区分度低 |
| 关系型 | 「这家公司的上游供应商有哪些」 | 答不出 —— 向量空间没有实体关系概念 |
| 聚合型 | 「近三年营收复合增速」 | 答不了 —— 需要计算而非检索 |

**目标**：构建一个四路召回 + 融合 + 重排的检索层，并**用可量化的指标证明它比单路检索更好**。

> 「证明更好」是本 spec 的核心要求。没有评测数据的检索改动不予合并（见 constitution 第四条）。

## 用户故事

- 作为研究 Agent，我希望检索结果带来源信息，以便在结论中标注引用。
- 作为研究 Agent，我希望精确型问题（代码、数字）能被准确命中。
- 作为系统维护者，我希望每次检索策略改动都有指标对比，以便判断是否真的改进了。

## 功能需求

### 召回层

| 编号 | 需求 |
|---|---|
| FR-1 | 稠密向量召回：基于 Qdrant + BGE-M3，支持元数据过滤（公司代码、日期区间、文档类型） |
| FR-2 | 稀疏召回：BM25 或 SPLADE，用于精确词、代码、数字匹配 |
| FR-3 | 图召回：基于 LightRAG，支持实体关系查询（上下游、竞品、控股关系） |
| FR-4 | 结构化召回：Text-to-SQL，用于财务数据的聚合与计算类问题 |
| FR-5 | 每路召回独立可降级：某一路不可用时，其余路正常工作（不整体失败） |

### 查询理解层

| 编号 | 需求 |
|---|---|
| FR-6 | 意图路由：判断问题类型，决定启用哪几路召回（避免无谓开销） |
| FR-7 | 查询改写：Multi-Query 生成 2-3 个语义变体，提升召回覆盖 |
| FR-8 | HyDE（可选开关）：生成假想答案用于检索，改善短查询表现 |

### 融合与重排

| 编号 | 需求 |
|---|---|
| FR-9 | RRF（Reciprocal Rank Fusion）融合多路结果，**融合前按 `doc_id` 去重，保留最高排名** |
| FR-10 | 交叉编码器重排（BGE-Reranker-v2），召回 Top-50 → 重排取 Top-8 |
| FR-11 | 上下文压缩：去除冗余片段，控制注入 LLM 的 token 数 |

### 溯源与评估

| 编号 | 需求 |
|---|---|
| FR-12 | 每个检索结果携带 `doc_id`、`source`、`page`、`snippet`、各路召回排名 |
| FR-13 | 生成答案时强制引用来源，无来源支撑的结论不得输出 |
| FR-14 | 提供 RAGAS 评测脚本，覆盖四类问题各 ≥ 15 条 |
| FR-15 | 评测结果写入 `tests/eval/` 并可在 CI 中运行 |

## 非功能需求

- **延迟**：单次检索（四路并发）P95 < 2 秒（不含 LLM 生成）
- **可观测性**：每次检索记录各路召回数量、融合后数量、重排耗时（接入 Langfuse）
- **可配置**：`recall_top_k`、`rerank_top_k`、各路开关均通过配置控制
- **可复现**：给定相同语料与查询，结果稳定（固定随机种子）

## 验收标准

- [ ] AC-1：四类问题各构造测试用例，均能召回包含正确答案的文档
- [ ] AC-2：精确型问题（含股票代码）的召回命中率显著高于纯向量检索（附指标对比）
- [ ] AC-3：关系型问题能通过图召回返回实体关联结果
- [ ] AC-4：聚合型问题能通过 Text-to-SQL 返回计算结果
- [ ] AC-5：任一路召回失败时，系统返回其余路结果而非抛异常（降级测试）
- [ ] AC-6：融合后结果中不存在重复 `doc_id`
- [ ] AC-7：每个结果均含完整的溯源字段
- [ ] AC-8：RAGAS 评测可运行，并输出 `faithfulness` / `context_precision` / `context_recall` 三项指标
- [ ] AC-9：README 或 `docs/RETRIEVAL.md` 中含「单路 vs 四路」的指标对比表

## 明确不做（Out of Scope）

- 微调 embedding 模型（成本高，先用现成模型 + 重排）
- 多模态检索（图片、图表识别留待后续）
- 实时索引更新（采用离线批量建索引）

## 边界与异常

| 场景 | 期望行为 |
|---|---|
| 查询为空或过短 | 返回参数校验错误，不发起检索 |
| 向量库不可用 | 降级到稀疏检索，记录 warning |
| 图检索超时 | 降级，其余路结果正常返回 |
| Text-to-SQL 生成非法 SQL | **必须白名单校验（仅允许 SELECT）**，拒绝执行并降级 |
| 全部路均失败 | 抛出 `RetrievalUnavailableError`，由 Agent 层决定是否重试 |

> **安全红线**：Text-to-SQL 生成的语句**必须**经过 SQL 解析器校验，只允许 `SELECT`，禁止任何 DDL/DML。这是防注入的硬要求。
