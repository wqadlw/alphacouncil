## 一、为什么要推送通道

红线 7 要求**每条教训自动入排程**，spec 028 给了笔记一个「**会自己回来找你**」的复习队列。

⭐ **两个承诺都只兑现了一半**：排程存在，然后程序等着**你去打开那个页面**。
一个只能靠「去某个页面才能发现」的待办不是提醒，是表格里的一行。

⚠️ 但边界要说清楚：**本 spec 只建通道，不建决策。**
「什么东西值得发出去」属于排程器。把这个判断放进通道，一个函数就干两件事，
也就只有一个地方可以出错。`notify/` 里的每个模块只接受已经渲染好的标题与正文。

## 二、⭐ 卡住 Webhook 的那个问题：HTTP 出口的归属

TSP 的 `webhook_adapter.py`（16.7KB）本身很干净 —— 只依赖 `httpx` + 标准库，不碰它的领域类型。

⭐ **但它抄不过来**，原因是本项目的 S-01：

> 不在 `providers/` 目录下 `import httpx` = `CHECK_RAW_HTTP` error，
> 官方修复建议是「走 provider 层 —— `alphacouncil.providers.default_router()`」

而**那条修复建议对 webhook 是错的**：`default_router()` 是**行情**路由，
按 `Dataset` 声明能力、按 `BatchSemantics` 处理批量失败。把一个 webhook POST 塞进去，
就是让一个为「腾讯/新浪/东财的日线」设计的抽象去发一条飞书消息。

⭐ **所以这不是「抄代码」的障碍，是一道真实的架构问题。** 三个选项：

| 选项 | 做法 | 代价 |
|---|---|---|
| **A. 给 S-01 加白名单目录** | 把 `notify/` 列为允许直连 HTTP 的第二个包 | ⭐ **红线规则新增例外**，且例外理由是「我需要一个 HTTP 客户端」—— 不足以服人 |
| **B. 提到 `core/http.py`** | 一个被允许构造 client 的工厂模块，两个包都用它 | 要改 S-01 的判定（从「目录」改成「模块」），但**没有一个包获得特权** |
| **C. 不做 Webhook** | 只保留邮件通道 | 少一个渠道，但零架构改动 |

**倾向 B，但本 spec 不做决定。** ⭐ 理由：S-01 现在判的是**目录**，
而它真正想守的是「**HTTP 客户端只在被认可的地方被构造**」。
⭐ 从目录改成模块，是把规则对准它的**意图**，而不是扩大它的口子 ——
但这属于改一条 P0 规则，得先想清楚。

📌 无论选哪个，**三条品牌串必须改**：`User-Agent: TickFlow-Webhook/1.0` ·
`X-TickFlow-Timestamp` / `X-TickFlow-Signature` · 截断提示里的「回到 TickFlow 应用内查看」。
⭐ 那是**用户能看见的字符串**，上面写着别人的产品名。

## 三、已落地：SMTP（`notify/email.py`）

⭐ 选它先做，是因为它**只依赖 `smtplib`，完全不碰 `httpx`** —— 零 S-01 冲突。

从上游复制，保留了三处真实缺陷类的修复：

1. ⭐ **`QUIT` 失败不得重试。** `send_message` 成功就意味着邮件已送达；
   此时 `quit` 抛错再重试 = **收件人收到两封，而且无法分辨哪封是真的**。
   有专门一条测试叫这个名字。
2. ⭐ **STARTTLS 之后必须再 `ehlo()` 一次。** 不是装饰：不补这一次，
   会话会保留 TLS 升级前的 capability 集，部分服务器据此拒绝登录。
3. **校验全部在开 socket 之前。** 端口写错应该是**零成本**，而不是每次发送都赔上一次
   10 秒连接超时。

**两处按本项目规矩改了**：MIT 署名进文档字符串（不是进一个没人会打开的 `NOTICE`）、
`logging` → `structlog`（S-10 禁 `print`）。

## 五、明确不做

- **不做**系统弹窗（上游的 `notify_adapter.py` 依赖 `winotify`，那是一个新依赖，
  而本 spec 只需要一个最没有主张的渠道）
- **不做**在通道里判断「值不值得发」
- **不做**为了让 Webhook 能跑而悄悄给 S-01 加白名单 —— ⭐ 那是一条 P0 规则，
  而「我需要一个 HTTP 客户端」不是理由
