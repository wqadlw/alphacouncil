## 一、背景：那个数字从来没人查过

宪法第一条是一张 15 行的表，**第三列逐行写着"实现层面的强制手段"**。
从项目建立到现在，**没有任何东西检查过那一列**。

于是"我们的红线在代码里被强制执行"是一句**和 v1 那份架构文档同类的断言** ——
说得很有力，而没有人核对过。

本 spec 做两件事：把那一列变成机器可读的注册表并**真的跑一遍**；
以及把 0004 的教训变成一条规则，因为**我在修完它的同一天就又犯了一次**。

## 二、`make eval`：第一次诚实的测量

### 2.1 数据：`.ai/eval/redlines.json`

15 条，每条含 `id` / `title` / `enforcement`（宪法的手段原文）/ `coverage` /
`verifier` / `evidence` / `gap`。

`coverage` 三态，**`partial` 与 `none` 必须写 `gap` 说清差在哪**。

### 2.2 关键规则：**没有检查 = 失败**（T-19 用在产品自己的承诺上）

> 一条没有 verifier 的红线**算失败**，不算"不适用"，也不算 skip。

理由是本项目已经被这个坑咬过两次：`0002`（一个从不被解析的 JSON 台账）
与 `check-static` 里长期 `skipped` 的 S-09。
**"没查过"报成"没问题"，是这里最常见的一种谎。**

所以 **`dev.py eval` 今天是红的，这是它的诚实状态**。

### 2.3 两种 verifier，差别不是装饰

| kind | `eval` 做什么 | 标注 |
|---|---|---|
| `static` | **当场执行** `python -m checks --json --strict --only <id>`，要求该规则**真的跑了**（skipped 不算）且 0 error | `executed` |
| `gate` | **不执行**（那是门禁每轮的事）。只验证**声明不会腐烂**：门禁仍在 `CHECK` 里，且**被点名的测试仍存在于源码中** | `declared` |

把 `gate` 说成 `executed` 就是夸大 —— 输出里两者分开标注。

**为什么 static 要一条规则一个子进程**：`checks --json` 的契约只有 `summary`
+ 扁平 `issues`，**没有按规则归属**（实测确认）。改那个契约是动别人已文档化的行为；
`--only` 逐条问能通过**已存在的接口**拿到同样的答案。

### 2.4 结果

```
5 / 15 guarded (33.3%)  ·  coverage: full 5 · partial 2 · none 8
baseline 2026-09-28: 5 / 15 (+0 since)
```

**baseline 在"动手修任何东西之前"就写进了注册表** ——
所以这个数字不可能被"测量行为本身"抬高。

| coverage | 红线 |
|---|---|
| **full（5）** | 1 不做预测增强 · 4 结果之前记录 · 6 未成熟结果留空 · 9 不展示成绩 · 12 必须显示时间的成本 |
| **partial（2）** | 2 只做过程优化 · 13 不讨好用户 |
| **none（8）** | 3 记录优先于分析 · 5 过程分与结果分独立 · 7 教训必须能再次遇到 · 8 功能是拦截不是推荐 · 10 面对不舒服的数据 · 11 不鼓励频繁操作 · 14 日常体验要顺 · 15 Agent 只抽取不判断 |

**8 条 `none` 里有 5 条的 `gap` 写着"依赖某个未实现的能力"**（K3 / J3 / D2 / agent）。
换句话说：**这个项目的红线表里，超过一半的条目目前没有可被违反的对象。**
这与 `docs/ARCHITECTURE.md` 新增的「Adopted but not implemented」是同一件事的两个侧面。

**红线 14 被明确标成 `none` 且写"这条大概率永远无法有自动化检查"** ——
它关于"整体手感"。**如实标注，而不是硬造一个假检查把数字做好看。**

## 三、S-13：把 0004 变成规则

### 3.1 起因：**我修完当天就又犯了一次**

spec 014 修了三个工具（`dev.py` / `check_licenses.py` / `checks/__main__.py`）。
写 `eval.py` 时**忘了加 `use_utf8()`** —— 它的 `--json` 输出是 GBK，
把一个中文字符串从中间截断，我是在 `UnicodeDecodeError` 里发现的。

**三个调用点不是机制。** 而且我在 spec 016 §三 明确写过
"不新增静态检查，因为答不出'具体故障'"。**现在答得出了：故障就是我自己。**

### 3.2 规则

**S-13 `tool-encoding`**：`scripts/*.py` 与 `checks/__main__.py` 打印人类可读输出
却没调 `use_utf8()` → error。`_console.py` 自身豁免（它是实现，不能自调）。

放 **P0** 而不是 P2：它守的不是风格，是**门禁本身能不能说话**。

### 3.3 **它第一次运行就抓到了第四个文件**

`backend/scripts/smoke_market.py` —— 一个手工跑真实网络的冒烟脚本，
打印且从不调 `use_utf8()`。**它不在 0004 的波及范围里，因为我只修了known的三个**，
而且**没有任何测试跑过它**（它不进 pytest）。已修。

> 一个真实的、无声的、就在仓库里的缺陷。**这就是"规则"与"三个仔细的调用点"的差别。**

## 四、变异检查（4 / 4 变红）

| # | 改坏哪里 | 结果 |
|---|---|---|
| M1 | S-13 不再检测未守卫的工具 | ✅ 2 failed |
| M2 | 允许 `partial` 通过 | ✅ 2 failed |
| M3 | 让 `skipped` 的静态规则算通过 | ✅ 1 failed |
| M4 | `gate` verifier 不再检查测试是否还在 | ✅ 1 failed |

**M3 与 M4 各暴露了一个真实测试缺口**，而这两个缺口是同一种病：**我写的测试
重新实现了逻辑，而不是调用它。**

- M3：`test_a_skipped_rule_is_not_a_pass` 造的 report 里 `rules_ran=0`，
  于是代码先命中 `ran == 0` 分支，**从没走到 `skipped` 分支**。分支正确且完全没被钉住。
- M4：`TestDeclaredVerifiersCannotRot` 在**测试侧**重新实现了一遍"测试还在不在"，
  于是删掉 runner 里的实现没有任何测试变红。**重新实现规则的测试是第二条规则，它会各自腐烂。**

> ⚠️ 变异脚本本身也出了一次**假绿**：第一版把 `"path -k S13"` 当成单个 argv 传给 pytest，
> pytest 收集到 0 个测试、退出码非 0，于是三个变异被报成"已抓住"。
> **"收集到 0 个测试"必须判为 harness 错误，不能判为抓住。** 已修（第二次跑即报 HARNESS ERROR）。
> 这是本项目第 N 次同一种错误，不同的是这次它出现在**测量工具**里。

## 六、明确不做

| 不做 | 为什么 |
|---|---|
| 把 `eval` 加进 `CHECK` / `make check` | 它今天是红的。放进 `check` 会让 `check` 永久红，**而一个永久红的门禁会训练所有人忽略汇总** —— 那正是"门禁不再是门禁"。保持为**要主动调用**的命令 |
| 把 `partial` 算成通过 | 数字会好看，文档就是假的 |
| 给红线 14 硬造一个检查 | 它关于"整体手感"。**宁可 5/15 不好看，也不假装 6/15** |
| 立刻去补那 8 条的检查 | 那是路线图（K3 / J3 / D2），不是本 spec。**本 spec 只负责让缺口被看见并可测量** |
| 实现运行期 agent 来验证红线 15 | ADR-0027 的启用条件不满足 |
| 改 `checks --json` 契约以获得按规则归属 | 动别人已文档化的行为；`--only` 够用 |
