## 一、⭐ 先回答一个不回答就不能写代码的问题：**这撞红线 8 吗**

红线 8 的原文：

> **功能是「拦截」不是「推荐」** · 禁止「机会推送 / 每日精选 / 异动提醒」类功能

⭐ **禁的是那三类，不是「所有通知」。** 标题就是判据：这个产品的职责是**在你动手前拦住你**，
不是**替你找机会**。而「拦截」如果只在你恰好打开今日页时才发生，它就不是拦截，是一行表格。

⭐ 所以边界落在**一句话上**，而且这句话**已经存在**：`spec 040` 写在今日页的那五个句子
（「已越过 / 没有越过 / 还差 48 根 / 不在我们能算的指标里 / 取不到日线」）。

| | 发什么 | 撞不撞红线 8 |
|---|---|---|
| ✅ | 「你写的判据『gpMargin > 0.95』**已越过** —— 毛利率 现在 0.97。」 | ❌ 不撞。它**报告的是读者自己写的阈值比较** |
| ❌ | 「贵州茅台值得关注」「今日精选」「你的持仓异动了」 | ✅ 撞。**主语是产品，不是读者** |

⚠️ **`spec 033` §一已经写了同一条纪律**：「本 spec 只建通道，不建决策」——
「什么东西值得发出去」属于排程器。⭐ 本篇把这句话变成结构：**通道只接受已渲染好的文本。**

## 二、⭐ 真正的设计问题：那句话现在只存在于前端

`spec 040` 的五态句子在 `frontend/src/criterionVerdict.ts`。⭐ **后端只有状态和数值。**

```typescript
// frontend/src/criterionVerdict.ts:87
verdict: `已越过 —— ${metric.label} 现在 ${formatValue(metric.value)}（${metric.as_of}）。`
```

⭐ **所以照着做只有两条路，两条都错**：
1. ⭐ 在 Python 里**重写一遍**那句话 —— 两个孩子，而它们会漂移
2. ⭐ 让 webhook 只发状态码（`crossed`）—— 那不是一条提醒，是一行调试输出

⇒ **后端成为那句话的唯一所有者，前端只留表现**（颜色、`adjudicable`）。

⭐ 这不是「为了做 webhook 而重构」——**它让「今日页和通知不可能说不一样」变成结构性的**，
而不再是一条要靠人记住的约定。注释一起搬（理由不搬家就会被重新发明一遍）。

## 三、⭐ 去重**不是**数据缓存，而这两件事极易被混为一谈

⭐ 用户跑两次 `send_due`，就会收到两条一样的话。看上去要「加个缓存」——
⭐ **而那正是 ADR-0031 明令禁止的那一格**：

> 缓存 | ⭐ **不要 —— 有害** | 要

| | 数据缓存 | 通知去重 |
|---|---|---|
| 说的是 | 「我们 5 分钟前取过这个数」 | 「关于**这一件事**，我已经说过了」 |
| 错在哪 | 一条提醒被悄悄丢掉，**且看不出丢了** | 同上 |
| 为什么禁 | ⭐ 「长得太像『复用了已有的好机制』」 | — |

⇒ **去重要的是一张 append-only 的 `notifications_sent` 表**，记录「我告诉过用户什么」。
⭐ 这是**记录一次对外发言**，和 `audit_log` 同一族，不是缓存。

⚠️ **明确不做**：不设 TTL 重发、不做「已读」、不做撤回。
⭐ 「重发直到你看」正是红线 11「不鼓励频繁操作」的反面 —— 而**重复发送的代价由用户承担**。

## 四、⭐ 触发方式：一个命令，不是守护进程

本项目**没有运行期 agent**（ADR-0027：LangGraph/fastmcp 已采纳未实现），
所以「定时自动检查」需要一个后台进程 —— ⭐ 而那要引入调度、生命周期、日志、以及一个新的失败模式。

⇒ **`python -m alphacouncil.notify send_due`**。零新依赖、零后台线程、可测试、
⭐ 且它诚实地只承诺「你跑了它，它就说」。

⚠️ **Windows 计划任务**是使用方式，**不是实现的一部分** —— 那是部署决定，不是代码决定。

## 五、Webhook 通道：ADR-0031 的判定表，逐行执行

| §7.8 的机制 | webhook | 怎么做 |
|---|---|---|
| 超时 / 连接复用 | 要 | `build_client()` |
| 最小间隔 + 抖动 | 要（飞书等有 QPS 限） | ⭐ **照抄 `financial.py` 的三件套**（锁 / 间隔 / 抖动），理由相同 |
| 默认 UA | ⭐ **要，但必须诚实** | `AlphaCouncil-Webhook/1.0` —— ⭐ **不冒充浏览器** |
| 熔断 | 要，语义不同 | 连续失败不重试到死；返回 `False` |
| ⭐ 缓存 | ⭐ **不要，有害** | 通道层**不引入任何缓存** |

⭐ **三条品牌串必须换掉**（spec 033 §二 记着，而它们是**用户能看见的字符串**）：
`TickFlow-Webhook/1.0` · `X-TickFlow-Timestamp` / `X-TickFlow-Signature` · 「回到 TickFlow 应用内查看」。

## 六、配置：沿用已有的形状

`core/config.py` 的 API key 是 **环境变量 + `SecretStr`**（不进文件、不进仓库）。
⭐ webhook 整体按 `SecretStr` 处理 —— **URL 里通常带 token**，所以不是「URL 一个字段 + token 一个字段」，
而是**整个 URL 都是秘密**。⭐ 拆开会把 token 写进一个可以 `print` 的普通字段。

## 七、明确不做

* ⭐ **不做推荐/精选/异动** —— 红线 8，且通道层没有判断能力可用来做它
* ⭐ **不重发、不设 TTL、不做已读** —— 红线 11
* ⭐ **不做守护进程 / 定时器 / 系统弹窗** —— 没有运行期 agent（ADR-0027）
* ⭐ **不做「什么值得发」的一般规则** —— `spec 033` §一已划给排程器
* ⭐ **不把通知塞进 `providers/router.py`** —— ADR-0031 的被拒方案，理由是「一行一条消息要按
  `Dataset` 声明能力」会让行情抽象承担它不理解的东西
* ⭐ **第一批只发「到期判据」** —— 因为那是**已经存在的句子**，不需要我新写一句推荐
