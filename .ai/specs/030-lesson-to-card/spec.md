## 〇、⭐ 本 spec 自己被纠正过一次，记在这里

第一稿把教训放进 `cards`：放松 `source_url` / `source_title` 为可空，加一个
`review_id`，让出处变成「URL **或** 复盘」。听起来很有道理 —— provenance rule
不但没松，还更强了，因为一次复盘比一个链接更说明你当时怎么想的。

然后我去读 `0003_knowledge_cards.up.sql`，发现两个 `NOT NULL` **改不了**：
SQLite 不能 DROP 掉 NOT NULL 或 CHECK，除非**重建整张表**，而 `cards` 被
`card_schedule` / `card_events` / `note_links` 外键引用，自带三个索引。

**但重建不是重点，重点在我自己写过的话里。** `status.md` · spec 026 那行的诊断：

```
`cards` 表被 `source_url` 必填 + `source_title` 必填 + 前端硬编码单只 6 位代码
三条锁死 → 宏观判断、方法论、教训、读书笔记全都记不下
```

⭐ **教训就是当初建笔记的原因之一。** 为了让它回去而放松 `cards` 的出处规则，
是把 spec 026 整个反过来 —— 然后还要为这份特权付一次表重建。

**教训没有 URL 可给。** 这不是缺陷，这是它的定义：
它的出处是**一次真实发生过的、你自己的判断失误**。

## 一、红线 7 自己怎么写的

`constitution.md` 第 7 条：**教训必须能再次遇到 · 每条教训必须生成一条调度项（FSRS）**。

`.ai/eval/redlines.json` 里它记着自己的缺口：

> **机制有了，「每条教训自动生成」还没有。** 本项目**没有「教训」这个类型**
> （`cards` 表只有 `origin`/`priority`/`status`），J5「教训转卡」未开工，
> 所以**没有任何东西保证一条教训会走进队列** —— 全是用户手动排程的。

⭐ 关键词是**自动**。今天的排程是用户点一下才发生的，红线要的是
**每条教训自动产生一条调度项**。这两句话之间差的不是「加个按钮」，是**性质**。

⭐ 顺便注意红线**没有**说的话：它从没说「每条教训必须变成卡片」。
给教训一条调度项，字面上就是它要的东西。

## 二、⭐ 四张表，以及每一张为什么存在

| 表 | 是什么 | 为什么非它不可 |
|---|---|---|
| `lessons` | 教训本身 | 它的出处是一次复盘，而 `cards` 的出处是一条 URL —— 两者不能互换 |
| `lesson_schedule` | 「现在怎么样」的真源 | 红线 7 的落点 |
| `lesson_reviews` | append-only 流水 | 每次交互一行；与 `card_reviews` / `note_reviews` 同构（ADR-0014） |
| `lesson_promotions` | append-only，转卡的记录 | ⭐ 见 §3 —— 因为**教训不可变**，所以「转成卡片了」不能是 UPDATE，只能是流水 |

### 2.1 ⭐ 教训**不可变** —— 而这有一个可推导的后果

K1 刻意不给卡片编辑动词，理由是「我当时复习的那条」永远是同一条。
**教训同一条**：你不会去改一条教训，因为你改完它就不是那条教训了，
你会写另一条。

⭐ **于是 `lesson_reviews` 没有 `outcome = 'reset'`。**

这不是抄漏了，是 spec 028 那次发现**反向**用上了：
> `note_reviews` 需要第三态 `reset`，因为**笔记可变** ——
> 队列里的东西被改写后，FSRS 的记忆强度还挂在**已经不存在的文本**上。
> **卡片不可变，所以它永远不需要 `reset`。**

教训也是不可变的，**所以它也不需要**。
现在三套流水里只有 `note_reviews` 有第三态 —— 而**三套里有两套没有**，
这个不对称是「教训和卡片同一类」的直接证据，不是巧合。

## 三、⭐⭐ 「转卡」不能是 UPDATE —— 于是它变成一条事实

教训不可变（第 2.1 节）。那「这条教训已经变成卡片了」怎么记？

**不能写在 `lessons.card_id` 上** —— 那是 UPDATE，而 `lessons` 不许被改。
所以它是 `lesson_promotions` 的一行：

```sql
lesson_id TEXT NOT NULL UNIQUE   -- ⭐ 一次教训只转一次
card_id   TEXT NOT NULL UNIQUE   -- 一张卡片只来自一条教训
```

⭐ **两个 UNIQUE 是这条设计里最强的部分**，因为它们让「重复转卡」在数据库层
不可能，而不只是「代码记得检查」。

### 3.1 ⭐ 转卡要求你给出处 —— 而这个要求是推导出来的，不是加的

一张卡片必须有 `source_url` + `source_title`（红线 4）。一条教训**两者都没有**。

所以：

> **「我拿不出出处」= 这条还不该是卡片，它已经是一条教训了。**

这不是新规则，是既有约束的**推论**。而它恰好是对的：
**「转卡」是一个判断动作，不是一次数据搬运。**
「记下了但还不敢署名的想法」由 spec 026 的笔记装着 —— 那是它本来就该去的地方。

⭐ 所以 `POST /lessons/{id}/promote` **不接受**「没有出处」这个选项，
它要求你写出来。**这道坎是这个功能最有价值的地方**：
它拦住的是「把一条还没想清楚的东西签上名，然后让它以卡片的身份被复习」。

### 3.2 转卡之后，教训**继续留在自己的队列上**

不删、不停排。理由：红线 7 的保证不能有任何「转卡就失效」的分支 ——
**一个能让红线失效的例外，比没有例外更糟。**
教训是那段经验本身；卡片是它被署名之后的样子。**两个都在，是对的。**

## 四、⭐⭐ 「转」这个字：一次事务，教训 + 调度项

`POST /reviews/{decision_id}/lesson` 在**一个事务**里：

1. 写 `lessons` 一行
2. 写 `lesson_schedule` 一行（**入队**）
3. 写 `lesson_reviews` 一行（`outcome = 'reviewed'`、`rating = NULL` ——
   刚入队时用户没有回忆任何东西，所以**没有评分**；沿用 `note_reviews` 的
   `reset` 那一行形状，理由相同）
4. 没有第四件事

⭐ **于是红线的强制手段是结构性的，不是流程性的。**
没有「记得调 `enroll`」这种代码路径，因为**没有这样的路径** ——
写教训的那几行里，排程那一句是无条件的、紧挨着的。
`lesson_schedule` 的 INSERT 失败 → 整个事务回滚 →
**不存在没有调度项的教训。**

对比今天：卡片是**用户手动**排程的，所以「每张卡都在队列上」从来没成立过。
红线 7 要的不是「多一个按钮」，是**让那句话从愿望变成不变量**。

⭐ 用**一个反向测试**钉住，比正向断言强：

> 造一个 BEFORE INSERT 触发器，**拒绝**往 `lesson_schedule` 里写 ——
> 然后记一条教训，**必须失败**，而且**不能留下任何教训行**。
>
> 正常的正向测试会问「排程在不在」，而这个测试问的是
> **「它不可能不在吗？」** —— 后者才是红线那句话的意思。

---

## 五、⭐ 自动入队与「手动入队」并存，差别是**有意义的**

- 手动写的卡片 / 手动入队的笔记：**你选择**它要不要回来找你。
- 一条教训：**已经回来过一次了**。

⭐ 因为一条教训的定义是「我因为某次决策吃过一次亏」——
**它已经被验证过一次**，所以它该回来，而且该**立刻到期**（`learning`）。
而你刚敲进去的一张卡片还没有任何理由回来。

这个差别不是技术限制，是产品判断，而且它必须**在代码里看得见**：
教训没有「入队」这个动作，只有「记下来」。

## 六、验收

| # | 项 |
|---|---|
| 1 | 能从一次复盘记下一条教训，生成 `lessons` + `lesson_schedule` + `lesson_reviews` 三行 |
| 2 | ⭐ **挡住 `lesson_schedule` 写入 ⇒ 记教训失败，且不留任何教训行**（原子性） |
| 3 | ⭐ **`lessons` 表一出现，`cards` 的两条出处 CHECK 一个字没动**（红线没被偷偷放松） |
| 4 | 刚入队的 `lesson_reviews` 行**没有评分**（用户没回忆过任何东西） |
| 5 | 教训**立刻到期**（`state = 'learning'`、`due_at` = 记下的那一刻） |
| 6 | 一次复盘可以记多条教训（一次吃亏能抽出好几条） |
| 7 | 复盘还不存在 / 没写完 ⇒ 不能记教训 |
| 8 | ⭐ 教训**没有 PATCH 动词**（不可变），改一条教训 = 写另一条 |
| 9 | ⭐ `lesson_reviews` **没有** `reset` outcome，且这被一个测试钉住（对照 `note_reviews` 有） |
| 10 | ⭐ 转卡**要求出处**；`lesson_promotions` 的两个 UNIQUE 让重复转卡不可能 |
| 11 | ⭐ 转卡后**教训继续留在队列上**（红线 7 没有失效分支） |
| 12 | 红线 7 的 coverage `partial` → **`full`**，verifier 指向一个**真跑**的测试 |
| 13 | 约束台账计数更新并写明增量 · 门禁 10/10 + 退出码 0 · 变异检查覆盖新代码 |
