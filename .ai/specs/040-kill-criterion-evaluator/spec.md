# spec 040 · 失效条件求值器 —— 让「到期」能变成「触发」

> 状态：**已完成**（2026-09-29）
> 起因：主人说「把功能好好看看，再加一些功能」。⭐ 找回来的不是 TSP 的选股，
> 而是 **`status.md` 自己列了两次、而我上一轮判成「不该做」的那个缺口**。

## 一、⭐ 先撤回我上一轮的一个判断

上一轮我把 TSP 的「监控中心」和「异动监控」一起归进 **不做**，理由是
「做了就不是 AlphaCouncil 了」。

⭐ **那个理由是错的，因为我当时没读功能清单。** `references/research/2026-09-29-tsp-capability-matrix.md`
是一份**数据层**矩阵（`Dataset` / 能力声明 / 路由 / 源可用性），**它从来没有走过
`docs/features.md` 的功能清单**。用一份数据层矩阵去否掉一整个功能面，是没有依据的。

而项目自己的 `status.md` 里有两行：

> **J3**… **还差**：复盘页的导航入口 · **主动触达**（受红线 8 约束，
> 形态应是今日页上的一行陈述而非通知，**需单独 spec**）
> **J5**… **还差**：变异检查本轮未跑；「转卡」的界面没有

⭐ **「主动触达」被项目自己记了两次，而我判它「不该做」。** 这一篇就是那个 spec。

## 二、⭐ 缺口长什么样

`/api/v1/today` 的全部逻辑（`routes/today.py:190-210`）：

```python
for row in decision_repository.list_all(connection):
    for criterion in row.kill_criteria:
        if criterion.due(as_of=today_date):      # ⭐ 只有日期
            attention.append(...)
```

**它只问「到期了吗」。从不问「越过阈值了吗」。**

而 `DueCriterionRead` **已经把 `metric` / `operator` / `threshold` 三个字段传到了前端** ——
前端拿得到用户写的判据，**只是没有值可以比**。

⭐ 今日页第 95 行因此印着一句话：

> 到期不等于触发：**系统还没有指标数据源**，能不能成立要你自己看一眼。

⭐ **这句话现在是假的。** spec 034 给了 HTTP 出口，spec 037 算了指标，
spec 038 把它画在页面上了。

而它之所以成为假话，是因为**它在为一个可以修的缺口找技术债当借口**。
真正缺的不是「指标数据源」，是「**一个把 metric 名字变成当前值的求值器**」。
⭐ 说错原因比不说更糟：读者会以为那是一件很大的事。

## 三、⭐ 决定：指标目录就是 spec 037 那套，不新造口径

`KillCriterion.metric` 是一个**自由 token**，只做形状校验
（`[a-z][a-z0-9_]*`），docstring 写得很清楚：

> **刻意是形状规则而不是封闭集**：指标目录属于财务数据层（D4），
> 而它没建；在这里编一份清单，意味着 D4 落地那天会拒绝一个有效指标。

⭐ **所以不许把 `metric` 改成 enum。** 那是把一条为未来留的门焊死。

求值器另有一份**更小的、能算的**目录。⭐ **入选门槛只有一条：**

> ⭐ **口径已经在别处被钉死，才进目录。** 没有钉死的不进 ——
> 因为求值器一旦开始回答「越过了吗」，它答的就是**用户的记录该不该继续**。

于是目录 = **spec 037 的指标集**（SMA/EMA/RMA/MACD/RSI/KDJ/布林/ATR/年化波动）
+ **Quote 模型已经定义的价格事实**（`close` / `open` / `high` / `low` / `volume` / `change_pct`）。

⭐ **零个新的口径分叉。** 5 日动量、20 日动量这类看着自然的东西**不进** ——
「5 根是 5 个交易日还是 5 个日历日」是一个真实的分叉，而它还没被任何地方钉死。
⭐ 这就是 spec 037 §2 那条规则的应用：**分叉处每一个都会改变数字。**

财务指标（`gross_margin` 之类）⭐ **一律 `unknown_metric`**，不是 `no_data`。
D4 落地那天它们会自己进来，本篇不预判任何一个。

## 四、⭐ 三个状态，而且其中两个是「我们不知道」

| 读者看到的 | 状态 | 含义 |
|---|---|---|
| 「MA20 跌破 1200 · 现在 1185.3」 | `ok` + 越过 | **去处理** |
| 「MA20 1200 · 现在 1205.0」 | `ok` + 未越过 | 到期，去看一眼（今天已有的行为） |
| 「这个指标还在预热段，20 根里只有 12 根」 | `warming` | ⭐ **不是「条件没成立」** |
| 「`gross_margin` 不在我们能算的指标里」 | `unknown_metric` | ⭐ **不是「条件没成立」** |
| 「这个代码没有日线」 | `no_bars` | 数据源不报它 |

⭐ **最后三行是本篇的全部价值。** 它们全都是「判据无法被回答」，
而今天它们**共用同一个沉默** —— 一条永远不会被求值的判据，
在页面上和「条件没成立」长得一模一样。

⭐ 而这正是宪法 §4.6 存在的原因：**「无法判断」降级成「看起来合理的默认值」是最危险的失败模式。**
一个从不触发的判据不是沉默，**它是在替用户说「你写下的条件没有成立」**。

## 五、⭐ 不加通知 —— 这是红线 8，不是我的选择

`status.md` 已经把形态定死了：「**今日页上的一行陈述而非通知**」。

⭐ 所以本篇**没有**推送、没有徽标、没有声音、没有弹窗、没有邮件。
一个越过阈值的判据只在默认页上多一行字。

这不是取舍，⭐ **这是红线 8**：「功能是『拦截』不是『推荐」，
禁止"机会推送 / 每日精选 / 异动提醒"类功能」。
而一个越过阈值的失效条件**正是「拦截」的定义本身** —— 它是用户自己写下的、
针对自己记录的条件，到点了就该拦住他。

## 六、红线逐条

| 红线 | 本篇 |

| 1 不做预测 | ✅ 不预测。是「用户写的阈值」与「市场产生的数」的比较 |
| 2 只做过程 | ✅ 判据是用户自己写下的过程陈述，不是评分 |
| 3 记录优先于分析 | ✅ 输入是**已存在的记录** |

| 6 未成熟留空 | ✅ `warming` 是一个状态，不是一个 0 |

## 七、明确不做

* ⭐ **财务指标求值** —— D4 没建，判据一律 `unknown_metric`，不猜
* ⭐ **通知/推送** —— 红线 8

* 盘后定时管道 —— ⭐ 全市场定时拉取正是招来封 IP 的做法（§4.5），本篇不碰
