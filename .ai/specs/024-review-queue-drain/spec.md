# Spec 024 · 复盘队列必须**排得空**

- **状态**：已完成（2026-09-28 · 回归 0007）
- **性质**：**缺陷修复**，不是新功能。缺陷记录见 `.ai/regressions/0007-reviewed-decision-stays-in-queue.md`
- **本 spec 存在的理由**：修法里含一个**设计决定**，缺陷记录只记现象

---

## 一、要决定的事

`due_reviews()` 该把什么算作「还欠着」？三条候选：

| | 含义 | 判断 |
|---|---|---|
| A | `due_at <= now` | ❌ **缺陷本身**。做完也不走 |
| B | **有 review 行** | ❌ 阴险。**半份复盘也有行** → 未完成的工作会离队 |
| C | **`reviewed_at IS NOT NULL` 的反面** | ✅ **完成章**才算完成 |

**选 C。** 理由是 spec 020 已经把语义定死了：
`reviewed_at` 是**只在写入结果分时**盖的章，含义是「复盘**已完成**」，
而**半份复盘是合法状态**。所以「已完成」这个问题只有一个正确的答案来源。

> **写错成 B 会怎样**：用户认真写下了过程分（那是他花的时间），
> 决策却因为「有行」而离开队列 —— **未完成的事被藏在他自己刚写下的那一行后面**。

---

## 二、⭐ 顺带暴露的限制：**一条决策只能复盘一次**

修好之后浮现的事实：`decision_review_state` **没有 reschedule**，`due_at` 永不改变。

所以「再进一次队列」**没有路径**。这是**限制，不是缺陷**——
当前数据模型就是"到期一次、复盘一次、结束"。

而要发明第二个间隔，就是**发明策略**：
和 spec 020 拒绝「买满 90 天」、spec 023 拒绝「三天未处理」**完全同一种判断**。

**想再看一次某条决策 = 记一条新决策**，或者把教训变成卡片走它自己的排程（J5）。
若将来要"第二次复盘"，需要**一个会移动的到期日**，并开一条 ADR。

---

## 三、验收

- [x] 复盘完成后离开队列（仓储层 + API 层各一条）
- [x] ⭐ **半份复盘仍在队列里**（最容易改错的一处）
- [x] ⭐ 离开队列 ≠ 丢记录（`reviews` append-only，ADR-0014）
- [x] 今日页 count 与队列页**对同一件事说法一致**
- [x] 变异 **3/3**（拿掉 / 写反 / 用 review 行代替完成章）
- [x] 门禁 **10/10 + 退出码 0**

---

## 四、明确不做

| 不做 | 为什么 |
|---|---|
| 第二次复盘的路径 | 需要**会移动的到期日** + ADR |
| 复盘历史视图 | `reviews_for()` 已就绪无调用方。**队列的定义是"还欠什么"**，但"读者看不到自己过去写过什么"是真缺口 → 独立 spec |
| 给 `due_at` 加 reschedule | 那是发明策略（§二） |
