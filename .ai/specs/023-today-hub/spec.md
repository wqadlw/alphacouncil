# Spec 023 · 今日页枢纽：让产品**来找**你（而不是你去找到它）

- **状态**：Active
- **目标阶段**：把红线 10 从 `partial` 推到 `full`（若诚实成立）
- **依赖**：spec 019（卡片复习队列）· spec 021（决策复盘队列）· spec 022（全局导航）
- **依据**：`项目总纲` §2.1 ⑤ · 宪法红线 8 / 9 / 10 / 11 · `today.py` 自己的 docstring

---

## 一、这一片存在的理由：产品仍然**不会主动来找你**

红线 10 现在是 `partial`，`gap` 只剩两点，本片处理第 ② 点：

> `项目总纲` §2.1 的原则是「第 ④⑤ 个时刻用户**不会主动来**，所以产品必须主动找他」——
> 而**至今没有任何地方提示「有 1 条决策到期该复盘了」**。

而 `today.py` 的 docstring **已经把话说尽了**：

> The today page's first block ("今天要问的") is **the one place the product is
> allowed to come and find the reader** … this endpoint is deliberately the
> *only* thing it can find so far: a written kill criterion whose cutoff date has
> arrived.

**它自己声明了自己是唯一被允许来找人的地方，然后只带了一个东西。** 本片就是补上
另外两个队列。

---

## 二、⭐ 核心设计问题：什么东西算"来找你"，什么算"推送"

红线 8 禁止「机会推送 / 每日精选 / 异动提醒」，红线 11 禁止促使用户动起来。
`项目总纲` ⑤ 明确允许「三天未处理 → **一句陈述，无推送、无红点、无催促词**」。

三条规矩**看起来打架**，所以必须把界线写死，否则下一个人会往任一边滑。

### ⭐ 界线：**关于「你自己已经承诺过的事」的事实** vs **关于「你可能想要的东西」的建议**

| | 允许 | 禁止 |
|---|---|---|
| 主语 | **你写下的那句话** | 产品 / 市场 |
| 性质 | **事实** | 建议 / 推荐 |
| 时机 | 到期那一刻 | 「今日精选」「异动」 |
| 形式 | 一行陈述 | 通知 / 红点 / 角标 / 徽章 |

所以：

- ✅ 「到期要看的：**2 条决策 · 3 张卡片**」—— 这是**用户自己写下的承诺到期了**，
  是关于**他**的事实，措辞里没有建议
- ❌ 「今天有 3 个机会」「你的持仓异动了」「值得关注」—— 主语是产品，
  是**关于市场**的判断，而那正是红线 8 禁的东西
- ❌ 角标 / 红点 / 「3」挂在旁边 —— 红线 11 的打卡计数（且导航**已经**因此被 E2E 钉住无数字）

> **一句话记住**：可以主动来找用户的，是**到期的东西**；不可以的，是**新的东西**。

### ⭐ 为什么不发明「三天」阈值

`项目总纲` ⑤ 写的是「**三天未处理** → 一句陈述」。但**三天这个判据没有定义**：
三天之后说什么、和两天时说什么有什么不同、逾期更久要不要说得更重 —— 全都没写。

**和 J3 的复盘到期日同一种情况**：020 拒绝发明「买满 90 天」，021 让用户自己写。
所以本片**只显示「已到期」**，不实现三天阈值，并**把这条记为未定义**。

理由不止是谨慎：**「逾期三天就说你」很容易滑向「逾期越久说得越重」，
而那就是一个催促机制** —— 红线 11。

## 三、后端：`GET /api/v1/today` 增加一个 `due` 块

**为什么加在今天页而不是前端拼**：默认页现在要发 3 个请求（today / watchlist /
quotes），再加两个队列就是 **5 个**。而"今天该看什么"本来就是后端拥有的概念 ——
交易日判定已经在这里了。多一个请求换五份真相，是坏交易。

### 数据契约

```json
"due": {
  "cards":     { "count": 3, "href": "#/review" },
  "reviews":   { "count": 2, "href": "#/retrospective" }
}
```

**只有 `count` 和 `href`。没有 due_at、没有标题、没有排名、没有"最急的那个"。**

- ⭐ **不给每一条的明细** —— 队列页才是明细的地方。今天页只回答
  「有几件到期的事」，不抢队列页的活
- ⭐ **`count` 不是分数**：不排序、不取前 N、不标"最急"
- `href` 放在后端是刻意的：**导航与路由表是前端唯一真源**（spec 022），
  后端复制一份就成了第二份真相。所以这里返回的是**逻辑名**，由前端映射到自己的表

⚠️ 既然不能复制 href，字段就该叫逻辑名而不是 href。**改：`{count, queue}`。**

## 四、前端：今天页加一条陈述 + 两个入口

形态（**不是卡片网格、不是待办清单、不是进度**）：

```
到期要看的：2 条决策 · 3 张卡片
```

- 一行，句号结束，**句子里没有感叹号、没有动词祈使**
- 两个都是链接，指向队列页
- **没有数字徽章、没有红点、没有"新"标签**
- `count` 为 0 时**整行不出现** —— 「0 条决策」也是一句关于你的话，
  而你不是每天都需要被告知"你没有欠自己任何事"

## 五、验收标准

- [ ] **AC-1** `GET /api/v1/today` 带 `due` 块；`count` 来自**同一批**到期数据
- [ ] **AC-2** ⭐ 队列名是**逻辑名**（`cards`/`reviews`），前端映射到自己的路由表
- [ ] **AC-3** ⭐ 今日页那一行**整页无数字**的断言仍然成立（今天的页本来就有日期，
      所以这条**只对新增的这一行**断言 —— 见下方诚实说明）
- [ ] **AC-4** ⭐ `count` 为 0 时整行不渲染
- [ ] **AC-5** ⭐ **不发明三天阈值**，并在代码与 spec 里把"三天"记为**判据未定义**
- [ ] **AC-6** ⭐ 红线 8 的禁用词：今日页不得出现 `机会` `精选` `异动` `值得关注` `推荐`
- [ ] **AC-7** ⭐ 红线 11：不得出现 `连续` `打卡` `完成率` `待办` `逾期`（催促词）
- [ ] **AC-8** 已有到期失效条件那一块**不回归**
- [ ] **AC-9** 门禁 **10/10 + 退出码 0**
- [ ] **AC-10** 变异：加回 0 计数行 / 加"待办"字样 / 去掉入口链接 → 各自变红
- [ ] **AC-11** 诚实：红线 10 按**实测**更新；若只是补了入口而没补"主动"，仍是 `partial`

### ⚠️ 关于 AC-3 的一处诚实

今天页**本来就有数字**（日期 `2026-09-28`、市场判定的最后交易日、
`revenue_yoy < 0` 这类失效条件）。所以"今日页整页无数字"**从来不是**它的性质，
也不应该是。**真正的不变式是：新增的 `due` 那一行本身不含数字以外的任何计数表达** ——
即它是**纯文字的一个句子**，数字只来自 count 本身，不是来自徽章、排名或进度。

我会把 AC-3 写成对**那一行**的断言，而不是假装整页无数字。

## 六、明确不做

| 不做 | 为什么 |
|---|---|
| **三天阈值** | 判据未定义，**不猜**（§二） |
| 逾期越久说得越重 | 那就是催促机制（红线 11） |
| 排序 / "最急的那个" / 前 N | `count` 不是分数 |
| 队列明细上今日页 | 队列页才是明细的地方 |
| 通知 / 红点 / 角标 / 徽章 | 红线 8 / 11；导航已因此被钉住 |
| 跨页缓存失效 | 队列页写完之后今日页要自动更新 —— **这才是真正需要失效总线的时刻**（spec 022 §四留的伏笔） |
| J5 教训转卡 | 独立 spec；那会把红线 7 从 `partial` 推上去 |
