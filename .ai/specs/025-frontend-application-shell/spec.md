## 二、⭐ 合并两份规范，但不是各打五十大板

主人选「两者合并成一份 AlphaCouncil 自己的规范」。执行时发现两份规范
**在四处是有意不同的**，所以**逐条裁定**，而不是折中：

| | AlphaCouncil | Industrial AI Clean | 裁定 |
|---|---|---|---|
| 圆角 | **> 4px 一律禁止**（§4.4：一圆就变成 SaaS 后台） | 8 / 12 / 16px | **采纳本项目** |
| 阴影 | **任何 `box-shadow` 禁止**（研报是印刷品） | `0 1px 2px` | **采纳本项目**，⌘K 遮罩**开一个例外**，且用**纸白半透**而非黑色 |
| 衬线 | **必须**用于标题与主张 | 全 Inter | **采纳本项目**，并定分工：**衬线=内容，无衬线=外壳** |
| 入场动画 | **禁止**（每次打开都等 = 像 Landing Page） | `fade-slide` 0.18s | **采纳本项目**：本产品**零入场动画** |
| 字号 | 11/12px 用于表头与元数据 | 正文 ≥ 13px | ⚠️ **两者都对，说的是不同东西** |

**字号那条是本 spec 唯一的真冲突**，判据是一句话：
> **要读成段落的字不得小于 13px；表格与标签可以小，因为它们不是段落。**
> 规则 6（信息密度优先）说的是后者。

**采纳姊妹项目的**：工程管道（`cn()` / `cva` / 组件清单 / `app/ components/ hooks/ lib/` 分层）
与**「一个 minimal set 就够，不要装重型库」这个判断** ——
它 §2 的"冻结技术栈"列了 TanStack Query / Zustand / RHF+Zod / Recharts / fontsource，
**而 `package.json` 里一个都没装，实际只用了 3 个小依赖**。
这份"规范是愿望、落地是刻意极简"的证据，直接决定了本项目的依赖预算（§3）。

## 三、依赖预算（宪法第三条 · 经主人批准）

```text
lucide-react · class-variance-authority · clsx · tailwind-merge
```

**明确不装**：shadcn/ui 全量（Radix）· TanStack Query / Router · Zustand ·
React Hook Form + Zod · Recharts · auto-animate / motion / GSAP · 图表库 · 自托管字体包。

⭐ **为什么这个预算够**：`前端资源与打磨规格` §4.1 坚持 shadcn/ui 的理由是
「**复制源码进仓库 + 没有运行时依赖**」—— 而 shadcn 的模式**就是**用
`cva` + `clsx` + `tailwind-merge` 手写组件。**手写，用同样三个工具，不引入 Radix。**

## 五、⭐ V-01~V-08 从散文变成会失败的测试

`docs/FRONTEND_STYLE_GUIDE.md` §10 的验收项，写成散文就只是意图，
而**意图不会让构建失败** —— 这正是 §1.2 那 12 个组件的下场。
所以 `frontend/src/styleguide.test.ts` 让每一项都必须跑过：

| 项 | 断言 | 状态 |
|---|---|---|
| V-01 | 无阴影（Tailwind `shadow-*` / CSS `box-shadow` / React `boxShadow`），且**全局禁令本身仍在** | ✅ |
| V-02 | 无 `rounded-full`、无 > 4px 圆角、无裸 `rounded` | ✅ |
| V-05 | `tabular-nums` 令牌在 | ✅ |
| V-06 | **零 `@keyframes`** + 零 `animate-*` | ✅ |
| V-07 | `package.json` 只有批准的依赖 | ✅ |
| — | **红涨绿跌未被换掉**（`--color-up` / `--color-down`） | ✅ |
| V-03 衬线只用于主张 | ❌ **不做成测试** | 见下 |
| V-08 空状态 | ❌ **不做成测试** | 见下 |

⭐ **V-03 / V-08 故意不测**：两者都需要知道"这段字**是什么**"，而 grep 不知道。
页面标题上的 `serif` 和读者原话上的 `serif` 在源码里是同一串字符。
**在这里断言它们只会产出一个什么都不证明的绿灯测试** —— 那比没有测试更糟，
因为它会被当作"规则成立"的证据引用。它们保留为人工评审项，规范里也是这么写的。

### 5.1 变异检查：**9 次全部被抓住，且抓出了 3 个真 bug**

一个从没失败过的 lint 不算 lint。逐条注入违规后：

| 注入 | 结果 |
|---|---|
| `rounded-lg` / `rounded-full` | ✅ 抓住 |
| `@keyframes` / `animate-pulse` | ✅ 抓住 |
| 换掉 `package.json` 加一个未批准依赖 | ✅ 抓住 |
| 把 `--color-up` 换成绿色 | ✅ 抓住 |
| **`shadow-md`** | ❌ **第一版漏了** → 补 |
| **`shadow-[0_1px_2px_…]`** | ❌ **第一版漏了** → 补 |
| **`style={{ boxShadow: … }}`** | ❌ **第一版漏了**（正则大小写敏感，`boxShadow` 里有大写 S） → 补 |

三个漏洞都指向同一件事：**这个代码库里没人会手写 CSS，阴影会从 Tailwind 类名进来**，
而全局 `* { box-shadow: none }` 会把它**藏起来** —— 类名留在那儿看起来有意义，
改一行 CSS 就开始生效。**只有变异检查能发现这类漏洞**，因为它们在代码评审里完全正常。

另有 2 个**假阳性**也记在这里，因为它们的教训比漏洞本身更通用：

- **三处失败全是"规则在描述自己"**：`globals.css` 里的 `box-shadow: none`（禁令本身）、
  `index.tsx` 注释里的 `` `rounded-lg` ``（解释为什么禁止它）。
  → 扫描必须**先去注释**。不做的后果很具体：维护者会**为了让它变绿而删掉解释规则的注释**。
- **一条断言失败、消息却是空的**：`box-shadow\s*:\s*(?!none\b)` 里的 `\s*`
  会**回溯到零宽**，让负向前瞻站在空格上、判定通过。→ 用 `(?=\S)` 钉住。
  **"失败信息为空"是这条 bug 的唯一症状。**

## 六、⭐ 三个当场被 E2E 抓到的设计错误

`nav.spec.ts` / `routing.spec.ts` / `today.spec.ts` / `today-hub.spec.ts` 共 **5 处失败**，
**全部是真回归**，不是测试过时：

| # | 我写的 | 抓到什么 | 修正 |
|---|---|---|---|
| 1 | `UnknownRoute` 里自己写了一个 `<h1>这个地址看不懂</h1>` | `titleFor('unknown')` 已经由外壳标题渲染同一个句子 → **屏幕上出现两遍**，Playwright 严格模式直接判失败（**2 个测试同时红**） | 删掉重复的标题。**命名页面是外壳的职责** |
| 2 | 把「你写的失效条件「…」」和「去核实数据」拆成同一行两段 | ① 严格模式下 `去核实数据` 匹配到 2 个元素；② **更要紧的是丢掉了语义** ——「观察期已到 —— 去核实数据」是**一个从句**，拆成"状态 + 链接"读起来弱得多，而**弱的那个读法会让读者以为条件已经被裁定过了** | 恢复成整句 |
| 3 | 删掉了 `今天没有到期的失效条件。你写下的每个条件都会在它该被看的那天出现在这里。` | 这句的后半段是**空页面不是数据丢了**的唯一保证，删掉它等于让空态读起来像故障 | 恢复 |
| 4 | 页面级 `今天 · 2026-09-28 · 周一` 被"外壳已经说了今天"这个理由删掉 | 日期是今天页与静态列表的**唯一区别**。忽略日期的测试，会在一个悄悄丢掉日期的页面上通过 | 日期进**外壳标题**，且是**同一个句子**（拆成标题+副标题会打印两次"今天"） |

⭐ 第 4 条是这批里最有价值的一条：**测试用 `getByText('今天 ·')` 当"页面渲染了"的代理，
而这个代理恰好抓到了真东西。** 如果当初图省事把断言改成 `getByRole('heading')`，
日期就会悄悄消失，而这个测试仍然会绿。

## 七、⚠️ 过程偏差（如实记录）

**本 spec 写于实现之后。** 001~024 全部是 spec 先行。

- **为什么**：主人这句话是**方向性的判断**（"做成程序那样"），不是一个可拆的功能请求。
  我先做了一轮**本地调查**（找到两份规范），而调查结论**直接改变了要写什么** ——
  在知道"规范已存在且写了 12 个组件"之前写出来的 spec，会是另一份东西。
- **代价（如实承担）**：中途返工两次（`InputProps` 的 `size` 与 HTML 属性冲突；
  `AppShellFrame` 里把 `useEffect` 写成 `useMemo`），以及 §6 的 4 个返工。
  **其中 §6 那 4 个本可以被 spec 提前挡掉** —— 因为它们都是"我改了既有页面的措辞"，
  而 spec 先行时"既有措辞是被 E2E 钉着的"这一点会被写在任务清单里。
- **不做的事**：不把这份 spec 改写成"本来就是 spec 先行"。**台账的价值在于它记录真实发生的事。**

### 7.1 ⭐ 还有一个缺陷，**十道门禁全绿也发现不了**

`.gitignore` 的 `data/` 没有前导斜杠，**在任意深度都匹配**，
于是 `frontend/src/components/data/` 连同 `DataTable.tsx` 一起被静默排除。
`git add -A` 报成功，`git status` 看起来干净 —— **那个文件根本没进暂存区**。

**门禁 10/10 全绿，因为门禁跑的是工作区，而工作区里那个文件好好地在那儿。**
这个缺陷只在"将要提交什么"这个视角下存在；clone 该提交的人会得到一个**编译不过**的前端。

修法与仓库已有先例一致（`.ai/checks/data/` 早就需要 `!` 反选）。
可复用的检查写在变更日志 §4.2：**磁盘上的源文件 vs `git ls-files`，逐个比对**。
本轮实测 `31 / 31` 全部入库。

⭐ 这条与 §5.1 那三个阴影漏洞是同一类问题的两个面：
**一个"看起来对"的东西（`.gitignore` 规则 / `shadow-md` 类名）只有在
"换一个视角去看它"的时候才现形。** 换一个视角就是本轮反复用到的手段 ——
变异注入、`git status --ignored`、门禁退出码。
