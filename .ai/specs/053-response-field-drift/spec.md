# 053 · 响应字段漂移：让「服务器发的」与「客户端声明的」在编译期对账

## 背景与目标

**一个已经发生、并且今天仍然活着的缺陷。**

2026-10-04，本会话给 `DailySeriesRead` 加了 5 个字段
（`backend/src/alphacouncil/api/routes/instruments.py:396-425`），它们在网络上真实出现
（`:533-548`），而 `frontend/src/api.ts:1037-1045` 的 `DailySeries` 仍然只有
`bars` 与 `indicators`。⭐ **17 道静态检查、1432 条后端测试、137 条 e2e，全绿。**

为什么全绿，因为**没有一道检查看得见这件事**：

| 检查 | 为什么看不见 |
|---|---|
| **S-16** `no-enum-drift` | 只读 `enum` 数组（`no_enum_drift.py:250,253` 实测）⇒ **五个 `date\|None`/`bool` 字段在结构上不可达** |
| **S-17** `no-route-drift` | 只比 `(动词, 路径)`（`no_route_drift.py:378-382`）⇒ 字段漂移不在范围 |
| `tsc` | `api.ts:486` 是 `return (await response.json()) as T` ⭐ **无检查的断言** ⇒ 服务端多一个字段不是类型错误 |
| vitest / e2e | 没有任何 fixture 断言日线响应的形状 |

⭐⭐ **这不是「漏了一条检查」，而是整个仓库 17 道检查的方向是一致的：全部在比「枚举值」与「(动词, 路径)」，
⇒ 字段这一层从来没有人对过账。**

### 目标

让**服务器发布的每一个响应字段**都必须在客户端有一个具名类型声明它，⭐ 并且这条对账要能在
`make check` 里把上面那 5 个字段变红。

## 用户故事

作为**读这份代码的人**，我希望服务器发的字段与客户端声明的字段在提交时就对不上，⭐
以至于我不能靠「门禁全绿」推断「客户端知道服务器会发什么」。

作为**主人**，我希望页面读到的字段确实存在，⭐ 因为我看到 `TodayPage.tsx:91` 读
`today.data?.due`、`:309,312` 读 `due.reviews.count`，⭐ 而这一切的编译期保证来自一个
`as T` 断言。

## 新机制必须先回答的三问（宪法 2.2）

| 问 | 答 |
|---|---|
| ① 它守的是哪个**具体**失败 | 本会话那 5 个字段；`Quote` 的 `adj_factor`/`fetched_at`/`source`；`capabilities` 三兄弟客户端完全没有 |
| ② 为什么既有机制**不能**做 | S-16 的判据是「枚举值集合相等」，字段不是枚举；S-17 的判据是「(动词, 路径)」；`tsc` 被 `as T` 短路 |
| ③ 必须还是可选 | **必须**。宪法第十二条：「某段代码不该存在」这类缺陷测试永远抓不住，⭐ 而「客户端漏声明服务端会发的字段」正是这一类 |

## 功能需求

### FR-1 一条新检查 `S-18 no-response-drift`

- 输入：`openapi.json` 的 `components.schemas`（⚠️ **不提交快照** —— pydantic 自动生成，
  后端侧永不漂移，⭐ 见 `## 关键取舍`）＋ `frontend/src` 下所有 `.ts`/`.tsx` 的具名对象类型。
- 判据：**子集**。schema 的属性集合 ⊆ 某个客户端具名类型的顶层字段集合 ⇒ 通过。
  ⭐ **只报这一个方向。**
- ⭐⭐ **子集而不是相等，理由不是宽松，是义务方向**：客户端类型存在的目的，是让编译器能校验
  「对到达的数据的读取」，⭐ 那是一个**单向**义务。多声明的字段是**反向**缺陷，
  `no_enum_drift.py:44-48` 已经给它取好了名字：「客户端在等一个永远不会到达的值，
  ⭐ **而那个分支是看起来正确的死代码**」。

### FR-2 三个桶，每个桶的阈值都必须有实测依据

| 桶 | 条件 | 依据 |
|---|---|---|
| **error** | schema 属性数 ≥ `DISCRIMINATION_FLOOR` 且无任何客户端类型是超集 | ⭐ 阈值由探针量出（见附录），不是猜的 |
| **note** | schema 属性数 < 阈值 | ⭐ 3 字段的 `Symbol` 被 3 个无关类型满足 ⇒ **小 schema 没有判别力，静默放过等于谎称覆盖** |
| **note** | 一个客户端类型满足 >1 个 schema | ⭐ 对应关系有歧义，必须说出来 |

⭐ 第三条沿用 S-17 已有的三桶形状（drift / orphan / ok），⭐ **包括「orphan 只能是 INFO 而不能翻红」
这个已被本仓接受的决定**（`2026-10-02-plan.md:129-135`：
「不把 S-16 做成发现新枚举就报红 —— 那会在后端加枚举时逼人改前端，⭐ **而后端加枚举常常是应该的**」）。

### FR-3 一条新错误码 `CHECK_RESPONSE_DRIFT`

`S-05` 守着「错误码必须同时登记在 `.ai/error-codes.md`」⭐ —— 所以这一步不做，`S-05` 自己会红。

### FR-4 文档同步

`.ai/checks/static/README.md` §3 加一行（S-12 双向比对 id 与 slug，⭐ 不加就红）。

## 非功能需求

- **性能**：一次 `TestClient` 构造 + 一次 `frontend/src` 遍历。S-16 已经付过这个钱，⭐ 本条复用同样的构造方式。
- **可观测性**：每个 finding 的 `fix` 字段必须指出**具体该改哪个文件**，⭐ 而不是「同步一下」。
- **安全**：不引入任何运行时依赖（宪法 3.2.1）。⭐ 用 `re` + 手写平衡括号，⭐ 与 S-16/S-17 同一量级的手写解析。
- **零红落地**：门禁必须在**修完漂移之后**才允许进 `main`。⭐ `2026-10-02-plan.md:101-103` 的次序。

## 明确不做（Out of Scope）

- **不做 OpenAPI codegen。** `openapi-typescript`（8.4k star，MIT）要加依赖，
  ⭐ 且 `.ai/logs/changes/2026-10-02-plan.md:129` 已把它否掉（`V-07`）。
- **不做 Pact / 契约测试。** `2026-10-02-plan.md:17-20` 已否：单仓单人项目上契约文件会变成第三个要同步的地方。
- **不做提交 `openapi.json` 快照。** ⭐ pydantic 保证它与后端一致，快照只会引入一个新的陈旧源。

  字面量，⭐ 而 1 字段的 schema 会被任意含该字段的类型满足 ⇒ **判别力为零，报出来只是噪声**。
- **不碰 `decisions.thesis_id`。** J2 仍未获主人点头。
- **不动 `today.py:234-237` 那个产品决定**（关注池与复习队列「故意不在这条端点里」）⭐ —— 那是产品决定，不是漂移。

| 情况 | 应如何 |
|---|---|
| 应用构造不出来（语法错） | **skip 而非静默通过** —— 与 S-16/S-17 同一处理，⭐ 因为「跳过的门禁不是通过的门禁」（`dev.py:288-292`） |
| `frontend/src` 不存在 | 同上 |

## 已知的失败（宪法第十二条形态① · 对应 AC）

- ⚠️ **本规则看不见嵌套 schema。** 实测：`DueRead` 在 `Today.due` 里、`DueCriterionRead` 在
  `AttentionItem.item` 里，⭐ 而顶层比较看不见它们。⇒ 它们会被报成 error，⭐
  **除非给它们一份带理由的豁免。** 这是一个真实的、已知的、写在纸上的漏洞，⭐
  不是「以后再说」。
- ⚠️ **本规则看不见请求体**（见 Out of Scope，理由已量出）。
- ⚠️ **本规则只比字段名，不比类型。** `volume: float` 变成 `volume: string` 它不会红。
  ⭐ 这是 oasdiff 那种工具能查而本仓查不了的，⭐ 记在这里而不是假装覆盖。
- ⚠️ **手写 TS 解析器会被重排击败。** `no_enum_drift.py:194-196` 自己写着
  「a rule that can be defeated by reformatting is not a rule」⭐ —— 而本规则继承同一个赌注。
  ⇒ **AC-5 就是为这个赌注设的**：换行、缩进、注释都必须不影响结果。

## 附录 · 四次探针的实测数字（不是估计）

| 探针 | 结论 | 是否作数 |
|---|---|---|
| 1 | 65 个 schema / 71 个客户端类型 / 26 个「无精确匹配」 | ⭐ **作废**（解析器有 bug） |
| 2 | 逐个打印线 vs 客户端，发现 `Today` 缺 `due` | ⭐ **这个反例促成了 3 号探针** |
| 3 | 子集规则：15 个不满足、154 个多余字段 | ⭐ **作废**（同上） |
| 4 | 修正后：61 个考虑、46 个满足、**15 个不满足**、11 个歧义、191 个多余 | ✅ **本规格引用的数字** |

⭐⭐ **探针 3 报 `Today` 缺 `due`，而 `TodayPage.tsx:91` 正在读它 ⇒ 客户端没问题，是我的解析器错了。**
解析器的错是精确的：`due: {` **这一行既声明成员又开启嵌套**，⭐ 而当时的判据是「本行括号净值 > 0 就跳过」。
修法是**累计深度**而不是逐行净值，⭐ 并且顺带发现第二个 bug：成员正则接受了 `(`，⭐ 于是方法名被当成线上的字段。

⭐ **四次探针、三次作废，值得单独记一条失败模式。**
