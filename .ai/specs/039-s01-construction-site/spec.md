# spec 039 · S-01 的形状：目录白名单改成模块白名单

> 状态：**已完成**（只做决定与收窄，**不做 webhook 通道本身**）
> 日期：2026-09-29
> 前置：`spec 033` §2 留下的三选一 · **决定**：`ADR-0031`

## 一、要解决什么

`spec 033` 要抄 TSP 的 webhook 通道，撞在 S-01 上，**并且卡在那里三个月**：

> 不在 `providers/` 里 `import httpx` 就是 error，
> 而官方修复建议是「走 provider 层 —— `alphacouncil.providers.default_router()`」

⭐ **那条建议对 webhook 是错的**，而本篇要回答的不是「怎么绕过去」，
是「**为什么一条 P0 规则给了一个在本代码库里已经错了的建议**」。

## 二、⭐ 那条建议为什么错

`default_router()` 是**行情**路由：按 `Dataset` 声明能力、按 `BatchSemantics`
处理批量失败、三源互备、带磁盘缓存。

把一条飞书消息塞进去，意味着要给它发明一个 `Dataset` 成员 ——
⭐ 而加 `Dataset` 成员会打破两个断言**精确集合**的既有测试。
那两条测试变红不是障碍，是**它在告诉你这个抽象不接受这个东西**。

## 三、⭐ 规则真正想守的，逐条都是关于数据源

宪法 §7.8 给了理由：「限流**必须是一个函数**，不能是"请大家记得加 sleep"」。
§4.5 把它说全了：三源互备、东财连续请求触发限流、
**「限流」与「封 IP」是两件事**、**同一域名的不同子域风控面不同**。

⭐ 所以 §7.8 那一串机制（串行化 / 最小间隔 / 抖动 / 会话复用 / **默认 UA** / 熔断 / **缓存**）
**逐条都是数据源出口的关切**。而 S-01 的实现判的是**目录**：

```python
return relative.parts[:1] == Path("providers").parts
```

**意图**是「客户端只在被认可的地方被构造」，**实现**是「在一个目录里」。
⭐ 而这两个命题之间的缝，就是通知通道待的地方。

## 四、决定

**白名单从「`providers/` 这个目录」改成「`core/http.py` 这一个模块」**，
新增 `alphacouncil/core/http.py` 作为全项目唯一允许构造客户端的地方。

```
providers/sources.py   ──build_client(user_agent=_MARKET_DATA_UA)──▶  core/http.py
notify/webhook.py      ──build_client(user_agent=_WEBHOOK_UA)──────▶  core/http.py
```

`core/http.py` 只拥有**真的通用**的三样：超时、`follow_redirects`、连接复用，
⭐ 外加**要求调用方显式给出 `User-Agent`**。

## 五、⭐ 这是改紧，而且数字可数

| | 允许构造客户端的**文件集合** |
|---|---|
| 改前 | `providers/` 下**每一个** `.py`（今天 4 个，将来更多） |
| 改后 | **1 个**（`core/http.py`） |

`sources.py` 自己构造客户端这件事，**改后不再被允许** —— 它必须调工厂。
⭐ 口子是缩小到原来的一个文件，不是扩大到第二个目录。

而这个数字**现在是一条测试**（`test_the_construction_site_is_a_single_named_file`），
⭐ 因为不写成测试，它就会在某一次「顺手加个文件」里悄悄变回 4 个。

## 六、⭐ 一份 UA 不能两边共用，所以「一个入口」不是「一个 client」

`spec 033 §2` 要求把 `User-Agent: TickFlow-Webhook/1.0` 重新冠名 ——
⭐ **webhook 不该冒充浏览器**，而腾讯/新浪**必须**冒充（它们拒绝陌生 UA）。

把两者塞进一个带默认 UA 的工厂，等于让其中一个撒谎。
所以共享的是**「客户端在哪里被构造」这条规则**，不是**一个构造好的 client**。

⭐ 这也是为什么 `build_client` 的 `user_agent` 是**必填**：
**带默认值的那个默认值，迟早会在某一侧变成一句谎话。**

## 七、⭐ 两种权限被混成了一种，这是收紧时才暴露的

改完立刻报了一个**看起来像误报**的错：`providers/sources.py` 仍然 `import httpx`
（它要用 `httpx.HTTPError`、要标注 `httpx.Response`），而它不是构造点。

⭐ 这暴露了规则把**两种不同的权限**当成了一种：

| 权限 | 谁能做 | 名单 |
|---|---|---|
| **构造**客户端 | 只有构造点 | `CONSTRUCTION_SITES`（1 个文件） |
| **命名** `httpx`（为了类型与异常） | http-aware 模块 | `HTTP_AWARE_MODULES`（+`sources.py`） |

旧规则只能用目录同时表达两件事，于是选了**权限更大的那个**去满足。

⭐ **而这次能安全地放宽 import 名单，恰恰是因为收紧先做了**：
规则 3（构造）现在**无条件**在所有文件上生效，规则 2（`httpx.get`）也是。
所以「允许命名 `httpx`」不再带来任何构造能力。

⚠️ **顺序反过来就是一个洞。** 先放宽 import、之后再收紧构造 ——
那中间任何一刻，`providers/` 都能自己造客户端。这条写进了规则的 docstring。

## 八、⭐ 变异 7 个，第一个就存活了

| # | 变异 | 结果 |
|---|---|---|
| 1 | 构造点加回 `providers/sources.py` | killed |
| 2 | **删掉构造检查里的「对的文件」条件** | **SURVIVED** |
| 3 | 构造检查整个不触发 | killed |
| 4 | import 白名单变成整个产品 | killed |
| 5 | `HTTP_AWARE_MODULES` 塌缩成构造点 | killed |
| 6 | 工厂名清单去掉 `build_client` | killed |
| 7 | `CONVENIENCE_CALLS` 不再拦 | killed |

⭐ **存活的那一条是本次最有价值的产出。**

规则 3 有**两个**条件：对的文件 **且** 对的函数名。
而我原来的 fixture 把函数叫 `fetch` —— **两个条件同时被破坏**，
所以无论文件条件在不在，测试都红。**它测不出这两个条件是分开的。**

删掉文件条件后测试照绿 —— ⭐ **「这条测试通过」不等于「这个条件被测过」。**

补的 fixture：**函数名叫 `_client`（合法的工厂名），文件是 `providers/sources.py`（不是构造点）**。
只破坏一个条件。重跑 **7/7 全杀**。

⇒ `F-115`

## 九、⭐ 顺带修掉规则建议文案里的一个错

规则 1 的 fix 文案原来只说「走 provider 层」。那是**给想要行情的人**的正确建议，
和**给不想要行情的人**的错误建议 ——
⭐ **一条建议在本代码库的一个真实场景里是错的，下一个读者就会开始打折看整条规则。**

改成两个选项并列：`build_client(...)`（要发 HTTP）/
`default_router()`（要行情）。
