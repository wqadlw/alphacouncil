# spec 038 · 指标上屏

> 状态：**已完成**
> 日期：2026-09-29
> 前置：`spec 037`（指标纯函数）

## 一、要解决什么

`spec 037` 把指标算出来了，34 条测试守着，**但一个数字也没有出现在界面上**。
数据在库里，函数在 Python 里，图上是 214 根光秃秃的 K 线。

于是本篇只做一件事：⭐ **把已经算好的东西画出来，并且不引入第二份算法。**

## 二、⭐ 决定：指标必须服务端算

前端当然可以写一个 `sma()`。那样会得到第二个实现，而它和 Python 那份

* 从第一根起就可能不同（预热段、播种方式），
* 直到有人改了一边才暴露，
* 暴露的时候没有测试会红，因为两边都「对」。

⭐ `spec 037` 把六个口径分叉逐条钉死，就是为了**只有一处**能改。
再加一份 TypeScript 等于把那份文档变成两份互相矛盾的文档。

所以 `DailyResult.value` 从 `DailyBar[]` 变成：

```ts
{ bars: DailyBar[]; indicators: { name; label; values: (number|null)[] }[] }
```

⭐ **`values` 与 `bars` 等长且同序**，预热段是 `null` 而不是「跳过」。
少一格就得让前端去猜某个值属于哪一根 —— ⭐ 而**每一次这样的猜测都是一个可能错一格的地方，
错一格的线在图上看不出来，只在有人拿已知值核对时才发现。**

## 三、4.2.0 没有分 pane，所以 MACD 是第二张图

实测 `lightweight-charts@4.2.0` 的 typings：

| 符号 | 出现次数 |
|---|---|
| `paneIndex` | **0** |
| `addPane` | **0** |
| `addSeries` | **0**（那是 v5） |
| `addLineSeries` | 6 |

多窗格是 v5 才有的。两条捷径都不可接受：

* 把 MACD 叠在价格轴上 —— ±8 的数值画在 300 的价格里是一条平线。
* 给它一根覆盖价格轴 —— 读者会把第二个数字当成第二个价格。

⭐ 所以 MACD 面板是**独立的第二个 chart 实例**，两张图用
`subscribeVisibleLogicalRangeChange` 互相喂 `setVisibleLogicalRange`。

这不是装饰。⭐ **蜡烛从第 0 根开始，而 `dif`/`dea`/`histogram` 在预热段是 `null`，
所以两张图默认的可视区间根本不一样** —— 面板会晚 33 根打开，
两张图会对「光标底下是哪一天」各说各话。首屏复制主图区间就是为这件事。

守卫标志不是可选项：`setVisibleLogicalRange` 会重新触发对方的 handler。

## 四、⭐ 图例只列画出来的东西

第一版有 `SERIES_COLOR` 表 + 两份并行的 id 数组 + 一个 `?? FALLBACK`。

错在这里：**名字不在两个数组里的指标，会被从图上丢掉，却仍然出现在图例里**，
因为图例渲染的是 `indicators` 而不是「画了的那些」。
⭐ 结果是图上有一条写着「RSI」的图例项，而底下没有线 ——
**一条图上不支持的断言，而它每一部分单看都是真的，所以活得下来。**

`FALLBACK` 从来不是答案；`FALLBACK` 只是在掩盖「丢弃是个必须告诉人的决定」。

改法：

* 一张表 `PLACED`，颜色和窗格住在一起 —— 加指标就是加一行，忘记窗格不再可表达。
* 丢掉的一律进 `unplaced`，**页面上写出来**：「服务端算了 5 条，本页只画 5 条；
  未画的是 …」。沉默不在选项里。

## 五、⭐ 颜色必须四个都能分开

浏览器里渲染出来才看见的：**MA20 和 DIF 同为藏青，EMA12 和 DEA 同为黄铜**。
图例一行四个标签只有两种颜色。⭐ 读者没法靠颜色区分两条线 ——
**读者读图例是横着读的。**

指标面板这一对刻意**不占用红绿**：那两色在这个项目里意味着涨和跌，
花在震荡指标上会让页面在意思是「正」的地方说「涨」。

## 七、⭐ 顺手修掉一个真缺陷：DEA 有两个定义

浏览器实测数非空值时发现的 —— ⭐ **34 条测试全绿的时候**：

```
dif  warmup=25
dea  warmup=25   ← 文档说该是 25 + 8 = 33
```

`macd()` 的文档写着「DEA 继承 `ema` 的播种，所以在 MACD 自己的预热之上再多
`signal - 1` 个 `None`」。而代码是一个手写的循环，**用第一个值播种**，
`ema` 用的是**前 period 个值的 SMA**。

⭐ 于是同一份文件里有**两个 EMA 定义，且逐根不同**，文档描述的是第三个。
这是「一个教训只有一个家」在最难看的地方破掉：同一个文件里，
两个定义看起来都局部、都合理。

改法就一句 —— `dea` 变成对 `ema` 的**调用**：

```python
mature = [value for value in dif if value is not None]
pad: list[Indicator] = [None] * (len(dif) - len(mature))
dea: list[Indicator] = pad + ema(mature, signal)
```

⭐ 教训不是「加一行测试」。是：**文档里写下一个数字，就是一个有人得去核对的断言，
而核对它最便宜的方式是把它断言出来。** 所以 `dea` 现在在预热参数表里，值 33。

终值不变（DIF -15.94 / DEA -11.78 / 柱 -4.16，与 `spec 037` 记录一致），
因为 182 根的 EMA9 把种子洗掉了。⭐ **变的只是头部几根 —— 而头部几根正是图上
「线从哪里开始」的那几根。**
