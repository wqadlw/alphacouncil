# spec 032 —— S-14：让「每个源文件都被 git 跟踪」成为门禁，而不是一次手写检查

> 状态：**已实现** · 2026-09-29
> 相关：spec 027（检索，那次手写过等价检查）· spec 031（本轮先做的 npm 许可门禁）
> 归属：**护栏线** —— 把已经存在的能力变成不可绕过的检查

---

## 一、手写检查和门禁的差别，是它会不会被跳过

`.ai/status.md` 记着 **S-14**「每个源文件都被 git 跟踪」。spec 027 那轮我手写过一次等价检查，
跑完发现「198 个文件全被跟踪」，记成完成。

⭐ **但那是一次执行，不是一条规则。** 它没有 `CHECK_*` 代码、没有优先级、
没有「META 与实现必须一致」的测试、没有豁免机制、也没有在文档清单里占一行。
下一次谁都能不跑它 —— 而**没人会注意到没人跑它**，因为没跑和跑了输出一样干净。

⭐ 这和 spec 031 是同一句话的两个应用：**门禁的价值在于它不能被跳过，
而不能被跳过不是靠自觉，是靠它在清单上占一行、缺了就红。**

## 二、⭐ 真正要防的缺陷有两个，不是一个

第一个显而易见：**新写的文件没 `git add`**，本地一切正常，克隆出来就没了。

第二个危险得多，而且**用 `git status` 看不见**：

> `.gitignore` 里一条写得太宽的规则，会把源文件**藏起来**。

spec 025 §7.1 已经记录过这个坑：本仓库的 `.gitignore` 里 `data/` **没有前导斜杠**，
所以它不只匹配根目录的 `data/`，**也匹配任何层级的 `data/`** —— 包括
`backend/src/alphacouncil/**/data/`。那种情况下文件是「未跟踪且被忽略」，
而 `git status` 默认**不显示**被忽略的文件。

⭐ 所以只查「未跟踪」是不够的：那恰恰是最需要被看见的那种。
本篇用两个信号，和 spec 031 的 production 闭包同一形状 —— **各有一半看不见**：

| 信号 | 命令 | 判定 | 为什么 |
|---|---|---|---|
| 未跟踪且**未**被忽略 | `git ls-files --others --exclude-standard` | ⭐ **error** | 明确的缺陷 |
| 未跟踪但**被**忽略 | `git ls-files --others` | ⭐ **warn** | 忽略规则可能太宽 |
| 已跟踪 | `git ls-files` | 静默 | 正常 |

**被忽略的源文件是 warn 而不是 error**：`.venv`、`node_modules`、`__pycache__`、`dist`、
`*.db` 都被忽略且都是对的。

> ⚠️ **下面这句话我写错过，被现实否掉了。** 原文是：*「规则只走 `backend/`
> （跳过 `_SKIP_DIRS`）与 `frontend/src` / `frontend/e2e`，所以一条 warn 出现在这里，
> 只可能意味着某条 ignore 规则盖住了源码。」*
>
> **它是假的。** 规则第一次跑真实仓库就报了
> `warning CHECK_IGNORED_SOURCE  backend/.pytest_cache/README.md` ——
> ⭐ **工具缓存就在被扫的树里面**，而且好几个都带一个 `README.md`。
>
> 教训不是「warn 该改成 error」，而是：**「圈定了范围，所以只可能」这种推理，
> 必须由范围本身来兑现，而范围里住着什么不由我说了算。**
> 修在根上 —— `SKIP_DIRS` 里加上缓存目录，而不是调严重度。
> 而且 `SKIP_DIRS` 原来叫 `_SKIP_DIRS`（私有名），两个模块要用它时**提升为公开**，
> 而不是复制一份：⭐ 复制就会漂移，而漂移之后 warn 会为一种没人写下来的理由响起。

## 三、不是 git 仓库时要说「跳过」，不能报通过

`CheckResult.skipped` 的文档写着：*a check with nothing to scan must say so rather than
report a clean bill of health*。

⭐ 一个 tarball 里没有 `.git`，或者 CI 上还没 checkout 完 —— 此时报「0 个问题」就是撒谎。
所以 git 不可用、非仓库、或输出无法解析时，一律 `skipped` 并写明原因。

## 四、验收

1. 造一个真 git 仓库，故意不 `git add` 一个 `.py` → **error**
2. 同一仓库，`.gitignore` 写 `data/`（无前导斜杠），里面放一个 `.py` → **warn**
3. 全部 `git add` → 静默
4. `tmp_path` 里没有 `.git` → `skipped`，**不是** 0 issue
5. S-12 双向校验通过（`MODULE_BY_ID` ↔ README §3 都要有 S-14）
6. S-05 通过（两个新 `CHECK_*` 都要登记进 `.ai/error-codes.md`）
7. 变异检查

## 五、明确不做

- **不做**检查文件内容有没有被提交过（那要跑 git 历史，慢且与本规则无关）
- **不做**把「被忽略的源文件」升成 error —— 会有合法例外，而一个会误报的护栏会被关掉
  （spec 031 §2.2 同一个理由）
- **不做**扫 `.ai/**` —— 那些是文档，`git add -A` 早就覆盖，且不在源文件定义里
