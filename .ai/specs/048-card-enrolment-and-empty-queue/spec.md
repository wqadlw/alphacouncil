## 一、量出来的，不是想到的

### 1.1 一个新用户打开看到什么

对着**一个空数据库**（`ALPHACOUNCIL_DATABASE_PATH` 指到临时目录、8010 端口）
把十三个列表端点挨个打了一遍，**全部返回 `[]`**，`/today` 的 `attention` 为空、
两个计数都是 0。

然后在浏览器里把五个页面挨个截了图，量每页的正文长度：

| 页面 | 正文字数 | 空态说的是什么 |
|---|---|---|
| 今日 | 360 | ✅ 「关注池是空的 — 到关注池加一个，并写下你为什么关注它」+ ③④ 区说明了各自缺什么 |
| 关注池 | 267 | ✅ 「关注池是空的。你还没有关注任何标的」+ **表单就在上面** |
| **复习** | **62** | ⚠️ 「今天没有到期的卡片 / **还没加入复习的卡片不会出现在这里**」 |
| **复盘** | **74** | ⚠️ 「现在没有到期的复盘 / 记决策的时候写下「什么时候回来看看」」 |
| 知识库 | 178 | ✅ 「这里还没有笔记。点下面的「记一条」」 |

⇒ **「五个空页面」这句话不准确。** 今日 / 关注池 / 知识库的零态是**合格**的：
它们说了现在是什么、为什么、以及下一步在哪。**复习和复盘不合格** ——
它们说的都是**为什么队列是空的**，而对一个新用户来说，队列空的原因是
**上游根本没有东西可排**。

⚠️ 而这还不是最要紧的一半。

### 1.2 ⭐ 更要紧的一半：复习队列**结构性地进不去**

`status.md` K3 挂着「还差：标的页卡片的『加入复习 / 下次复习 N 天后』」。
挂着的缺口和真实存在的缺口长得一模一样（`regressions/0005`），所以对着机器量：

```
1. POST /api/v1/cards                 -> 201 card_1790916668533
2. GET  /api/v1/review/due            -> 0 条     （服务端不主动贡献任何东西）
3. POST /api/v1/cards/{id}/schedule   -> 201 {"state":"learning","due_at":"…"}
4. GET  /api/v1/review/due            -> 1 条
5. grep scheduleCard                  -> api.ts:282 定义，调用者 0 个
```

**⇒ 卡片只能靠写代码进复习队列。界面里没有任何地方能进去。**
这个复习页**对每一个用户都是空的**，与新用户无关。

⭐ **而笔记不是这样。** `VaultPage` 里有 `enrollNote`，配一段有理由的注释
（显式入队，因为「把读者写过的每样东西都入队会攒下一份没人清的欠账」），
**外加 `readNoteSchedule` 三态判断**。**同一个后端形状，卡片这边只有一半。**

这与本仓修过三次的形状完全相同：`J3` 的「机制齐了却够不着」、
零调用者的 `listNoteReviews`、`RecordTimeline` 的两个实现。

### 1.3 而缺的不止是按钮

`POST /cards/{id}/schedule` 存在，**`GET` 不存在**。⇒ **界面无法知道一张卡片在不在队列里。**

⚠️ 而且**不能从 `/review/due` 推断** —— 那个端点只给**到期**的，
一张排在下周三的卡片不在里面。**所以「加入复习」这个按钮如果只能靠点完才知道结果，
它就是一个赌注。**

⇒ 后端缺一条读路由。**但仓储层已经全有了**：
`scheduling.get_schedule(connection, card_id) -> ScheduleRow` 与
`CardNotScheduledError` 都已存在（实测确认）。**这个 spec 的后端改动是一条路由。**

## 二、设计

### 2.1 三态，不是一个布尔

界面必须能区分三件事，而笔记那边的实现把后两件合成了一件：

| 状态 | 界面说什么 | 为什么不是布尔 |
|---|---|---|
| **不知道** | 「复习状态取不到。」 | 后端没起来时显示「加入复习」，点了会失败 —— **那是一个骗人的按钮** |
| **未入队** | 「加入复习」 | |
| **已入队** | 「已入队 · 下次 10-09」 | |

⚠️ **笔记那边现在是 `.catch(() => false)` —— 任何失败都读成「未入队」。**
那是同一个形状的潜在缺陷（后端停了就显示「加入复习」）。**本 spec 不改笔记那条**
（那是另一处改动），但**卡片这边必须按 `error.code === 'CARD_NOT_SCHEDULED'` 判断**，
而不是「抛了异常就算未入队」。

### 2.2 `GET /cards/{id}/schedule` 答 409，不答 404 —— 而且理由不是我的

⚠️ **笔记的 `GET /notes/{id}/schedule` 未入队时答 404。卡片这边我本来要照抄，
然后去读了 `api/errors.py`，发现项目已经决定过了：**

```python
# K3. Both are 409 rather than 404 on purpose: the *card* exists, and what
# conflicts is the request with the card's scheduling state. Answering 404
# would tell the user their card is gone when it is sitting right there.
ErrorCode.CARD_NOT_SCHEDULED.value: 409,
```

⇒ **照抄笔记会推翻一条已经写明理由的决定。** 用 409。
⇒ **而这也让前端能区分**：「这张卡片不在队列里」（409，正常的空）
与「这张卡片不存在」（404，是另一个问题）。**三态因此也是后端给的。**

### 2.3 入队是显式的，且按钮不默认存在

沿用笔记那条已经想清楚的理由：**把读者写过的每样东西都入队，攒下的是一份没人清的欠账。**

⇒ 所以**不给「全部加入」**。每张卡片一个按钮，点了就是一次决定。
⚠️ **并且红色线 7**：教训是强制入队的（它不能有「转了卡就不用了」这种分支），
**卡片不是** —— 卡片是读者署名的东西，入队是他自己的决定。

### 2.4 空队列文案：加一句「它们从哪来」

复习页现在说的是「还没加入复习的卡片不会出现在这里」——
**这句话在卡片能入队之后才成立**，而它**一直是对的，只是没有对应的动作**。

⇒ 加一句它从哪来，并且**指向那个动作**：

> 这里现在没有到期要复习的卡片。**队列来自你自己写下的卡片 —— 在知识库或标的页上
> 点「加入复习」，它就会自己回来。** 没加入的不会出现在这里。

⚠️ **不加「你还没有卡片」。** 页面**不知道**你有没有卡片
（`/review/due` 为空时两种情况无法区分），**而一个会说错话的句子比没有更坏**。
「队列来自你自己写下的卡片」**两种情况下都是真的**。

复盘页同理加一句它从哪来。⚠️ 同样**不区分**「没有决策」与「没有到期」。

## 四、明确不做

- **不改笔记那边的 `enrolled` 两态。** 那是同一个形状的另一个实例，
  但改它属于 spec 028 的地盘；⚠️ **已记为欠账**。
- **不给「全部加入复习」。** §2.3。
- **不给队列加数字。** 队列显示的是「回来了的」，加计数会把它变成一张待办清单
  （`spec 028` 已经为此拒绝过显示标题）。
- **不改教训的强制入队。** 红线 7，与卡片相反，且这个不对称**是**理由。

⚠️ **我又猜了一次字段名**：卡片创建的字段是 `content` 不是 `claim`，
拿到 422 —— 与 `regressions/0008`（假设主键叫 `id`）同一个错误、同一种被抓住的方式。
⇒ 修正后的探针**先读 `CardCreateRequest` 的字段再发请求**。
这已经是本会话第三次猜字段（`TradingDayVerdict`、`?q=`、`claim`），
**「读模型再发请求」应当是探针的第一条规矩，而不是被坑三次之后才补的。**
