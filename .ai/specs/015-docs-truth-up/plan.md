# Plan 015 · 文档与残留清理

> ⚠️ **本文件对审查者隐藏**（`agent-guide.md` §一）。

## 一、最容易做错的地方

**把"更正"写成"重写"。** 本项目的先例是 `regressions/0003`：
> 「同时修正了 `api/deps.py` 那段把危险来源说反的注释 —— **保留原文并追加更正**，
> 而不是删掉重写，因为"曾经把风险说反了"这件事本身值得留在文件里。」

所以：
- `ARCHITECTURE.md` 顶部要**保留"上一版写了什么、为什么被移除"**，不是抹掉；
- `HANDOFF.md` 要**保留失效的原话**并逐条列出错在哪，不是悄悄改对。

理由：一份从不说自己错过的文档，读者无法判断它哪些话可信。

## 二、AC-1 / AC-2 怎么验

写完不能靠"读起来对"。要**回仓库里逐条指认**：

| 断言 | 指认到 |
|---|---|
| 分层图 | `backend/src/alphacouncil/` 的实际目录 |
| `checks/` `scripts/` 在图外 | 它们不在 `src/` 里 |
| 三个依赖零 import | 逐个搜 `^\s*(import\|from)\s+<name>\b` |
| 测试总数 | 跑一次 pytest 取真数，**不写"约"** |
| 迁移 0001–0004 | `storage/migrations/` 实际文件 |
| trigger 对 | `constraints.json` + 迁移 SQL |

**特别提醒**：`ARCHITECTURE.md` 里任何一个数字都必须来自一次实际运行。
写"528"而不去跑，就是把上一个缺陷换个地方重犯。

## 三、`status.md` 改动的顺序

先改**事实**（traces 三处），再改**评价**（make check 退出码），
最后加**新登记**（§五 5 条）。倒过来做会中途读到自相矛盾的版本。
