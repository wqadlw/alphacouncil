- **状态**：Done

  - `pyproject.toml` 第 46–51 行的依赖删除说明（"Do not re-add without an ADR"）
  - 约束①「写进简历」—— 简历上写的东西必须经得起点开

## 一、背景：三类"文档在骗人"

接手核查时发现三处**文档与代码不符**，严重程度递减，但性质相同：
**一个从不核实的断言，被后来的读者当成了事实。**

### 1.1 `docs/ARCHITECTURE.md` 描述的技术栈已被宪法全部移除（P1）

它通篇描述 LangGraph、Qdrant、LightRAG、RRF 融合、cross-encoder rerank、
四路召回，以及 `retrieval/` `agents/` `graph/` 三个层（13 处命中）。

而这些**在 2026-09-26 就被宪法 v2.0 明令移除**：

> v1.0 → v2.0 变更说明 第 2 条：技术栈含 LlamaIndex / Qdrant / LightRAG / AKShare / Next.js
> → **全部移除**。"v1 把'智能检索层'当产品卖点，**已被纠正**。我们做决策记录，不做检索框架。"

实际代码里这三个层**一个都不存在**，`pyproject.toml` 里甚至有一段专门的
"⚠️ Removed on 2026-09-26, deliberately"注释，逐个列出被移除的包。

> **为什么这条最严重**：一份"缺失"的文档只是没用；一份**自信地写错了**的架构文档，
> 会让每一个新接手的人（和每一个面试官）建立一个完全错误的认知。
> 它比没有文档更贵。

### 1.2 `status.md` 违反了它自己定的规则（P2）

该文件写着「**只改代码不改这里，视为未完成**」，但它自己写着：

- §一 S0 行：「还差：`.ai/traces/` 写入器（目前只有说明文件）」
- §三：「`.ai/traces/` ❌ **未实现**」
- §四 验收①：「❌ 三项全未达成 —— 还差：trace 写入器」

而 spec 011 早已落地，`core/trace.py`（8090 B）与 `tests/unit/test_trace.py`（10220 B）
都在仓库里，HANDOFF 第三节也列了它。**这个文件是本次唯一被判定"违反自己规则"的文档。**

顺带修掉一处**方向相反**的错误：§三「`make check` ✅ 已全绿 · **退出码 0**」——
那句话只在 UTF-8 环境成立（回归 0004）。不是"太乐观"，是"在错误的机器上测的"。

### 1.3 `HANDOFF.md` 落后一个提交，且有陈述已失效（P2）

- 「下一步 1：K1 知识卡片建表 + 界面」→ **已完成**（spec 012/013）
- 「Node 22.22.2 不在 PATH，需手动 export」→ **已在 PATH**（v24.21.0）
- 「下一个编号 **012**」→ 已是 014

三个都是同一类错误：**照抄上一份文档，没有回到代码里核实。**

### 1.4 残留：一个未跟踪的草稿文件（P2）

`backend/_fsrs_probe.py` —— 前任为 K3 做的 FSRS 探针，忘删。
`print` 触发 ruff `T201` → **lint 门禁红**。是接手时 `dev.py check` 唯一失败项。
