# Spec 004 · 关注池行情（把 D3 接到 D1）

- **状态**：Active
- **目标阶段**：S1（status.md §一 S1 行还差项「行情与关注池之间还没有连接」）
- **依赖**：D1 关注池（已完成，`watchlist_current` 视图）· D3 行情（已完成，`MarketDataRouter`）
- **ADR 依据**：ADR-0017（`(market, code)` 复合主键）· 记录与报价分离原则（`api/routes/instruments.py` 模块注释，既有约定）

---

## 背景与目标

P0 验收句是「每天打开能看到动态」。当前关注池页只显示**你写了什么**（代码 / 理由 / 时间），不显示**标的现在什么样**（价格 / 涨跌）。数据层的两半都存在，但没有一根管子把它们接起来 —— 这是 S1 收尾的最后一块。

**本 spec 只做连接，不做新数据能力**：不新增数据源、不新增缓存、不新增字段。所有行情语义（四态 / 熔断 / 降级）已由 D3 的路由器拥有，这里只是调用它。

## 用户故事

- 打开关注池页，能看到每只关注中标的的**最新价与涨跌幅**（红涨绿跌 + 符号双编码）。
- 某只票取不到行情时，那一行**显式说明**是哪种取不到（无报价 / 取数失败 / 无法确认），其余行照常显示。
- 页面**不自动刷新**；想看新价，自己点「刷新行情」。

## 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | `GET /api/v1/watchlist/quotes`：对**当前关注中**的每个标的取实时快照，返回列表。定价范围 = `watchlist_current` 视图 —— 与 `GET /watchlist` 列出的**同一批行**，两个端点不许对"谁在池子里"各持一份理解 |
| FR-2 | 每个标的的结果是**自己的**四态 `DataResult[RealtimeQuote]`。**绝不合并成批次级状态**：批次的真话是「7 只 ok · 2 只无报价 · 1 只失败」，任何单一状态都是对其中至少一只的谎报 |
| FR-3 | 每行以 `(market, code)` 复合键标识（ADR-0017）—— 裸 code 不唯一（`000001`） |
| FR-4 | 空池 → `200` + `[]`（没有要定价的东西，不是错误） |
| FR-5 | 已移出的标的**不定价**（"当前关注中"是本端点语义的一半，另一半在 FR-1） |
| FR-6 | 逐只**顺序**调用路由器，每只恰好一次。理由见「已知的失败」#4 |
| FR-7 | 前端：行情是**独立于列表的第二个请求**；行情失败**绝不**弄瞎关注池列表（只显示一行说明） |
| FR-8 | 前端：四种状态各有紧凑的行内文案；完整句子（原因 / 错误码 / 数据时间）在标的页，不复制到行内 |
| FR-9 | 前端：**无自动刷新**（红线 11）；提供手动「刷新行情」按钮 |

## 验收标准

| 编号 | 标准 |
|---|---|
| AC-1 | 空池返回 `[]`，且路由器**一次都没被问** |
| AC-2 | 两只关注中标的 → 两行，各自 `(market, code, display, quote)`，`ok` 行带价格 |
| AC-3 | ok + no_data + error 三只并存 → 三行各自保有自己的状态与原因/错误码，HTTP 200（连坐语义：一只坏不连坐整批） |
| AC-4 | 加入又移出的标的不出现在结果里，路由器也没被问过它 |
| AC-5 | `stale=true` 原样透传（值 + 标记），前端显示「旧」标记 |
| AC-6 | 行内四态映射是**纯函数**并有测试（每态一条 + 未加载态 + stale） |
| AC-7 | 后端 ruff / mypy / pytest 全绿；前端 typecheck / lint / vitest / build 全绿；12 条静态检查 0 error |
| AC-8 | 变异检查 ≥ 3 条，记录在变更日志（改坏哪里 → 哪个测试红） |

## 已知的失败（本 spec 防的事故）

| # | 事故 | 防线 |
|---|---|---|
| 1 | 一只标的取数失败 → 整批报错 / 整页空白 | FR-2（每行自己的四态）+ AC-3 |
| 2 | 已移出的标的仍在被定价（对"池子"的两份理解开始漂移） | FR-1（唯一数据源 = 同一个视图）+ AC-4 |
| 3 | 旧的缓存价被当成今天的现价展示 | AC-5（stale 透传 + 「旧」标记；D3 已保证快照不命中缓存） |
| 4 | 批量并发轰炸数据源（N 只票 = N 个并发上游请求）—— 东财限流已实测过一次 | FR-6 顺序遍历；将来路由器长出自己的限流（7.8 唯一入口的串行化仍是待办），这里不需要跟着改 |
| 5 | 行情接口挂了 → 关注池列表一起消失 | FR-7（两个请求，各自失败各自说） |
| 6 | 自动刷新把「记录页」变成「盯盘终端」 | FR-9（红线 11；标的页同款先例：只有一个按钮） |

## 边界（本 spec 不做）

- **不合并** `GET /watchlist` 与本端点 —— 记录（本地、不会失败）与报价（网络、经常失败）分开 travel 是既有约定，合并会让数据源故障扣住用户自己写的话。
- 不做磁盘缓存、不做交易日探针、不做限流串行化（各自是 S1 独立还差项，各有 spec）。
- 不在行内显示完整四态句子（那是标的页的职责，`QuoteBody` 已有）。
- 不做涨跌排序 / 涨幅榜（红线 8、9：不制造"成绩单"）。
