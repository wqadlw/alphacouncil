# 新增依赖申请：`lightweight-charts`

> 依据 `.ai/constitution.md` §3.2（四点要求）与 §3.2.1（人工确认后方可加入）。
> ⭐ **状态：等待主人确认。** 在确认之前，`frontend-test` 的 V-07 会保持失败 —— 那是门禁在
> 正确工作，不是一个待修的故障。

---

## 一、为什么现有依赖做不到

| 已批准的运行时包 | 它是什么 | 为什么不能画 K 线 |
|---|---|---|
| `react` / `react-dom` | 渲染器 | 不画任何东西 |
| `lucide-react` | 图标（ISC） | ⭐ 图标不是图 |
| `cva` / `clsx` / `tailwind-merge` | 类名拼接 | ⭐ 就是 shadcn/ui 的全部运行时，纯样式管道 |
| `@milkdown/*` | Markdown 编辑器（MIT） | 编辑器不是图表 |

⭐ **现有依赖里没有任何一条通向屏幕上的蜡烛。** 这就是这一页长期停在
「一行文字数字」的原因：不是没取到数据，是**没有获批的方式把它画出来**。

## 二、替代方案对比

| 方案 | 许可 | 为什么不选 |
|---|---|---|
| `echarts`（TSP 通用图表用它） | Apache-2.0 | ⭐ 为一件蜡烛图引入一个全功能图表框架 |
| `recharts` | MIT | ⭐ **宪法 §3.2.1 明确未批准**；且它并不轻 |
| `chart.js` | MIT | 比 echarts 小，但蜡烛图要插件，交互要自己搭 |
| ⭐ `lightweight-charts` | **Apache-2.0** | ⭐ 专为此而生（TradingView 出品），拖拽/缩放/十字线吸附都是现成的 |

## 三、维护活跃度证据

* 版本 **4.2.0**，在活跃的 4.x 线上（2026-09-29 实测安装）
* 它同时是**自己文档的参考实现** —— 文档与代码同源
* ⭐ **实测并读取了它的类型定义**，而不是凭记忆写 API：4.2.0 有 `addCandlestickSeries`，
  而 v5 的 `addSeries` / `CandlestickSeries` 在其类型定义中**出现 0 次**
  （凭记忆写会得到一个「类型检查什么都不检查、也画不出东西」的组件）

## 四、⭐ 它给 exe 增加的体积：**实测（2026-09-29）**

⭐ 方法不是「装上量一次」，而是**两次真实构建相减**。两次都试图用「移除包」取基线，
两次都失败，且两次失败都说明了问题：

1. `npm run build`（= `tsc -b && vite build`）—— **类型检查先失败**，因为导入缺失模块的组件
   根本不能编译。⭐ 这不是测量出错，**这是依赖预算在正常工作**。
2. 单跑 `vite build` —— 在 import 分析阶段同样失败。

所以基线只能这样取：**保持 import 图有效，只把库从图里换掉**。做法是一个**同形状的本地
空实现** —— 组件的导出、hook、调用点全部保留，只把背后那 40 kB 的库去掉。

| | 产物 JS 原始体积 |
|---|---|
| 含 `lightweight-charts` | **512,641 bytes** |
| 同形状本地空实现 | **355,131 bytes** |
| ⭐ **库本身的贡献** | **157,510 bytes**（153.8 kB） |

⚠️ **原始体积会误导，所以两个口径都记**：

| 口径 | 数字 | 它回答什么问题 |
|---|---|---|
| 原始 | **+157,510 bytes**（基线 355,131 → 512,641） | 它在**产物文件里**有多大 |
| gzip | **约 45 kB**（按构建自报的 30% 压缩比折算） | 它在**下载与 exe 体积**里有多大 |

⭐ 作者说的「a few kB」指的是 minify 后的核心；上面两个数字**各自都是真的，只是在说不同的事**。
⭐ 只记原始值会让这个决定看起来比实际贵得多；只记 gzip 值会藏起它在产物里有多大。

⚠️ **量的是什么、不是什么**：量的是**这个库对产物的贡献**（§3.2 第 4 点问的就是这个）。
**不是**「如果去掉 K 线功能能省多少」—— 那还要去掉组件、hook 与前端客户端，
是一个大得多的问题，而且本 spec 不问它。

## 五、如果批准，需要改两处（不是一处）

1. `.ai/constitution.md` §3.2.1 表格加一行，并把「图表库」从未批准清单里**移出**
2. `frontend/src/styleguide.test.ts` 的 `approved` 集合加一项

⭐ **两处必须一起改**：只改测试不改宪法，那一行批准就没有出处；
而 §3.2.1 的原话是「批准这件事必须留在宪法里，只写在变更日志里，
等于把『这些包为什么合适』变成一个需要考古的问题」。
