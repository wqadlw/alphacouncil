### A5 的执行：⭐ 「L1 该落在哪」的判据不是「哪里有 hover」

全仓 14 个 `hover:` 里 **11 个是裸 `hover:underline`**。所以第一个判断是：

⭐ **`data-[motion='l1']` 只过渡 `background-color` / `border-color` / `color` —— 对这 11 处链接，它一点用都没有。**
下划线是 `text-decoration`，而 **`text-decoration` 不可动画；可动画的是 `text-decoration-color`**。
⇒ 于是 `l1` 补了第四个属性，`text-decoration-color 100ms`。⭐ **这是 A5 唯一的实质改动**，
而且它是「先量出形状」而不是「先把类铺满」的结果：铺满 14 处而不动 `l1`，等于给每处加了一个
看起来在起作用、实际什么都不做的类 —— `F-123` 的形状。

⭐ 落位分两种，这是关键区分：

| | 落点 | 理由 |
|---|---|---|
| ✅ **加 L1** | `EmptyState` 的动作 · `App` 的兜底链接 · `TodayPage` 的到期队列与段落标题 · `CardSection` 的**出处链接** · `VaultPage` 的关闭键 · `RetrospectivePage` 的标的链接 · `DataTable` / `TodayPage` / `AppShellFrame` 早已有 | 独立可 hover 的元素 |
| ⛔ **不加** | `TodayPage` 与 `PoolPage` 里表格单元格内的链接 | ⭐ **`transition` 是继承的** —— 父 `<tr>` 已有 L1，子元素的 `text-decoration-color` 一并覆盖。⭐ 加上去是同一个类写 11 遍换一个效果：**行才是被 hover 的东西，所以动效归行** |

⭐ 出处链接那条还有第二层理由：**它是全仓唯一会离开本产品的链接**，而它的缺席会悄悄把一条
「有出处的判断」变成「无出处的断言」。规则 5 说这种标记该是 2px 左规或边框，而行内的出处
拿不到这两样 —— ⭐ 所以 `hover:underline` + 淡入是此处唯一合规的妥协。

⭐ **`lucide-react@1.48.0` 实测**：

- `sideEffects: false` ⭐ ⇒ barrel 具名导入可摇树
- `dist/esm/icons/` 有 **4236** 个 `<kebab>.mjs` 单文件模块
- `dist/lucide-react.d.ts` 是类型入口（**`package.json` 没有 `types` 字段**，也没有 `exports` 映射）

### 9.1 已量到的包体成本（B 阶段落地后）

⭐ **五个图标的真实代价，且量得出来了一个意外的结论：**

| | 未包量 | 包量 |
|---|---|---|
| **JS 体积** | 514.79 kB | **519.49 kB**（+4.70） |
| **gzip** | 158.03 kB | **160.09 kB**（+2.06） |
| **transforms** | **57 modules** | **1926 modules**（+1869） |

⭐ **最重要的是最后一行：五个图标把 1869 个模块拖进了构建图。**

⭐ 而 gzip 只涨 2 kB。两个数字放在一起读才有意义：

1. ⭐ **摇树**（多采用的那条路）**是有效的** —— 否则应当是几百 kB。区别在于 `sideEffects: false` 已声明，且注册表里是**五个具名导入**。

⭐ 这也是为什么 V-11 把死项当不可配帢写在第一位：每多一个注册项都是一次全量的
barrel 扫描。“先注册看需不需要”在包体上不是免费的。

⚠信息（未验证）：**本项目前面本地运行**，1869 个模块在 Vite dev server 下的真实启动时间未测。
测的是**生产构建的输出体积与 gzip**，而非 dev 的冷启动时间。

⇒ **D 的下一步应该从这份 survey 出发，由主人定哪几项值得做，而不是从组件名清单出发。**

### ⭐ 这一步照出的失败模式（F-158 … F-164 七条）

- ⭐ **`F-161`：缺陷藏在「看起来正确」的解释后面。** 「面板在 DOM 最后所以向前 Tab 天然安全」
  —— **看着对、关于原因是错的**（面板被 portal 了，前五步是浏览器自己的顺序）。
  ⇒ **一个藏对了地方的缺陷才是贵的那个**，所以 Tab 要按**比行数更多**的次数按，两个方向都按。
- ⭐ **`F-164`：陷阱挂在 `window` 上是「差点写对」的形状。** 它会修好向后、留下向前
  —— `keydown` 在被处理的元素上**冒泡不到**后注册的 document 监听器。
  ⇒ ⭐ **最该做的那个变异体，是冲着「我差点写的那版」去的。**
- ⭐ **`F-163`：差点做一次「读起来必要」的 refactor**（把面板搬到 `App` 里当兄弟节点）——
  ⭐ `createPortal(node, document.body)` **已经**是 `#root` 的兄弟了，那次移动什么都不会改变。
  ⇒ **portal 落在哪由参数决定，不由它写在哪决定。**
- ⭐ **`F-158`：变异体抓出我规则的洞** —— `/…document\.body/` 匹配了
  `document.body.firstElementChild`。⭐ **一个不断言值在哪里停下的模式，会接受每个以同样
  方式开头的更长值。** ⇒ 而这条规律我是**两个方向都错过**：先太宽（`F-148`/`F-153`），
  这里太松。**方向的差别不重要，重要的是第一次跑没有告诉我。**
- ⭐ **`F-159` / `F-160`：变异检查自己出三个问题**（12 个变异体首次只有 9 个算数）——
  2 个被 **`tsc -b` 拦下**（不是被测试杀掉，报告却写成 `BUILD FAILED`）；1 个是
  **`stdio: 'ignore'` 让一次成功的构建返回 status 2**，于是五个变异体全被报成构建失败。
  ⇒ **变异体必须类型干净** · **探针必须和门禁同一种方式调工具链**（门禁 `npm.cmd`，
  探针调 `npm` → `npm.ps1` → 被执行策略拦）· ⭐ **`shell:true` 下 `cmd.exe` 不把 stderr
  传进管道**，必须打 `error.message`，否则探针把自己的失败归档到错误的原因名下。

⭐ **L2 过渡与 `<dialog>` 的冲突**：`showModal()` 直接切 `display`，没有过渡。⇒ 用
`@starting-style`（纯 CSS、**不需要 `@keyframes`**，因此不撞 V-06），而不是给 `display` 做动画。

⭐ **焦点回退的具体规则**（APG 原文，容易做错）：回到**触发元素**；若触发元素已不存在，
退到一个「提供合理工作流」的元素；⭐ **明确排除 `document.body` 与页首**。

⭐ **D1 的浮层不许有阴影**（V-01 直接抓）。层级用 **1px `--rule` 边框 + 不透明 `--surface` 底**表达，
这是 §3.2 的做法（⌘K 遮罩同理）。

## 阶段 D 之后（2026-09-30）

阶段 A/B/C 之后的五轮。⭐ 它们不是「补完阶段 D」，⭐ 是**从实测缺口里长出来的**，
⭐ 而其中两轮推翻的判词比它们本身更重要。

### D2 · 知识库的基本功能

⭐ 「基本功能」被量成了三个具体缺口，而不是一份愿望清单：

| 缺口 | 怎么量出来的 |
|---|---|
| 记下的笔记**不能改** | `PATCH /notes/{id}` 与 `notes.ts::updateNote` 存在、有测试、**零调用方** |
| 引用的笔记**不能撤回** | `POST /notes/{id}/links` 存在 ⭐ 而 `DELETE` 路由**根本不存在** |
| 正文是源码不是正文 | 四处把 Markdown 原文当文本插进 JSX |

⭐ 加上「`listNoteReviews` 有接口、有测试、零调用方」⭐ —— **这是本产品的第四次**
（`backlinks_for`、整个 Markdown 渲染器、现在的复习流水）⭐
**「后端有测试、界面无调用方」的能力看起来和「已完成」一模一样**。
找出它的方法不是测试，⭐ 是**数一遍每个导出函数有几个调用方**。

### D3 · Markdown 渲染

自写 `Markdown.tsx`，**不加 `marked`** ⭐ —— V-07 的批准清单里没有它。
三个理由记在模块里：零 HTML（返回 React 节点、从不拼字符串 ⭐ 所以零 XSS 面）、
纯函数（⭐ 所以在这个**无 jsdom** 的仓里可单测 —— 37 条，本仓第一个不靠 DOM 的逻辑测试）、
输出直接用本产品字号类。

⭐ **不支持 GFM 表格**：仓里已有 FTS5（所以是知识库不是文本文件）
⭐ 与带 0.5px 细线 + `tabular-nums` 的 `DataTable` ⭐ —— 表格两个都不沾。

### D4 · 复习流水

⭐ 阶段 C 明确**拒绝过**这个适配器，理由「复习流水的文案以读者为先」。
**那个理由当时是对的** ⭐ —— 它约束的是**复习界面**的按钮文案，
⭐ 不是**历史记录**的描述。⭐ 历史是「发生过什么」，不是「你做得好不好」。
⭐ 两句不同的句子，而当时我把它们当成了一句。

### D5 · 两个缺陷（不是功能）

⭐ **`.mark` 的层叠缺陷**（`F-170`）⭐ 与 ⭐ **S-15 `no-mojibake`** ⭐
⭐ —— 后者的起因是发现 `BacklinkList.tsx` 的 JSDoc **提交时就有 3 个 U+FFFD**。
⭐ 也就是说，下面「全局约定」里那条**「写中文件的自我扫描 U+FFFD」**
⭐ **在这一整个 spec 里被遵守着，而它该拦下的东西就在仓里。**
⭐ 一条被遵守的习惯拦不住一次写入路径的故障 ⭐ —— 所以它变成了门禁。

⭐ **D5b 顺带修的两处**（门禁自己抓到的，不是 review 抓到的）：

* ⭐ `test_fourteen_rules_in_order` 断言的**连续区间**与 `registry.py` 的
