# 057 · 演示库：让「五个空页面」变成一个能用的产品

> 宪法 2.2 的三问在 §〇。**这不是一个新功能，是把一个被自己标为「最大缺口」的东西补上** ——
> `status.md` T0 行原文：「⭐ **零首次体验** —— 没有 seed、没有 demo、没有 onboarding
> …… **这是产品当前最大的缺口，不是这一节在替它开脱。**」

## 〇 · 想做什么

**目标**：`dev.py demo` —— 一份**独立路径**的演示库，让任何人在**不碰主人真库一个字节**的前提下，
打开一个**五页都有内容**的产品。

**具体故障（实测 2026-10-05）**：主人真实库
`instruments 2 · watchlist_events 8 · decisions 5 · **cards 0 · notes 0 · reviews 0 · lessons 0**`。

⇒ **知识层是空的。** 而知识层是这个产品与整个交易日志品类的分界线（外部调研：
英文品类全部 P&L 优先、按构造违反我们的红线）。⇒ 复习队列、笔记召回、
教训队列**每天打开都是空的**，而它们**空不是因为坏了，是因为从来没有东西可以被复习**。

⭐ **而这改变了上一轮的建议顺序。** 我原本要先做「让它默认会来找你」——
**在没有任何东西可通知之前，那是在给一个没内容的产品优化送达率。**

**既有机制为何不行**

| 机制 | 为何不行 |
|---|---|
| README 的「种子数据」 | ⭐ **仓库里没有。** 实测 `grep seed|demo` 在 `backend/` 下只命中测试夹具与 EMA 的"种子" ⇒ 那些截图的种子是**一次性脚本，没留**（`F-140`）⇒ **截图无法从仓库复现** |
| `ALPHACOUNCIL_DATABASE_PATH` | 环境变量**已存在**且测试在用 ⇒ ⭐ 这条路是通的，**缺的只是「谁来填它」** |
| 预填示例数据进真库 | ⭐ **红线 3/13/15 + `agent-guide.md`「不替用户写决策记录」共同排除**，而 `status.md` 自己已经写明：**可做的是独立路径的演示库** |

**必需还是可选**：**必需。** 约束②「主人自己日常会用」在 `status.md` 里写「❌ 全未达成」，
⭐ **而实际情况比那更具体：不是没验证，是从没被用过。**

## 二 · 设计决策

### 2.1 ⭐ 三层「不可能被误认」，因为一层不够

**风险**：演示库长得和真库一样 ⇒ 有人拿它当自己的记录，或者把它的截图当成产品的真实样子。

| 层 | 做法 | 为什么这一层不够单独用 |
|---|---|---|
| 1 | **独立子目录** `%LOCALAPPDATA%\AlphaCouncil\demo\` | ⚠️ 文件名能改 ⇒ 不是保证 |
| 2 | ⭐ **`ALPHACOUNCIL_DEMO=1` → 全站常驻横幅** | ⚠️ 环境变量会忘 ⇒ 所以有第 3 层 |
| 3 | ⭐ **`dev.py demo` 拒绝写真库默认路径** | 这是**代码里的守卫**，不是约定 |

⭐ **判据：第 3 层是唯一一层「关掉就出错」的。** 前两层是提示，第三层是机制 ——
而宪法 §0.2 明确要求「能移到 ③/④ 的就移」。

### 2.2 横幅说什么 —— 用产品的语气

- ✅ 说事实：「**这是演示库。你的记录不在这里。**」
- ⭐ **不说**「欢迎体验」「示例数据」—— ⭐ 红线 13：**不讨好用户**，而「欢迎」是在讨好
- ⭐ **不含任何数字**（红线 11）—— 不写「5 张卡片」
- ⭐ **不提供「导入到我的库」** —— 那是一条把演示数据变成用户记录的路，**而演示数据不是用户的判断**

### 2.3 演示数据必须过的门禁

⚠️⭐ **`S-03 no-prediction-field` 扫全仓。** ⇒ 种子文案里出现「目标价 / 涨跌预测 / 买卖建议」
会让门禁变红，而**一个 README 的配图不该让门禁变红**。
⇒ **种子文案逐字遵守红线 1**，且这条要用一个测试钉住（不能靠自觉）。

⭐ 而且种子**必须用产品自己的 domain 函数**生成复习排程
（`note_recall.enroll` / `record_review`）⇒ **FSRS 状态是真的**，
「下次 2026-10-03」不是编出来的字符串。README §八 已经这么做过一次，
⭐ **而那次用的是一次性脚本 —— 本轮把它变成仓库里可复跑的东西。**

### 2.4 命令形态

```
python scripts/dev.py demo              # 建库 + 播种 + 启动
python scripts/dev.py demo --no-launch  # 只建库（CI / 验证用）
```

⚠️ **`demo` 不进 `CHECK`** —— 与 `eval` 同一个理由（`dev.py:414-419`）：
**一个会写文件的命令不该被门禁跑。**

## 三 · 红线落点

| 红线 | 怎么落 |
|---|---|
| **1** 不做预测 | ⭐ 种子文案逐字遵守，且**用测试钉住**而不是靠自觉 |
| **3** 记录优先于分析 | 演示库是**记录**，不是分析 |
| **11** 不鼓励频繁操作 | 横幅**不含数字**；且演示库不是日常用的库 |
| **13** 不讨好 | 横幅说事实，不说「欢迎」 |
| ⭐ **15 / agent-guide「不替用户写决策记录」** | ⭐⭐ **这是本规格最核心的一条**：演示数据**只存在于另一个库**。主库**一个字节都不动**，而这是**代码守卫**（§2.1 第 3 层）保证的，不是承诺 |

## 四 · 不做什么

| 不做 | 为什么 |
|---|---|
| ⭐ **往真库里塞任何东西** | 红线 3/13/15 + `status.md` 已判定 |
| ⭐ **「导入演示数据到我的库」** | 那是一条把演示判断变成用户判断的路 |
| **onboarding 教程 / 引导流程** | 独立一轮。⚠️ 演示库解决「打开有东西看」，**不解决「第一次记录要多久」** —— 后者是下一件 |
| **让 `demo` 进 `CHECK`** | §2.4 |
| **截图工具** | ⭐ 有演示库之后截图是自然的，**但那是 README 的活，不是产品的活** |

## 五 · ⚠️ 本规格**不**解决的（诚实清单）

| 项 | 状态 |
|---|---|
| ⭐ **主人自己的库仍然是空的** | ❌ **本轮不解决。** 演示库不是用户数据 ⇒ 约束②**仍然未达成**，而达成它要靠**降低记录成本**，是下一件 |
| ⭐ **触发器默认不工作** | ❌ 仍然。`send_due` 仍是手动 CLI，`send_email` 仍零调用者。**但有了演示库之后，「有没有东西可通知」这个问题第一次变得可回答** |
| **README 截图重拍** | ❌ 不在本轮 |
| 演示库的**内容质量** | ⚠️ 见 spec §七 |

## 六 · 已知会失败的地方（不假装覆盖）

| # | 会以什么形状骗过我 |
|---|---|
| 1 | ⭐ **`grep demo` 找不到东西 ⇒ 以为没有播种。** 而 `tests/` 里的 `_seeded()` 夹具会让这个 grep 命中 —— **同一份代码，两种含义** |
| 2 | ⭐ **播种「成功」但库是空的** —— ⚠️ `notifications_sent` / `market_cache` 之类可能掩盖。⇒ **播种后必须数行数，不是看有没有报错** |

| 4 | 横幅在某个页面没渲染（⭐ 三栏外壳 + 开屏 + 深链都可能绕过它）⇒ **每个页面都要断言** |
| 5 | ⭐ **播种用 SQL 直插，绕过 domain** ⇒ 排程是假的，「下次 X」是编的。**这正是 README §八 说的那件事**，本轮不能重犯 |
