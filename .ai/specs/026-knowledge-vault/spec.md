## 一、⭐ 缺口在哪：不是"没装软件"，是数据模型堵死了入口

| 实测（2026-09-28） | |
|---|---|
| backend 里的「笔记」概念 | **0** |
| 全文检索 / FTS5 | **0** |
| 标签 `tags` | **0** |
| Markdown | **0** |

整个知识层是**一张 `cards` 表**，而每一行被三条硬约束锁死：

```python
CardDraft:
  source_url:   str          # 必填，必须 http/https
  source_title: str          # 必填
  symbols:     tuple[Symbol] # Symbol = 6 位数字代码 + 市场
```

前端 `createCard` 更硬：`symbols: [`${market}${code}`]` —— **一张卡只能挂一只票**。

### 于是这些全都记不下来

| 想记的 | 能记吗 | 卡在哪 |
|---|---|---|
| 「流动性收紧时周期股先跌」（宏观） | ❌ | 无标的、无 URL |
| 「我的估值框架是这样」（方法论） | ❌ | 同上 |
| 「我第 3 次因为只看 PE 错过」（经验） | ❌ | 同上 |
| 一篇研报的读书笔记 | ❌ | 必须有 URL、必须挂票 |
| 任何没有出处的想法 | ❌ | provenance rule 是必填 |

⭐ **所以这个产品能"复习知识"，但不能"记录知识"。它有一个队列，没有一个知识库。**
这是主人这句话的字面含义。

## 四、⭐ 本轮范围（主人选定：笔记 + 卡片并列，一个真知识库页面）

### 4.1 数据模型：`notes` 与 `cards` **并列，不是它的变体**

| | `cards`（K1） | **`notes`（本轮）** |
|---|---|---|
| 主张 | 一句话，**≤3 行** | **Markdown 文档，长度不限** |
| 来源 `source_url` | **必填** | **可空** |
| 标的 `symbols` | 前端硬编码一只 | **可空、多个** |
| 立场 `claim_type` | 三分类 | 无 —— 笔记不是主张 |
| 复习 | ✅ 已实现 | ⏳ **下一轮**（见 §六） |

⭐ **provenance rule 一点没放松。** 卡片仍然必须有来源。
放松它会让"我以为我记住了，其实我在引用一段我没读过的东西"变得无法察觉 ——
而**笔记的存在正是为了让"没有出处"这件事有一个正当的容器**，
而不是为了让卡片可以没有出处。

### 4.2 迁移 `0007_knowledge_notes`

| 表 | 作用 |
|---|---|
| `notes` | id · title · body(Markdown) · created_at · updated_at |
| `note_tags` | note_id · tag（**一表多行，不塞逗号串** —— 否则 `WHERE tag LIKE '%宏观%'` 会命中 `宏观债`） |
| `note_links` | from_note · to_kind · to_id（`note`/`card`/`decision`/`instrument`/`lesson`）—— **互链骨架** |

### 4.3 诚实声明：`note_schedule` **本轮不做**

`research/09` 与规范都要求笔记能进复习队列（否则知识不会回来找你）。
本轮**只做"记录"**，复习队列是**下一轮**，理由与设计写在 §六。
**本轮不建用不到的表** —— 空表比缺表更坏，它会让人以为功能存在。

## 五、验收

| # | 项 |
|---|---|
| 1 | 能记一条**没有来源、没有标的**的笔记并读回来 |
| 2 | 能记一条**有标的**的笔记（宏观/方法论除外，个股观点也可以直接记） |
| 3 | Markdown 源码**原样存、原样取**（不 trim、不规范化、不转义） |
| 4 | 标签可增删，**`宏观` 不会命中 `宏观债`** |
| 5 | 互链可写可读，双向可见 |
| 6 | 与 `cards` 并列出现在同一个知识库页面，可分别筛选 |
| 7 | **门禁 10/10 + 退出码 0**；变异检查覆盖新代码 |
