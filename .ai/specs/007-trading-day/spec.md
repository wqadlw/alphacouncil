# Spec 007 · 交易日判定（探针，T-08）

- **状态**：Active
- **目标阶段**：S1（status.md D3 还差项「交易日探针」· TSP 借鉴 T-08）
- **依赖**：D3 行情路由（指数日线已实测可用）· spec 005（今日页，判定结果的展示位）
- **依据**：`references/tsp/借鉴笔记.md` ⑦（探针三级降级）· 宪法 4.6（数据四态）/ 7.7（状态用枚举 + 状态机）

---

## 背景与目标

**今天就是 Sunday 的活案例**：用户周日打开应用，看到的是周五（实际上周四，见下）的收盘价，页面上没有任何东西解释"为什么行情是旧的"——用户可能以为数据坏了，更糟的是可能把旧价当现价做判断（4.6 的安静失效）。

T-08 的本意是"节假日不轮询 + 诚实降级"。本 spec 先交付**判定**（今天到底是不是交易日、依据是什么）；"非交易日跳过取数"的优化依赖它与缓存 TTL 的交互设计，另立决策，不在本轮。

## ⭐ 关键实测发现（决定技术路线）

1. **腾讯指数快照的 `quoted_at` 是取数时刻，不是最后成交时刻**（周日实测：quoted_at = 当下，价格却是 09-24 收盘）——**快照时间戳无法用于交易日判定**，TSP 的"行情时间戳"探针在我们这一层不成立。
2. **指数日线最后一根 bar 的 `trade_date` 就是最后交易日**（实测：09-24，恰逢 09-25 中秋节休市，数据自己说出来，不需要节假日硬编码）。

→ 探针 = 取上证指数日线小窗口，看最后一根 bar 的日期。**零节假日知识**：不维护会过时的日历表（写死的 2026 节假日表要么过时要么凭记忆虚构——宪法 2.4 禁止）。TSP 的第一层"日历"待找到可人工核实的权威来源后再接入，届时它只是提高确定性，不改结构。

## 判定规则（状态机，规则 = 数据不是 if 链）

| # | 输入 | 判定 | 依据（basis） | 为什么 |
|---|---|---|---|---|
| 1 | 今天是周六/周日 | `non_trading_day` | `weekend` | **确定**：A股调休上班的周末仍休市，周末从不开市 |
| 2 | 探针失败（非 ok / 无 bar） | `unknown` | `none` | 无证据。4.6：不猜 |
| 3 | 最后交易日 == 今天 | `trading_day` | `probe` | 今天已有 bar，市场开过 |
| 4 | 工作日 && 时刻 ≥ 10:05 && 最后交易日 < 今天 | `non_trading_day` | `probe` | 交易日必然已有当日 bar（09:30 开盘 + 35 分钟余量） |
| 5 | 工作日 && 时刻 < 10:05 && 最后交易日 < 今天 | `unknown` | `none` | 无法区分"未开盘"与"节假日" |
| — | 最后交易日 > 今天（未来数据） | **抛 ValueError** | — | 数据源异常，不是业务答案；路由层捕获 → unknown + warn |

⚠️ 规则 4 有一个**已声明的假设**：东财/腾讯日线在盘中包含当日 bar。已登记 status.md §五 未验证项，下一个交易日早晨必须核实；若证伪，修正的是常量与规则 4，回归立即可见（交易日早晨误报"休市"会立刻被用户看到）。

**对 TSP 的有意偏离**：TSP 的兜底层"工作日 → 交易日"我们不采纳——工作日可能是节假日（周一国庆），工作日推断出的"交易日"会把未验证冒充答案（4.6）。周末方向保留（那是确定的）。

## 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | `domain/trading.py`：`TradingDayVerdict`（trading_day / non_trading_day / unknown）+ `TradingDayBasis`（probe / weekend / none）+ 纯函数 `verdict_for(now, last_trading_date)`——状态表即数据，日期/时刻全部注入 |
| FR-2 | 常量：探针窗口 = 今天往前 **14 天**（理由：A股最长假期 ~8 天，窗口保证任何假期后仍有 bar）；开盘确定性截点 = **本地 10:05**（理由见规则 4） |
| FR-3 | 探针取数走路由（7.8 唯一入口）：`Symbol(SH, 000001, INDEX)`，`get_daily(start=今天-14天, end=今天)`；取**最后一根 bar 的 trade_date**；路由三源互备/熔断/缓存天然复用 |
| FR-4 | `GET /api/v1/today` 增加 `market_status: {verdict, basis, last_trading_date, checked_at}`；探针的 ValueError 捕获 → unknown + warn（一个数据源抽风不能 500 整个今日页） |
| FR-5 | 今日页头部：`non_trading_day` → 显示「休市 · 最后交易日 MM-DD」（事实，来自 last_trading_date）；`trading_day` / `unknown` → 不显示徽标（不制造不存在的信息） |
| FR-6 | 不做：非交易日跳过取数（另立决策）· 日历层（待权威来源）· 财务日历 |

## 验收标准

| 编号 | 标准 |
|---|---|
| AC-1 | 领域：周六/周日任意时刻 → non_trading_day + weekend（无需探针数据） |
| AC-2 | 领域：最后交易日 == 今天 → trading_day + probe |
| AC-3 | 领域：工作日 10:05 后、最后交易日 < 今天 → non_trading_day + probe |
| AC-4 | 领域：工作日 10:05 前、最后交易日 < 今天 → unknown；探针失败 → unknown；未来日期 → 抛 |
| AC-5 | API：`/today` 带 market_status；探针失败 → unknown 且页面其余部分正常（200） |
| AC-6 | 前端：休市徽标显示最后交易日；unknown / trading_day 不显示 |
| AC-7 | 门禁全绿 |
| AC-8 | 变异 ≥ 3 |

## 已知的失败（本 spec 防的事故）

| # | 事故 | 防线 |
|---|---|---|
| 1 | 用快照 `quoted_at` 判定交易日——它在该源是非交易日时盖"当下"的戳，周日被判为交易日 | FR-3 用日线 bar 的 trade_date；实测发现已记录 data-sources.md |
| 2 | 工作日推断"今天开市"——周一国庆被误判 | 规则表：工作日单独永远不产生 trading_day（对 TSP 的有意偏离） |
| 3 | 写死节假日表——过时或凭记忆虚构 | 不做日历层；探针零节假日知识 |
| 4 | 探针挂了 → 今日页 500 | FR-4 捕获 → unknown；今日页其余区块不受影响 |
| 5 | 盘中当日 bar 缺失导致交易日早晨误报休市 | 已声明假设 + status.md §五 登记 + basis 字段可溯源；证伪即修常量 |
