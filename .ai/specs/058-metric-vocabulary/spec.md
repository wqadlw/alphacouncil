# 058 · 指标词表：让「我写的东西能被求值」在**写入时**就成立

> 宪法 2.2 的三问在 §〇。⭐ **这不是「新功能」，是修一个产品正在误导读者的地方。**

---

## 〇 · 想做什么

**目标**：读者填「失效条件」时，⭐ **要么他写的产品算得了，要么当场知道算不了。**

**具体故障（实测 2026-10-05，全部可复现）**

`DecisionForm` 的失效条件有一个自由文本框，placeholder 是 **`gross_margin`**。
⭐ **而 `gross_margin` 不在任何一张指标表里。**

| 量的问题 | 结果 |
|---|---|
| 产品能算几个指标 | `CATALOGUE` **24**（日线算） + `FINANCIAL_CATALOGUE` **8**（财报算）= **32** |
| ⭐ 这 32 个有中文名吗 | ⭐ **有，`catalogue_labels()` 已经全部写好**（`close`→收盘价） |
| ⭐ **`gross_margin` 在里面吗** | ⭐ **不在，两张表都没有。** ⭐ **产品有毛利率，它叫 `gp_margin`，标签「销售毛利率」** |
| 域层校验吗 | 只校验**形状**：`[a-z][a-z0-9_]*`（`domain/decision.py:204`）⇒ **不校验存在** |
| 写入会失败吗 | ❌ **`POST /api/v1/decisions` → `201`，原样存进库** |
| 写入时有任何提示吗 | ❌ **一句都没有。** `/today` 在 `as_of` 之前什么都不显示 —— ⭐ 而那是对的，于是**没有东西是红的** |
| 有端点能列出词表吗 | ❌ **`/api/v1/metrics` → 404，`/api/v1/catalogue` → 404，没有任何路由引用词表** |
| ⭐ 那产品**知道**吗 | ⭐⭐ **知道。`metrics.read_metric` 已经返回 `MetricStatus.UNKNOWN_METRIC`**，且它的 docstring 写着：<br>「早退的顺序就是全部设计。先查未知名字，⭐ 这样这个版本答不出的名字**永远不会走到一个可能给它返回貌似合理值的指标函数**」 |
| API 文档的例子呢 | ⭐ `routes/decisions.py:62` 的三个例子 `gross_margin` / `revenue_yoy` / `price` —— **三个都不在词表里** |

⇒ **一句话的结论**：⭐ **产品有毛利率，叫 `gp_margin`；界面让读者写 `gross_margin`；
没有任何东西说这两个不是一回事；等产品终于在几个月后判定 `UNKNOWN_METRIC` 时，
那句话听起来像在说「数据不够」，而数据是够的。**

⭐⭐ **而这不是「打字麻烦」。** 记一个决策要填五档动作、两个文本框、一条失效条件 ——
⭐ **(a)–(c) 只是费力，而对这个产品的论点（记录优先于分析）来说费力是正当的。**
⭐ **(d) 是另一回事：三个必填字段之一，照着产品自己的例子填，会得到一条静默地
无法履行它唯一职责的记录** —— 失效条件的全部意义就是「让数据来找我」，
⭐ 而产品**早就有能力判定这条判据永远不会响**，只是**问晚了几个月**。

**必需还是可选**：**必需。** 约束②「主人自己日常会用」。⚠️ 而这一条与真库空不空无关 ——
⭐ **即使主人今天就有决策，其中带 `gross_margin` 的那些也是死的**，而他不会知道。

## 二 · 设计决策

### 2.1 ⭐⭐ 不是「换成下拉框」，因为那会**删掉一个能力**

⚠️ **最省事的做法是把自由文本换成 `<select>`，而那是错的。** ⭐
`criterion_sentence` 有**整整一个句子状态**是为「不在我们能算的指标里」准备的
（实测渲染：「观察期已到 —— 「revenue_yoy」不在我们能算的指标里，这条判据没有被求值过。」），
⭐⭐ **换成 select 之后，读者再也写不出那种判据，那个句子状态也就永远不会被渲染。**
⇒ **那是删功能，不是修缺陷。**

⇒ **决定**：**给出能算的（按市场），同时仍然允许写别的，写的那一刻说一句话。**

⭐ **判据**：一个不能算的指标名，**是读者关心的一个真实概念**（他关心毛利率），
⭐ 而产品算不了是**产品的问题**，不是读者写错了。⭐ 拒绝它 = 把产品变成只接受它会算的东西。

### 2.2 那句话说什么（红线 11 / 13）

- ✅ **说事实**：「`gross_margin` 我算不了。」+ ⭐ **列出能算的。**
- ⭐ **不拒绝写入。** 红线 3：记录优先于分析 —— 他写下毛利率是一个**事实**
- ⭐ **不说「没关系」「已记下」** —— 红线 13，不讨好
- ⭐ **不给「你写错了」** —— ⭐ **他没写错，产品才是不全的那个**
- ⭐ **数字是关于产品的，不是关于读者的** ⇒ 红线 11 允许（「我能算的有 32 个」是产品的事实）
  ⭐⭐ **但更好的做法是直接列出来而不是报数** —— 列表比数字有用，⭐ 而「列出」这件事
  ⭐ **本身就是把限制说清楚**

### 2.3 端点：复用，不重述

`GET /api/v1/metrics?market=sh` → 按市场过滤后的 `{token, label, grain}`。

⭐ **可用性必须来自 `capability_matrix()`，⭐ 不能来自一张写死的表** ——
⭐ 否则 `.BJ` 标的会拿到 8 个算不了的指标，⭐ **那就是我在修的同一种谎，换了个方向。**

## 三 · 红线落点

| 红线 | 怎么落 |
|---|---|
| ⭐ **8** 禁「机会推送 / 每日精选 / 异动提醒」 | ⭐ **这是它的反面**：这句话说的是「我永远只会看这些，其余一概不认」。⚠️ **绝不能排序成「推荐」**，⭐ 也绝不能标一个「首选」—— 那是暗示产品有意见，`DecisionForm` 给五个动作同等权重就是为这个 |
| **3** 记录优先于分析 | ⭐ **被加强**：记录现在会说真话 about 自己 |
| **11** 不鼓励频繁操作 | 无数字**关于读者**。列表是产品的事实 |
| **13** 不讨好 | 一句事实，不是一句安慰 |
| ⭐ **4 / provenance** | 不涉及 |

## 四 · 不做什么

| 不做 | 为什么 |
|---|---|
| ⭐ **拒绝写入不能算的指标** | §2.1 —— 那是删能力 |
| ⭐ **给指标加「推荐」标记或默认排序** | 红线 8 + `DecisionForm` 现有的「五个动作同等权重」原则 |
| **把 8 个财报指标从词表里删掉** | 它们是真的，只是 `.BJ` 算不了 ⇒ **按市场过滤，不是删除** |
| **改域层校验，让未知指标 422** | ⭐ 那会让 §2.1 那个句子状态永远无法从界面到达 |
