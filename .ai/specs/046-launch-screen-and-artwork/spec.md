## 二、做了什么

### 1. 31 幅，逐日一幅

选品**分两轮**，而这件事本身是这个 spec 里最值得留下的部分。

第一轮 31 幅是看 300 px 缩略图选的。把它们铺成一张全尺寸图看之后**换掉 17 幅**，
因为**缩略图看不出三件事**：

- **题跋占了九成画面**，绘画只在底部一条（day-19）
- **裱绫的蓝边横穿画面**（day-27）
- **屏风照片带着折痕接缝**，像一张有竖线的纸（day-28、day-30）
- 300 px 看着是浅色的，1133 px 下是发闷的褐（day-24、day-29）
- `破墨` 既是 beautiful 又是 empty（day-31 留下了 —— 那是优点）

⇒ **可复现的那部分是：先看缩略图筛掉题材，再看全尺寸定去留。**
写进 `PROVENANCE.md` 的「为什么是这一批」一节。

留下的是赵士谔《武陵清溪》册页、梅清《九龙湟》、沈周仿王翚、
王原祁仿倪瓒、八大山人、董其昌《青卞》、许本《溪山行旅》1372、
雪舟《破墨山水》、谷村素月《潇湘八景》…… 以及少量日本画僧。

### 2. 开屏

- **不是路由。** `routing.ts` 的表驱动导航 / 解析 / 标题 / href；
  开屏没有地址、不能被链接、Back 不会回来，也绝不能出现在导航里。

- ⌘K 里「重看开屏」是唯一回去的路。

## 四、这个 spec 里最贵的两条（都是失败换来的）

### 1. 深链必须绕过开屏 —— 101 条测试换来的

第一版把开屏放在**所有路由**前面，整个 e2e 套件崩了：**10 过 101 挂**，
每一条都失败在「shell 不在屏幕上」。

⚠️ **而那不是测试的 bug。** 一个从书签打开 `#/i/sh/600519` 的读者问了一个具体问题，
用一幅全屏画回答，是应用把自己的引导排在读者意图之上。

三种修法里两种是错的：
- **给十二个 spec 各加一次 `localStorage.clear()`** —— 套件绿了，产品照旧坏
- **只在空 hash 上显示** —— `#` / `#/` / `''` 三种拼法都表示 today（`parseHash` 归一化），
  这是在**选一个拼法而不是选一个含义**
- ✅ **深链绕过开屏** —— `#/` 是唯一表示「我没有特定目的地」的地址

### 2. 门禁的 CSS 扫描一直在空转

`SRC_DIR` 走 `URL.pathname` 加剥前导斜杠。`URL.pathname` 是百分号编码且总以 `/` 开头，
所以在 Windows 上它产出 `/D:/AAA/.../frontend/src`；剥掉斜杠后得到
`D:/AAA/.../frontend/src` —— **一个当作相对路径用的绝对 Windows 路径**。
它不抛错，它只是不存在，于是回退到 `frontend/` 根目录。

而唯一的样式表在 `src/styles/globals.css`，`frontend/` 根目录**一个 `.css` 都没有**。
⇒ 十一条 `for (const file of CSS)` 的规则**一次都没有执行过**。
**实测：往 `globals.css` 里塞一个 `@keyframes`，三十七条测试全绿。**

⇒ 新增一条断言：`CSS` 非空且必须含 `styles/globals.css`。
守卫必须和它守的东西写在一起 —— 原来它要写在 240 行之后，所以没人写。
