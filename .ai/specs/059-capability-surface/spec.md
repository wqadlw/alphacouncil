# 059 · 能力矩阵：让「我算不了」有一个读者能看见的地方

> 宪法 2.2 的三问在 §〇。⭐ **这不是新功能，是把仓库自己写下的规则用在自己的端点上。**

---

## 〇 · 想做什么

**目标**：⭐ **一个读者看不见的边界不是边界**（`UniversePage` 的 footer 原文，⭐ 而
`pool.spec.ts:77` 就在断言那一句）—— ⭐ **而这个产品现在有一个端点说明它能看见什么，
界面上一个字都没有。**

**具体故障（实测 2026-10-05）**

| 量的问题 | 结果 |
|---|---|
| `GET /api/v1/capabilities` 存在吗 | ✅ 存在，返回 **15 格** `dataset × market` |
| ⭐ 界面上有谁读它 | ⭐ **`grep getCapabilities frontend/src` 只命中 `DemoBanner` 的一个字段 `is_demo`** ⭐⭐ **矩阵本身零消费者** |
| 仓库自己怎么说 | ⭐ `UniversePage:171`：「这一页只显示事实」；⭐ `pool.spec.ts:77` 断言「一个读者看不见的边界不是边界」 |
| ⭐ 那读者会怎样 | ⭐ 关注一只 **`.BJ`** 标的，⭐ 实测 `daily` 与 `financial` **都是 `pending`** ⇒ **一个指标都算不了**，⭐⭐ 而界面上**没有一个字说这件事** |

⭐⭐ **这和 spec 058 是同一件事的两个方向。** 058 说「你写的那个指标我算不了」；
⭐ 059 说「**这个市场我整体什么都算不了**」—— ⭐ 而 058 的 `.BJ` 分支已经量到了后一半，
⭐⭐ **前端却只有那一行字，没说「一个都没有」。**

**必需还是可选**：**必需。** ⭐ 因为它是 `status.md` 记着的「未决孤儿」，
⭐ 而**一个端点存在而没人读，是本仓反复出现的形状**（`F-248`：「一张表存在不等于有人用它」）。

## 二 · 设计决策

### 2.1 ⭐ 放哪：标的页，不是新页面

| 候选 | 判断 |
|---|---|
| ⭐ **标的页一个区块** | ✅ **矩阵是按市场的**，而标的页**免费就有市场**；⭐ 而且那正是读者**做承诺**的地方（跟随 / 记决策）—— ⭐ 边界应该出现在承诺旁边，不是另开一页 |
| 新开一页 | ❌ ⭐ 红线 8 的精神是**不要新增可供浏览的面**；⭐ 而矩阵**不随时间变化**，⭐ 不值得一个入口 |
| 全局页脚 | ❌ ⭐ 读者在别的页面不会需要它，⭐ 而那正是 `.BJ` 用户最需要的时刻（他在 `.BJ` 的页面上） |

### 2.2 ⭐⭐ 只说「能 / 不能」，⭐ **不说数据源名字与健康度**

`CapabilityCell` 带 `sources: [{name, healthy, cooldown_remaining_s}]`。

⭐⭐ **决定：界面上不渲染数据源名字、健康度、冷却剩余。**
- ✅ 要说：某个市场某个数据集**能不能算**。
- ❌ 不说：`eastmoney` 健康吗、`cooldown_remaining_s: 42`。
- ⭐ **理由是红线 8**：⭐ 一个「数据源 42 秒后恢复」的显示，⭐ 离「过会儿再试」只有一步，⭐
  而**「过会儿再试」就是一次 nudge**。⭐ 读者要的是「我能不能算这个」，不是运维面板。

### 2.3 措辞：说事实，不安慰也不邀功

- ✅ 「这只票所在的 **京** 市场，我还没有能算的数据。」
- ⭐ **不说**「我们尽力」/「数据源偶尔不稳定」/「建议稍后再试」
- ⭐ **不排序**：⭐ 按 `Dataset` 的**声明顺序**，⭐ 不按「重要性」—— ⭐ 与 058 的 token 同理

### 2.4 空矩阵是答案，不是错误

`.BJ` 的两个数据集都 `pending` ⇒ 那句话要成立。⭐ **而这也是唯一一个矩阵页真的会说的话**
（sh/sz 全 `usable`），⭐ 所以**它必须被测**，⭐ 否则它等于不存在。

### 7.2 ⭐ 我自己制造又自己抓到的一个缺陷

⭐⭐ **我把源码标记 `⭐` 漏进了渲染文案。**
第一版结尾那句是 `⭐ 写下来的判据照记，⭐ 到期时…`，⭐⭐ **星号在 JSX 里** ——
⭐⭐ 于是**每个看 `.BJ` 标的的读者都会看到它们**。

- ⭐ **没有一条断言抓到它。** ⭐ 一条断言「我算不了」的**子串没匹配上**，⭐⭐ 于是我去读实际文本，⭐ 才看见。
- ⭐⭐ **然后我的修复重复了同一个缺陷**：⭐⭐ 我把「泄漏」这段解释**写进了同一个 `<p>`** —— ⭐⭐ **那里也会渲染**，⭐⭐ 于是第二版给读者看了更多星号加一段英文。

⭐⭐ ⇒ **`⭐` 是源码注释的标记，不是句子的部分。**

### 7.3 ⭐⭐ 那条守卫踩了两个坑（`F-270` + `F-271`）

⭐⭐ **变异存活了三次，我才发现守卫本身是空的。**

| 坑 | 是什么 |
|---|---|
| ⭐ **没等** | 测试读完 `goto` 就读 DOM，⭐⭐ 而那个区块**要等 `/api/v1/capabilities` 回答后才存在**。⭐⭐ 于是断言读的是**还不含被守对象的文档** ⇒ ⭐⭐ **「把 `⭐` 放进 JSX」这个变异存活了，而守卫是绿的** |
| ⭐ **读错属性** | `innerText` 渲染感知、`textContent` 不感知；⭐ U+2B50 是 emoji 呈现字符，⭐⭐ `innerText` **看不见它** —— 量了三次：bundle 里有、DOM 探针里有、断言里没有 |

⭐⭐ **同一个 describe 里另一条测试是碰巧对的**：⭐
`the provider names never reach the page` 在读之前 `await expect(notice).toBeVisible()`，⭐⭐
**这就是它的变异死掉、而这条活着的原因。** ⭐⭐ **一个恒真的守卫比没有守卫更坏，因为它报绿。**

### 7.4 ⭐⭐ `S-18` 自己发现了一条豁免在藏绿灯

⭐⭐ 加完客户端类型后门禁红了，而 `S-18` 说的是：

> the `NOT_MIRRORED` entry for `CapabilitiesRead`
> **waives something no client type is missing, so it is hiding a green result**

⭐⭐ **意思是**：那三条豁免（`CapabilityCell` / `CapabilitySource` / `CapabilitiesRead`，
理由是「没有 UI」）⭐⭐ **在它守护的东西修好之后就失效了** ——
⭐ 三条客户端类型现在字段齐全，⭐⭐ **豁免正在遮一条会变绿的检查。**

⭐⭐ 与 `F-258` 同形（**一条记着「未修」的东西，理由先失效**），⭐⭐ 而这里代价更直接：
**留着它，服务端与客户端类型的对应关系就处于「未经验证但看起来已豁免」的状态。**
⇒ **三条已删。** ⭐ `S-16` 对 `CapabilityState` 的那条**留着** —— ⭐ 那是字符串字面量联合、
不是对象，⭐ `S-18` 的字段集匹配根本看不见它 ⇒ **那是检查够不到的缺口，不是遮绿灯的豁免。**
