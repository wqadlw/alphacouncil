# Spec 022 · 落地计划

---

## 一、这不是重构，是补一个缺件

上一轮我自己认下来的缺口是"复盘页没有入口"。写 spec 时才查清**它的真实范围**：

```
src/*.tsx 里 <nav> 出现次数：0
六个页面各自 import 一个 HREF 常量、各自手写一个「← 回到 X」
```

**全站唯一能到达任何页面的方式，是手敲 hash。**

而产品定义写着「打开就落在今日页」，`项目总纲` §2.1 写着「第 ④⑤ 个时刻用户
**不会主动来**，所以产品必须主动找他」。**一个没有全局导航的产品，这两条都无从谈起。**

所以这不是"把代码写漂亮"，是**补一个框架层**。

## 二、⭐ 三个决定，全部来自调查而非喜好

### 2.1 依赖：零新增

宪法第三条禁止未经批准引入运行时依赖；锁定表的前端是
**Vite + React + TypeScript + shadcn/ui**（明确**不用 Next.js**），
而 **TanStack Router / Query 根本不在表里**。

2026-09-28 主人明确选择：**不引入，用现有栈建好框架层**。

于是 `shadcn/ui` 与 TanStack 一样，归入宪法 §3.0 的
**「已采纳、未落地」**——**如实标出，不假装已实现，也不顺手引入**。

### 2.2 ⭐ 外壳里**不能有任何数字**（这条是查出来的）

我先以为"导航加不加角标"是审美问题。查 E2E 时发现**三条测试断言的是整页正文**：

| 断言 | 位置 | 禁止的东西 |
|---|---|---|
| 危险象限下**整页无任何数字** | `retrospective.spec.ts:119` | `0-9` |
| 整页不含 | `review.spec.ts:75` | `%` `正确率` `记住率` `掌握度` **`评分`** `得分` |
| 整页不含 | `today.spec.ts:25` | `收益率` |
| 空态不含 | `retrospective.spec.ts:184` | `连续` `打卡` `完成率` `%` |

**导航是正文的一部分。** 所以：

- 导航**零数字**、零禁用词
- ⭐ **任何元素都不得叫「评分」** —— 即使它显示的是过程分。这就是为什么全应用
  一律叫「过程分」

这条还顺带解释了 021 里那个 `retro-empty` → `empty-state` 的 testid 迁移：
共享组件接管了空态，测试就该指向共享件。

### 2.3 ⭐ 导航**不预告队列里还剩几条**

`项目总纲` §2.1⑤ 对"想忘记"那个时刻的规定是：
**一句陈述，无推送、无红点、无催促词。**

`复习 3` 这个角标会把"你欠着三张卡"变成**看得见、能攀比**的数字 ——
那是红线 11（不鼓励频繁操作 / 禁止打卡计数）**戴着.helpful的小牌子**。

所以：**导航只有文字。** 队列里有几条，由**点进去之后**的那句话回答。
（队列页**内部**报数是可以的——那是读者已经选择去看之后的事实。）

## 三、路由表作为唯一真源

改之前，一个新页面要改**三个地方**：

1. `parseHash` 里的 if 链
2. 一个 `HREF` 常量
3. `App.tsx` 里算 `document.title` 的**嵌套三元**

**漏掉任何一个都不会报错** —— 页面进不去，标题还借了别人的。
这正是本项目到处当缺陷处理的那类"看起来成功了"的失败。

现在 `ROUTES` 是**唯一声明处**：导航、hash 解析、标题、`HREF` 全部由它派生。
**加一页 = 加一条表项。**

## 四、⭐ 一个测试当场抓到的设计错误

我第一版把 route **name** 从 href 上切出来（`href.slice(2)`），
看起来很聪明。测试立刻红了：

```
expected { name: 'unknown', raw: '#/' } to deeply equal { name: 'today' }
```

`'#/'.slice(2)` 是 `''`，不是 `'today'`。**name 不是从 href 可还原的。**

> **"聪明"和"错"的比例最差的一种，就是只在唯一一个 case 上错的那种。**

改成表里显式写 `name`。这条写进了 `RouteDef` 的注释里。

## 五、⭐ `useResource`：把竞态从"看不见"变成"测得到"

六个页面约 **35 处**手写 `setLoading` / `setError`。收成一个 hook 之后，
**6 个 `set-state-in-effect` 警告消失**——因为那不只是噪音，
那是每次加载多一次渲染。

而 hook 里唯一微妙的东西是**代次计数器**：切到另一张卡时两个请求同时在飞，
**后到的会覆盖先到的**，页面静静显示错的那一行。

问题来了：**本仓库 vitest 没有 DOM 环境**（没有 jsdom，加它算新依赖，
宪法不批）。所以 hook **根本没法测**。

于是把代次计数器抽成 `RequestRunner`（一个普通 class，不需要 React），
hook 变成薄绑定。测试直接驱动它，**把两个请求乱序 settle** ——
**这是唯一能证明计数器有用的办法**；按顺序 settle 的测试，
对一个根本没有计数器的实现也会通过。
